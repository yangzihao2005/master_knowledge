# 操作系统强化课 第3讲 内存管理

## 场景一题干信息提炼：二级页表综合题的已知条件

[00:00:00 - 00:16:00]

本讲以虚拟页式（二级页表场景）为主线，串联连续分配、伙伴算法，最后借缺页中断引出 DMA 等设备知识。做大题先用"笨办法"：边读题边把关键参数抄到草稿纸，之后只依据草稿纸作答，避免长题干反复干扰。场景一的参数为：物理内存 4MB，含 TLB 与 Cache；Cache 直接映射，共 16 行，行大小 256B；按字节编址，定长指令 4B（32 位）；进程虚拟地址空间 256MB，页面大小 1KB；页目录表与页表各占一页（1KB），表项大小均为 2B；表项由存在位、物理页框号、访问权限位组成；页表项采用大端存放。

> **易错点**：页表的"表大小"与"表项大小"都要参与位数推算，缺一不可；大端/小端会影响读出的表项值。

## 虚拟地址格式（二级页表）

[00:16:00 - 00:21:00]

虚拟地址共 28 位（256MB），划分为页目录号 9 位 + 页号 9 位 + 页内偏移 10 位。页内偏移由页面大小决定：1KB = 2^10，故 10 位；页号位数由"一个页表有多少个表项"决定：1KB / 2B = 512 = 2^9，故 9 位；页目录号同理，1KB / 2B = 512，也是 9 位。

> **公式**：页内偏移位数 = log₂(页面大小)；表项数 = 页表大小 / 表项大小，索引位数 = log₂(表项数)。
> **易错点**：页目录号/页号在不同教材中叫法混乱（一级/二级页号），答题时按题目给的字段名对应，不要背名称。

## 物理地址格式与 Cache 地址划分

[00:21:00 - 00:24:00]

物理地址 22 位，按页式划分为物理页框号 12 位 + 页内偏移 10 位；页框数 = 4MB / 1KB = 4K = 2^12。同一个 22 位物理地址按直接映射 Cache 再划分为：块内偏移 8 位（256B）、Cache 行号 4 位（16 行）、标记位 10 位（22 − 12）。两套划分针对不同对象，互不干扰：对页表用页框号，对 Cache 用行号与标记。

> **易错点**：不要试图用一套字段同时满足页式与 Cache；标记位是"剩余位数减出来"的。

## 页表项各字段位数推算

[00:24:00 - 00:25:00]

页表项共 16 位，由物理页框号 K + 权限位 + 存在位（1 位）构成。页表项中存放的"物理地址"实质是物理页框号，其位数与物理地址中的页框号一致，即 12 位，于是权限位 = 16 − 12 − 1 = 3 位。

> **易错点**：页表项存的是页框号（12 位）而非完整物理地址（22 位）。

## 二级页表地址转换全过程（本讲核心）

[00:25:00 - 00:40:00]

例：PTBR = 0x000C00（页目录表基址），访问逻辑地址 0x2000400。① 把地址展开为 28 位二进制后按 9/9/10 切分，得页目录号 0x040、页号 0x001、页内偏移 0x000。② 页目录项地址 = 基址 + 索引 × 2B = 0x000C00 + 0x040×2 = 0x000C80，读出 2 字节 0x4523（大端：按原序即 0x4523；若小端需交换字节）。③ 拆项：页框号 0x452、权限位 001、存在位 1（为 1 才可继续）。④ 页表基址 = 0x452 << 10 = 0x114800；页表项地址 = 0x114800 + 0x001×2 = 0x114802，读出 0xE811。⑤ 拆项：页框号 0xE81、存在位 1。⑥ 物理地址 = 0xE81 << 10 + 0x000 = 0x3A0400。

> **易错点**：9/9/10 都不是 4 的倍数，**绝不能直接切十六进制**，必须整体转成二进制再按位切、最后转回十六进制；只有位数是 4 的倍数时才能直接切十六进制位。
> ⚠️ **需回看视频 [00:36:00]**：口误/识别混用，把"页表基址"称作"页框号" —— "页框号是0x114800h，那么它对应的地址是不是需要给它左移十位……最后得到的这个地址是0x114800h"

> ⚠️ **需回看视频 [00:38:00]**：最终页框号前后不一致，末句写成 0x181H，与前面推出的 0xE81 冲突 —— "其中它的物理页框号是0X181H，然后页内偏移量是000H"

## 多级页表下 TLB 保存的映射

[00:40:00 - 00:44:00]

TLB 表项保存的是"完整虚拟页号 → 物理页框号"，即除页内偏移外的全部高位。本例 18 位虚拟页号 0x08001（0x2000400 右移 10 位，等于页目录号 0x040 与页号 0x001 拼接）映射到物理页框号 0xE81。多级页表只是硬件为节省页表空间所做的切分，TLB 缓存的是最终映射结果，命中后无需再逐级查表。

> **定义**：TLB 是页表项的高速缓存，本质仍是"虚页号→页框号"映射，与页表级数无关。

## Cache 访问与缺失处理，换地址验证

[00:44:00 - 00:50:00]

物理地址 0x3A0400 拆为标记 0x3A0、行号 4、块内偏移 0：先定位 4 号 Cache 行，用比较器比对标记，相等即命中，取出该行第 0 字节；不等则 Cache 缺失，从内存把整块调入该行并把标记改写为 0x3A0 后重新访问。教材（原书）写法是数据同时送 Cache 与 CPU，另一种写法是先写入 Cache 再取，两种设计考试按题意判断，一般不影响结果。换地址验证：0x200000 的页目录号仍为 0x040（页目录项仍是 0x4523），页号为 0x000，对应页表项 0xC2A8，其存在位为 0，故此次访问发生缺页中断。

> **易错点**：先判存在位再看页框号；存在位为 0 时页框号无效。

## 进程切换对 TLB 与 Cache 的影响

[00:50:00 - 00:53:00]

[01:15:00 - 01:19:00]

PTBR 指向当前进程的页目录表，进程切换后页表基址改变、映射关系整体改变，因此同一逻辑地址在不同进程中不保证命中，也不保证对应同一物理地址。TLB 全系统只有一套，若不清除，P1 的映射会被 P2 误用，故进程切换时必须刷新（整体清空）TLB。Cache 按物理地址索引与比较，旧块只会造成一次不命中，随后被替换，一般不需要专门处理。用户进程不能直接访问页表：页表位于内核空间，直接按地址访问属越权；正常的地址转换由 MMU 硬件完成，不产生越权。

> **易错点**：TLB 切换必须刷新，Cache 通常不用；两者原因不同（映射会错 vs 只是失效）。

## 页表项的权限检查与越权异常

[00:53:00 - 00:56:00]

页表项除地址映射外还携带访问权限：S/U 位区分内核页与用户页，读写位区分该页可读还是可写。硬件在做地址转换的同时完成权限检查：用户态访问内核页（S 位），或对只读页执行写操作（如 MIPS 的 store），都会被硬件拒绝并触发越权异常。这正是"用户空间与内核空间由同一套映射机制隔离管理"的具体实现方式。

> **定义**：越权异常由 MMU 在地址转换中检测，属于异常而非中断。

## 页表内容与 Clock 页面置换（模拟题）

[00:56:00 - 01:15:00]

页表中不需要保存虚拟页号：页表是页表项数组，虚拟页号就是数组下标。存在位为 1 的项说明进程当前占有的页面及其物理页框（0 号页→7 号框，3 号页→8 号框），由此反推操作系统给该进程分配的是 7、8 两个固定页框；存在位为 0 的项其页框号是废数，不能用于判断。局部置换下进程的页框数始终不变。

访问序列（页大小 1KB、12 位地址，高 2 位为页号）：C5FH → 页 3，命中 8 号框，访问位置 1，指针不动；B83H → 页 2，缺页，Clock 依次把 7 号（1→0）、8 号（1→0）给第二次机会，再回到 7 号（已为 0）换出 0 号页，装入 2 号页、访问位置 1，指针后移到 8 号；4ABH → 页 1，缺页，指针所指 8 号访问位为 0，直接换出 3 号页，装入 1 号页、访问位置 1，指针后移到 7 号；再访问页 0 → 缺页，两个访问位均为 1 先置 0，第二轮换出 2 号页，装入 0 号页，指针后移到 8 号。全程共缺页 3 次。

> **易错点**：换入新页后扫描指针要再后移一位（新页应最后被检查）；缺页处理完要重新执行该指令，所以新换入页的访问位置 1。

## 内存分配方式总览

[01:19:00 - 01:24:00]

内存分配分连续分配与非连续分配。连续分配含单一连续分配（只支持单道程序，考得极少）、固定分区分配（产生内部碎片）、动态分区分配（不产生内部碎片但产生外部碎片）；动态分区的分配算法重点是首次适应、最佳适应、最坏适应。非连续分配含页式、段式、段页式。首次适应平均性能最好；最佳适应最容易产生外部碎片；最坏适应不易产生碎片，但会把大块切小，不利于大进程。

> **易错点**：动态分区分配"不产生内部碎片"不等于"不产生内存碎片"。

## 内部碎片与外部碎片

[01:24:00 - 01:29:00]

内部碎片源于分配单位固定：操作系统按固定粒度（如 512B、按 2^k 分配）给空间，进程用不完的部分仍属该进程，别人无法使用；因此凡"不可变长"的分配方式都有内部碎片——分页、文件按块分配、固定分区。外部碎片需同时满足三个条件：① 必须分配连续空间；② 不定长（按需）分配；③ 空间可释放（释放后留下的细小空洞难以再利用）。典型场景：动态分区分配中的最佳适应、文件的连续分配、分段分配。

> **易错点**：判断外部碎片的实质是"被释放的小空闲区能否再被利用"。

## 分页与分段的区别

[01:29:00 - 01:31:00]

页由系统按固定大小划分，对用户透明，逻辑地址一维；段由程序员按逻辑功能划分（代码段、数据段、堆、栈），对用户可见，逻辑地址二维（段号 + 段内偏移），段长可变。段既是存储单位又是功能单位，可以整段赋权、整段共享，故比页更便于实现共享与保护，代价是产生外部碎片；页式只能逐页处理共享与保护，产生内部碎片。

> **定义**：段表项主要包含段的起始地址与段长，转换时先查段长做越界检查，再"起始地址 + 段内偏移"。

## 动态分区分配真题：最佳适应与空闲分区链

[01:31:00 - 01:38:00]

第一题问"最容易产生内存碎片的动态分区算法"，答案是**最佳适应**：它总挑刚好够用的分区，剩余部分极小，极易变成无法利用的外部碎片（注意题干说的是"内存碎片"而非"内部碎片"）。第二题：最佳适应下空闲分区链按**容量从小到大**排序，以便第一个够大的分区即可分配；回收起始 60K、大小 140K 的区间 [60,200) 后，恰好填满 20–60 与 200–400 之间的空洞，合并为 20–400（380K）。合并后共 3 个空闲分区，按容量升序第一个是起始 500K、大小 80K，选 B。

> **易错点**：空闲分区链按大小排序而非按地址排序，合并后必须重新排序；此题必须画内存条图（标出各分区起止地址）才能避免错位。

## 页目录表表项数真题：页表不超过一页

[01:38:00 - 01:43:00]

题给逻辑地址空间 2^16 页，即页目录号 + 页号共 16 位（页内偏移 10 位另计），页目录项 2B、页大小 2^10B。要求页目录表表项数"至少"，即页目录号位数最少 → 页号位数最多。隐含前提：除顶级页表（页目录表）外，每级页表最多占一个页面，即 2^10B，可容纳 2^10/2 = 2^9 个表项 → 页号 9 位 → 页目录号 7 位 → 表项数 2^7 = 128，选 B。

> **易错点**：把"页目录表"与"页表"混为一谈；忘记"低级页表不超过一页"这一隐含约束，就会误按 16 位平均切分。
> ⚠️ **需回看视频 [01:42:00]**：顶级页表可否超过一页，教材未明确，且此处转写疑似乱码 —— "顶级页表它可能可以超过一个亿"

## 伙伴算法（Buddy System）

[01:43:00 - 01:53:00]

把内存按 2^k 个"基本单位"（可能是字节、KB 或页，视场景而定）组织成 2^0～2^K 的空闲块链表，每块只需记录起始地址，且起始地址必须是块大小的整数倍。分配：取最小的、不小于需求的 2^k 块；不存在就不断二分分裂（如 1024→512→256→128 取一块给 100 单位需求，余 28 成为内部碎片）。回收：同大小的相邻"伙伴"可合并，判据是合并后的起始地址必须是合并后大小（2^(k+1)）的整数倍；满足则逐级向上继续合并。

> **公式**：合并条件 = 合并后起始地址 mod 2^(k+1) == 0。
> **易错点**：两块同大小且相邻并不一定能合并，必须做地址对齐判断（如起始 20 的两块 4 合并成 8，20 不是 8 的倍数，不能合并；起始 24 则可以）。
> ⚠️ **需回看视频 [01:49:00]**：合并条件的口语表述含糊 —— "它是不是这个二的k次方加一的整数倍"，应理解为 2^(k+1) 的整数倍

## 缺页异常与三类异常

[01:53:00 - 01:59:00]

访存时 MMU 先查 TLB，未命中再查页表（单级或多级）；转换成功即访问物理内存，并把该映射回填 TLB。转换失败分三类：**权限不够**（越权，如用户态访问内核页、写只读页）、**访问越界**（地址不在本进程的有效地址空间内，虚存虽大但进程只映射了一部分）、**缺页**（地址有效且权限通过，但页面还在磁盘上）。408 选择题已多次暗示应把三者视为不同异常分别处理。

> **定义**：缺页中断是异常（属于广义中断），由访存/取指过程触发，不是外部设备中断。
> ⚠️ **需回看视频 [01:56:00]**：三类异常的命名与区分表述混乱 —— "第三种是在地址空间且权限检查通过，叫权限越界中断"

## 缺页中断处理流程

[01:59:00 - 02:02:00]

① 先看有无空闲页框，无则按置换算法选出受害页 Q。② Q 若被修改过则写回外存（未修改可直接丢弃，省一次 I/O）。③ Q 的页表项存在位清 0，腾出的页框 F 归 P 使用。④ 从外存把 P 读入 F，P 的页表项存在位置 1、页框号改为 F。⑤ 重新执行引起缺页的那条指令。

> **易错点**：缺页处理完返回的是"重新执行当前指令"，返回"下一条指令"的是系统调用（自陷）。

## 页面交换与磁盘区域

[02:02:00 - 02:04:00]

与虚拟存储相关的磁盘空间分文件区与交换区：换出的页面写入交换区，因其特殊设计，再次调入比从文件区调入更快；首次调入的页来自文件区。页面在磁盘上的具体定位方法不在 408 考查范围，只需知道"由页故障地址能够找到该页"。页面交换的实质是"内存页→磁盘"与"磁盘→内存页框"两个方向的搬运，由磁盘驱动程序以 DMA 方式控制。

## DMA 控制页面交换与数据传输过程

[02:04:00 - 02:13:00]

磁盘驱动程序给 DMA 控制器下发参数：传输方向、磁盘地址、内存地址、传输长度、启动命令，随后启动磁盘设备。传输时：磁盘控制器把数据备到缓冲 → 向 DMA 控制器发 DMA 请求 → DMA 控制器向 CPU 发总线请求 → 获得总线（常考周期窃取）后把字搬入 DMA 缓冲再写入内存 → 释放总线 → 发下一个字的读命令，循环至整块传完。

> **易错点**：对 CPU 而言 DMA 传送的基本单位是"块"，但总线上实际是一个字一个字搬运；"DMA 请求"（设备→DMA 控制器）与"总线请求"（DMA→CPU）是两个概念，广义上都可叫 DMA 请求，按题目语境判断。
> **易错点**：传完一个字就释放总线，说明采用的不是"停止 CPU 访存"方式。

## 缺页处理中 DMA 的整体流程与数据落点

[02:13:00 - 02:18:00]

应用程序缺页陷入内核 → 修改页表 → 磁盘驱动程序发起 I/O 并阻塞当前进程 → CPU 切换去执行其他进程 → DMA 在后台把页逐字搬入内存 → 完成后发 DMA 中断 → 中断处理程序唤醒原进程。普通缺页（无页缓冲）时，DMA 直接把页送入**用户空间**对应的物理页框：DMA 使用物理地址定位，即使进程已切换，数据仍落到原进程的页框里。对比：文件 I/O 经内核文件缓冲区，键盘输入因跨地址空间也必须先入内核缓冲区。

> **易错点**：不要一概认为"外设数据先进内核缓冲区"，缺页的页可直接进用户空间。

## DMA 传送中的页框不可被抢占

[02:18:00 - 02:22:00]

若正在被 DMA 写入的页框 N 被其他进程抢占，DMA 不会中断，仍按物理地址 N 写入，结果把 P1 的数据写进了 P2 的页面，P1 反而拿不到数据，故该页框不可抢占。若采用页缓冲（先读入内核页缓冲，再复制到用户空间），DMA 锁定的是内核缓冲，用户页框被抢占不影响数据完整性，此时允许抢占，代价是多一次复制。

## 缺页处理真题

[02:22:00 - 02:26:00]

关于缺页处理的错误叙述是 D：A 项"缺页是地址转换时 CPU 检测到的异常"正确（由 MMU 在转换中发现）；B 项由操作系统提供的异常处理程序处理正确；C 项"根据页故障地址从外存读入所缺失的页"正确（不考查如何定位外存地址）；D 项"返回发生缺页指令的下一条指令"错误，应重新执行该指令。第二题：从磁盘读入内存的顺序为 ②驱动程序初始化 DMA 并启动磁盘 → ③DMA 把数据传到内存缓冲 → ①DMA 完成后发中断 → ④执行 DMA 中断处理程序（唤醒进程），即 2314，选 B。

## DMA 方式真题与软硬件辨析

[02:26:00 - 02:31:00]

四条叙述均正确：传送前由设备驱动程序设置参数；传送前由 DMA 控制器请求总线使用权；传送过程由 DMA 控制器直接控制总线完成；传送结束后由中断服务程序收尾。争议点"设参数的是 CPU 还是驱动程序"：软件即指令，指令只能由 CPU 执行，设备驱动程序同样是 CPU 执行的程序，两种说法等价。但硬件不等于 CPU：中断隐指令、MMU 地址映射、DMA 传送、设备与设备控制器之间的数据交换都可无指令参与，其中后两者已脱离 CPU。

> **易错点**：软件一定由 CPU 执行；硬件可能是 CPU 内部功能，也可能与 CPU 无关。

## 不同设备的访问流程

[02:31:00 - 02:43:00]

I/O 层次结构（用户层 → 设备独立性软件 → 设备驱动程序 → 中断处理 → 硬件）主要贴合磁盘类设备，各设备顺序不同，不能死记。输出设备（打印机）：用户程序直接下发输出命令，任务交给控制器后进程通常不因等待 I/O 而阻塞；若被阻塞，是被"独占设备 + 临界区"挡住，而非被设备本身阻塞，这正是 SPOOLing 能把独占设备改造为共享设备的前提。输入设备（键盘）：进程发系统调用后阻塞，键盘中断到来后由中断处理程序调用驱动程序把数据读入内核缓冲区，再唤醒进程，顺序是"先中断、后驱动"。磁盘：系统调用后驱动程序直接命令设备传输，DMA 完成后中断唤醒进程，顺序是"先驱动、后中断"。中断控制方式的设备：驱动下发读命令 → 进程阻塞 → 数据进入 I/O 控制器端口 → 中断 → 中断处理中再调一次驱动把数据读入内核缓冲区 → 唤醒进程，全程两次调用驱动。

> **易错点**：键盘与磁盘的"驱动/中断"先后顺序相反；中断处理程序里可以调用驱动程序接口。

## 课末答疑：缺页的"触发"与"处理"

[02:43:00 - 03:03:38]

触发缺页不需要进入内核态：访存指令（或取指）产生地址，MMU 查 TLB 与页表全部由硬件完成，即使落在用户态也一样，因此缺页的检测是硬件行为；只有 CPU 响应并开始处理该异常时才陷入内核态——"触发不会，处理会"。提高磁盘交换区容量只是让置换更快，并不减少缺页次数，故不能缓解抖动。DMA 使用物理地址，进程切换不影响数据落点；单总线时 DMA 占用总线 CPU 便无法访存，多总线或周期窃取则可并行。少量教材表述不一致的争议点出现概率极低，不必纠缠，优先拿稳靠实力可得的分。

> **易错点**：区分地址映射（address mapping）与地址转换（address translation）；区分"缺页的检测"与"缺页的处理"。
