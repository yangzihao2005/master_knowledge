# 操作系统强化课 第1讲 绪论与进程基础

## 装机阶段：物理格式化、磁盘分区与逻辑格式化

[00:00:00 - 00:18:00]

开机前的"装机"分四步，顺序固定：物理格式化 → 磁盘分区 → 逻辑格式化 → 安装操作系统。物理格式化（低级格式化）由磁盘厂商完成，把盘面划成盘面、磁道、扇区，之后才能用"盘面号+磁道号+扇区号"三元组寻址。磁盘分区把物理空间绑成若干逻辑单元（一个盘可分多区，多个盘也可并作一区），并产生 MBR 主引导扇区及磁盘分区表来记录各分区的位置、是否为系统分区等信息。逻辑格式化以分区为对象，有几个分区就做几次，作用是写入 PBR（分区引导块）与文件系统元信息（FAT、inode 表等）并创建根目录，故又称"文件系统安装"。安装操作系统则是把 OS 装入某个分区，该分区即系统分区（启动分区），多系统即多个分区各装一套 OS。

> **易错点**：根目录是逻辑格式化创建的，不是操作系统初始化创建的；逻辑格式化（写磁盘）≠ 操作系统安装（装 OS 本体）。
> **真题叫法**：划分盘面/磁道/扇区 = 物理格式化；把物理空间划为逻辑磁盘 = 磁盘分区；按文件系统装入文件系统信息 = 逻辑格式化。

## 操作系统引导：BIOS → MBR → PBR → OS

[00:18:00 - 00:29:00]

引导是把 OS 从启动分区逐步载入内存并让其接管 CPU 的过程，按 2021 年真题总结为三步（加一步收尾）：执行 BIOS 并加载 MBR → 执行 MBR 并加载 PBR → 执行 PBR 并加载 OS → 控制权交 OS。BIOS 是内存 ROM 区的固定程序（固件），开机时 PC 天然指向其入口；它做开机自检、初始化自检与读盘所需的基础中断，用 I/O 指令把磁盘第一个扇区 MBR 读入内存，再把 PC 指向 MBR。MBR 含磁盘分区表与引导程序，据分区表选出活动（系统）分区并加载其 PBR。PBR 知道本分区内核的位置，把内核装入内存，PC 指向 OS 入口，OS 正式运行。

> **易错点**：BIOS 必须在内存且在 ROM——PC 只能指向内存（外存程序必须先装入），RAM 断电即失，只有 ROM 的非易失性能保证开机时有 BIOS 可执行。
> **易错点**：为什么能按操作系统类型选择分区？因为 MBR 中有磁盘分区表。多系统启动菜单的本质就是选择不同启动分区的 PBR。

## 操作系统初始化的总览与中断/异常初始化

[00:29:00 - 00:35:00]

引导结束后 OS 已在内存并持有 CPU，初始化就是各子模块上岗前的准备（全局变量赋值、资源分配），分五块：中断异常、内存管理、进程管理、文件系统、I/O。中断异常初始化第一件事是构建中断向量表：它本质是一个数组，表项为中断向量（服务例程入口），位于内存，由 IDTR 指向表首址，中断发生时据此跳转到对应服务例程。注意 BIOS 阶段用的是实模式中断向量表，OS 初始化时已是保护模式中断向量表，两者无关，408 后面所说的中断向量表都指后者。第二件事是初始化时钟：设定时钟中断的触发间隔并使能时钟。

> **易错点**：时钟中断间隔是程序设定的，不是一个时钟周期触发一次；时钟中断与时钟周期没有固定对应关系。

## 内存管理初始化

[00:35:00 - 00:37:00]

动态分配（伙伴系统、动态分区、连续分配等）都要先从"内存池"里取，初始化时必须为分配器划出可用内存池，否则切分与分配无从谈起。同时要探测硬件内存信息（如物理页框总数）并配置分配器的全局参数。关键一步是内核页表的建立：地址映射（分页）机制生效后只能用虚拟地址访问，因此在开启分页前必须先完成内核空间的映射、填好内核页表。

## 进程管理与调度器初始化

[00:37:00 - 00:38:00]

创建 idle（闲逛）进程及若干初始用户进程（如 Windows 的图形界面进程）。调度器初始化要为就绪队列等数据结构分配空间，并按实际情况配置相关全局变量（如系统允许的最大进程数）。

## 文件系统初始化：根文件系统与 VFS

[00:38:00 - 00:42:00]

OS 所在分区上的文件系统是根文件系统；加载 OS 的过程中，根文件系统运行所需信息（分区表、FAT、超级块等）已被放入内存，此外还要做 VFS 初始化（创建 VFS 根节点）。非根文件系统则不同：其超级块等全局信息在**挂载**时才进入内存，而不是初始化时——内存有限，用不到的文件系统不该常驻。这一块常被反着考：磁盘上的布局信息、根目录的创建属于逻辑格式化，不属于文件系统初始化。

> **易错点**：区分口诀——在磁盘上做的事是逻辑格式化，在内存里做的事才是文件系统初始化（或挂载）。

## I/O 初始化与场景一配套问答

[00:42:00 - 00:47:00]

I/O 初始化包括：使能各设备中断、设置中断屏蔽字以确定中断优先级、探测系统中有哪些设备及其位置（刚开机时 OS 并不知道设备清单）。配套问答结论：命令行方式运行程序时，命令解释程序负责把用户命令转换成系统调用并触发它，运行在用户态；根目录由逻辑格式化写入磁盘，其余文件/目录由用户程序通过系统调用创建；鼠标点击的反馈依靠中断机制，而"鼠标中断 → 对应服务例程"的映射是在构建中断向量表时建立的。

## 用户程序的执行流程与进程创建

[00:47:00 - 00:53:00]

用户使用计算机的方式是执行用户程序，链路为：形成可执行程序 → 创建进程（申请 PID 与空白 PCB → 申请资源 → 初始化 PCB → 入就绪队列）→ 调度上 CPU。创建通过父进程发出的系统调用完成，参数是磁盘上可执行文件的路径；系统中进程数有限，申请不到 PID/空白 PCB 则创建失败。子进程处于创建态时，父进程处于运行态（它正在执行"创建子进程"这件事）。若创建到一半因资源不足无法继续（如内存不够），是父进程进入阻塞态等待资源，子进程仍是创建态。

> **易错点**：阻塞的是父进程而不是子进程；若一开始就创建失败或顺利完成，父进程都不阻塞，只有"干到一半等资源"才阻塞。

## 创建进程时的资源分配与页表初始化

[00:53:00 - 00:56:00]

申请资源可串联各类分配策略：连续分配给固定/动态分区；非连续分配（基本页式/段式）给足页框或段；虚拟存储只装入部分页，缺页时再分配或置换。初始化 PCB 的典型工作是填写页表基址等管理信息：例，某进程基本页式需 5 页（页 0～4），分配器给了页框 21、76、20、88、89，PCB 记录页表始址，页表写入"页号→页框号"映射，进程运行时即可完成虚拟页到物理页的转换。

## 进程的内存布局（代码段、数据段、BSS、堆、栈）

[00:56:00 - 01:02:00]

程序装入内存后按区分布：代码段放指令与只读常量；数据段放已初始化的全局/静态变量；BSS 段放未初始化（或初始化为 0）的全局变量；堆放动态分配的空间；栈放局部变量与函数调用信息。加载前逻辑上已存在的是代码段与数据段，BSS、堆、栈在装入后分配。例：`int *a = (int *)malloc(100*sizeof(int));` 中 `a` 是局部指针变量，位于栈；`a[10]` 是所分配数组的元素，位于堆。

> **易错点**：BSS 中的变量初值为 0，但空间仍在装入时分配，不占可执行文件体积。

## 虚拟地址空间的形成与重定位

[01:02:00 - 01:05:00]

不论静态链接、装入时动态链接还是运行时动态链接，程序的虚拟地址空间都在**链接**时形成——链接把主程序与库函数的逻辑关系确定下来，才构成一个地址完整的可执行文件。物理地址的形成时机则看重定位方式：静态重定位在装入时确定指令和数据的物理地址；动态重定位在运行时由硬件机制完成虚拟地址到物理地址的转换。

> **易错点**：虚拟地址形成于链接，物理地址形成于装入（静态重定位）或运行（动态重定位）。

## 程序入口、正常退出与程序/进程的关系

[01:05:00 - 01:09:00]

PCB 中保存程序入口（entry point）的虚拟地址，首次从内核态返回用户态时以该地址作为断点恢复，程序便从 main 开始执行；编译时会在末尾自动插入 exit 系统调用，保证任务正常终止。程序是磁盘上静态的二进制文件（指令+数据），要被"执行"必须创建进程、分配 CPU 与资源，因此程序的执行必须依赖进程。至于"BIOS 加载 MBR"与"CPU 加载 MBR"两种说法并不矛盾：BIOS 本身就是指令序列，由 CPU 执行；同理"驱动程序初始化 DMA"与"CPU 初始化 DMA"也只是视角不同。

> **易错点**：有虚拟存储时，PC 与 PCB 中保存的入口/断点都是虚拟地址。

## 课间答疑：时钟中断、文件系统挂载与创建失败

[01:09:00 - 01:16:00]

时钟中断的时间间隔在初始化后仍可修改（调长或调短）。文件系统挂载是用户程序发起的一种系统调用，不是操作系统初始化的工作；非根文件系统的全局信息在挂载时才入内存。创建进程若一开始就失败，父进程不阻塞（工作直接结束）；顺利创建完也不阻塞；只有创建到一半等资源才阻塞。命令解释程序是边解释边执行。

## 进程控制块 PCB 的内容与组织

[01:16:00 - 01:19:00]

PCB 保存进程管理的全部信息：PID、状态、时间片、优先级、上下文（通用寄存器组、PC 等）。PCB 通常以"PCB 队列"组织，但操作系统里的"队列"未必是真队列，可能是数组、链表、优先级队列（堆）甚至栈，按需选择。按状态分组：所有就绪进程组成就绪队列（多级反馈队列算法下可有多条），每种阻塞原因对应一条阻塞队列。

> **易错点**：阻塞队列不是唯一的，一个阻塞原因一条队列，才能在事件发生时快速定位该唤醒谁。

## 阻塞、唤醒与 current proc

[01:19:00 - 01:21:00]

唤醒：阻塞队列对应的事件发生 → 取出某进程 PCB（状态字段由 blocking 改为 ready）→ 插入就绪队列。阻塞：运行中的进程需等待某事件 → 状态由 running 改为 blocking → 入相应阻塞队列 → 当前无进程可运行，需调度。current proc（current）是指向当前运行进程 PCB 的指针；调度就是从就绪队列选出一个 PCB，让 current proc 指向它。

> **易错点**：只把 current proc 指向新 PCB 并不等于完成切换——CPU 里的上下文还没换，必须再做进程切换。

## 调度与上下文切换

[01:21:00 - 01:30:00]

时间片轮转下 PCB 有 time slice 字段（单位为时钟中断次数），每次时钟中断减一，减到 0 就置 need_resched=1；中断返回前检查 need_resched（及 can_resched）决定是否调度。调度：按算法（FCFS、SJF、HRRN、时间片轮转等）从就绪队列选出进程，标记为 next proc。切换四步：把当前处理器状态（寄存器组、PC、栈指针等）存入 current proc 的 PCB → 把该 PCB 插入就绪队列 → 把 next proc PCB 中保存的上下文装入处理器 → 更新 current proc 指向新进程。之后才由中断返回回到用户态继续执行。

## 线程切换与 PCB 相关问题

[01:30:00 - 01:34:00]

同一进程内不同线程切换：上下文（寄存器组、PC、断点）要换，栈要换，但地址空间（即页表）不换。进程切换则还要换地址空间/页表。用户程序不能访问自身的 PCB——PCB 是内核中供 OS 管理进程的数据结构，属内核空间。优先级调度算法的就绪队列用堆（优先队列）效率最高，因为每次只需取最高优先级。若根页表总占一个完整页框，PCB 中的页表基址可只存页框号，节省位数。

> **易错点**："线程切换什么变、什么不变，进程切换什么变、什么不变"是高频送分点，务必背清。

## 进程状态转换及触发事件

[01:34:00 - 01:40:00]

运行→阻塞：等待除 CPU 外的任何事件（发起 I/O、P 操作使信号量 ≤0、条件变量 wait、创建途中资源不足、等待键盘等输入设备数据）。阻塞→就绪：所等事件完成（I/O 完成中断、V 操作、signal、资源到位、数据到达）。运行→就绪：时间片用完、被更高优先级进程抢占（该高优先级进程可能是被唤醒的，也可能是刚创建的）、协作式调度下主动 yield 放弃 CPU。就绪→运行：被调度选中（当前进程时间片到、阻塞或终止，或自身优先级更高）。

> **易错点**：阻塞态不能直接到运行态，必须先经就绪态等待调度。
> **易错点**：条件变量的 wait 一定阻塞（条件判断在调用 wait 之前由程序完成），不是"可能阻塞"；管程中 signal 唤醒的进程能否立即抢占取决于管程实现，与被唤醒者优先级无关。

## 抢占式调度下的状态变化分析

[01:40:00 - 01:44:00]

分析套路：先看事件改变了谁的状态，再看是否触发抢占。例：I/O 完成 → 中断唤醒进程 P，P 由阻塞变就绪，若其优先级高于当前进程则抢占 → P 就绪变运行，当前进程运行变就绪。时间片到 → 当前进程运行变就绪，另一进程就绪变运行。新进程创建完成 → 创建变就绪，可抢占。当前进程申请 I/O → 运行变阻塞，另一进程就绪变运行；当前进程终止同理。P 操作（信号量 ≤0）使当前进程阻塞，V 操作唤醒一个进程，被唤醒者能否抢占看优先级。

## PCB 与文件系统、PCB 内容辨析

[01:44:00 - 01:57:00]

PCB 中保存进程级打开文件表（及其指针），这就是 PCB 与文件系统的关联点。判断某信息是否在 PCB：看它是否与进程相关联。系统级打开文件表入口地址、磁盘块的内存缓冲区、系统时间等属于系统、可被多进程共用，不在 PCB；进程创建时间、是否需被调度的标志属于进程属性，在 PCB。

> **易错点**：PCB 是进程存在的唯一标志，凡"与进程相关"的信息才入 PCB。

## 键盘中断场景总览与题设

[01:57:00 - 02:04:00]

题设：4 种可屏蔽中断 I1～I4，响应优先级 I1>I2>I3>I4，处理优先级 I2>I3>I1>I4，I4 为键盘中断；进程 P1 的代码为 `int a; scanf("%d",&a); printf("%d",a);`，只分析 scanf 读入一个字符的过程。全链条：scanf（库函数）→ 转换为系统调用 → 参数传递 → trap 陷入内核 → 中断响应 → 系统调用服务程序 → 自行阻塞 → 键盘硬件中断 → 中断处理（驱动把数据读入内核缓冲区）→ 唤醒 P1 → 调度与切换 → 从内核缓冲区拷入用户地址 → 中断返回。其中 CPU/内核完成的部分与"用户+外部硬件"完成的部分要分开看。

> **公式/口诀**：库函数 → 系统调用 → trap → 中断响应（硬件）→ 中断处理（软件）→ 驱动 → 内核缓冲区 → 唤醒 → 返回用户态。

## 系统调用的参数传递

[02:04:00 - 02:08:00]

scanf 的语义是读到回车，分析时只看单字符输入，故最终转为读接口（read）系统调用。需要向内核传四类信息：读哪个设备（键盘）、读多长（1）、读到用户空间的哪个地址（&a）、以及系统调用类型（调用号）。调用号必须显式传：trap 之后内核无法从指令本身知道是哪个系统调用。参数放入通用寄存器（用户态与内核态共用同一套寄存器，故可传递）。

> **易错点**：系统调用号本身也是参数之一，不能省略。

## trap 指令与中断响应/中断处理前半段

[02:08:00 - 02:11:00]

trap（自陷、陷阱、陷入；x86 为 int 指令）触发 0x80 号异常进入内核。中断隐指令由硬件完成三部曲：关中断、保存断点（PC 与 PSW，保存区通常是内核栈）、按中断向量跳转；若来自用户态，同时完成用户态→内核态的特权级切换。跳入服务程序后，软件先保存上下文（其余寄存器）到内核栈，再开中断，然后才做真正的处理。

> **易错点**：关中断→保存断点→跳转是硬件；保存上下文→开中断是软件。
> **记忆技巧**：保存/恢复现场这类"改状态"的操作都应夹在关中断与开中断之间，防止中途来新中断导致状态不一致。
> ⚠️ **需回看视频 [02:08:00]**：转写中"中断引指令"疑为术语"中断隐指令"的 ASR 误识（全篇多处同误），需确认 —— "我们需要去包含一个特权级切换，就是在这个中断引指令硬硬件完成的过程当中"

## 内核处理系统调用：查表与取参

[02:11:00 - 02:13:00]

系统调用服务程序读寄存器中的调用号，查系统调用表得到对应处理函数地址并跳转（此处为 read 的处理函数）。再从寄存器取参数：长度 1、目标地址 &a、设备为键盘，据此调用内核内部的键盘读函数，把键盘数据送往目标地址。

## 进程阻塞与调度切换（P1 阻塞、P2 上机）

[02:13:00 - 02:15:00]

scanf 执行时光标等待输入，说明数据尚未产生，故 P1 在真正读键盘前必须等待：读键盘函数第一步把 P1 阻塞，PCB 存入"等待键盘输入"的阻塞队列（先保存内核态上下文）。随后调度另一进程 P2 上 CPU：P1 下处理机，P2 运行，此后 CPU 上执行的是 P2 而非 P1。

## 键盘中断的硬件过程

[02:15:00 - 02:17:00]

按键后，键盘设备经硬件电路把数据送入 I/O 控制器的数据寄存器，同时置位状态寄存器表示有新数据，然后由控制器向 CPU 发出外设中断（只告知"有输入"，不告知字符内容）。若系统未及时取走数据，控制器内的数据缓冲区可暂存多个字符。这一整段是纯硬件自处理，数据仍在 I/O 控制器，尚未进入主机。

## 地址隔离与内核缓冲区

[02:17:00 - 02:22:00]

中断处理时当前运行的是 P2，能否直接把数据写到 P1 的变量 a？不能：进程间地址空间严格隔离，P2 在 CPU 上时页表映射不到 P1 的用户区，即使 OS 也送不进去。正确做法是中断处理程序先把数据写入内核缓冲区；内核空间在所有进程中都映射到同一物理区域，天然共享，任一进程放入、另一进程可取，无需切换进程即可传递数据。待 P1 重新上 CPU（地址空间切换为 P1）后，再从内核缓冲区复制到用户地址 a。

> **易错点**：不能直接写对方用户空间的原因是地址空间隔离（页表映射不同），而不是简单的权限问题。

## 设备驱动程序与 I/O 端口访问

[02:22:00 - 02:28:00]

要把数据从 I/O 控制器的数据寄存器取出，必须通过设备驱动程序，用 I/O 指令访问 I/O 端口。端口编址有两种：独立编址（专用 I/O 指令 + 端口号，如 x86 的 in/out）与统一编址（端口映射到内存地址，用访存指令访问）。I/O 指令只能在端口与通用寄存器之间传送数据，不能直达内存，所以要两步：先把端口数据读入寄存器，再用访存指令写入内核缓冲区。驱动把端口访问细节封装成 read 接口，中断处理程序只调接口，OS 无需关心设备实现细节。

## P1 唤醒与系统调用返回

[02:28:00 - 02:32:00]

中断处理程序（在 P2 运行时发生，P2 全程无感）把数据放入内核缓冲区后，从键盘阻塞队列取出 P1 的 PCB，置为就绪并插入就绪队列。之后经调度与进程切换，P1 上 CPU；此时 P1 的地址空间已切换上来，用户区可见，且内核缓冲区可访问，于是把数据从内核缓冲区复制到目标地址 a。系统调用任务完成后，关中断、恢复现场与断点、开中断、中断返回用户态，P1 继续执行后续指令。

## 系统调用与中断的联动（用户态/内核态判定）

[02:36:00 - 02:38:00]

把 a 的地址作为参数传入发生在用户态（参数传递属用户程序）；用户程序主动触发的是异常（内中断），通过访管/trap 指令；内核判断"是哪个系统调用"靠软件读寄存器中的调用号；而"跳到系统调用处理程序入口"靠硬件（中断隐指令查中断向量表）。这一问的核心即系统调用与中断如何联动：用户态准备参数 → trap 陷入 → 硬件响应 → 软件查表分发。

## 真题：外部中断与内部异常的判别

[02:38:00 - 02:41:00]

判别口径：外部中断由 CPU 外部事件（设备、时钟等）触发；内部异常是"执行指令过程中"触发。键盘输入由外部设备送入 → 外部中断；除数为零、浮点运算下溢 → 执行运算指令时发生 → 异常；访存缺页虽俗称"缺页中断"，实为异常，且任何指令取指都可能缺页，不必是访存指令。

> **易错点**："缺页中断"属于内部异常。

## 真题：单级中断系统中中断服务程序的执行顺序

[02:41:00 - 02:45:00]

## 真题：用户态执行的程序与进程调度的层次

[02:45:00 - 02:48:00]

OS 提供给应用程序的接口是系统调用；库函数是语言/编译器层接口，最终必须转为系统调用。用户态执行的是命令解释程序（把命令解析为系统调用流并触发）；缺页处理程序、时钟中断处理程序、进程调度程序均在内核态执行。进程调度与切换发生在内核中：进程先陷入内核，在内核里完成"内核态进程→内核态进程"的切换，再中断返回用户态，并不是用户进程直接跳到另一个用户进程。

> **易错点**："进程调度程序在用户态执行"是高频错误选项。

## 真题：用户程序发出磁盘 I/O 请求的处理流程

[02:48:00 - 03:04:00]

键盘与磁盘的流程差一步：键盘路径是系统调用处理程序发现数据未就绪即阻塞，不调用驱动（对键盘发命令无意义）；磁盘是块设备，需向设备发命令，故系统调用处理程序 → 设备驱动程序 → 阻塞等待 → DMA 传输 → DMA 中断 → 中断处理唤醒进程。DMA 中断到来时数据已全部在内存，中断处理不再访问设备/驱动；缺页时数据直接装入进程页框，读文件时先进内核缓冲区再复制到用户缓冲区。计算柱面号、磁头号、扇区号的程序是设备驱动程序——凡涉及设备硬件细节的都由驱动完成。

> **易错点**：磁盘 I/O 的"系统调用→驱动→中断"顺序与键盘不同；中断发生时数据位置也不同（键盘在 I/O 端口，DMA 在内存）。

## 共享存储通信

[03:04:00 - 03:07:00]

共享存储把同一块物理内存映射进多个进程各自的虚拟地址空间（不同虚拟页 → 同一物理页框），一方修改另一方可见。共享区位于用户空间，不是内核空间——内核空间本就天然共享，无需再做共享存储。建立共享内存要改页表，在内核态完成；访问共享数据在用户态完成；使用时需自行处理同步互斥（不在 408 本讲考点内）。

## 共享内存与动态链接库结合（模拟题）

[03:07:00 - 03:11:00]

题设：P1、P2 共用动态链接库 S，采用运行时动态链接；S 装入物理页框 M，P1 页表中关于 S 的页表项虚页号为 n。逐项判断：P2 的虚页号也必须是 n —— 错，只需映射到同一物理页框，用哪个虚页无所谓；S 装入时 P1、P2 页表都已有该页表项 —— 错，P2 未运行到调用 S 处时尚未链接；S 在内存中位置不能变 —— 错，动态重定位下可移动，只需改页表项；必须有支持动态重定位的硬件 —— 对。

> **易错点**：共享的判据是"同一物理页框"，不是"同一虚页号"。

## 消息传递

[03:11:00 - 03:14:00]

直接通信：发送方把消息直接投到接收方的邮箱，接收方从自己邮箱按发送者取消息；因此 PCB 需有指向本进程邮箱（message buffer）的指针。间接通信：消息放入内核中的公共邮箱，收发双方都要指明邮箱标识，消息本身含发送者、接收者与正文。消息与邮箱均在内核空间，用户只提供消息内容。

## 管道通信

[03:14:00 - 03:20:00]

匿名管道要求通信双方有血缘关系（共同祖先）。管道通过文件系统的 read/write 接口访问，本质是一段内核缓冲区（循环队列），只支持半双工：必须"一方写完、另一方读完"后才反转方向；若交叉写入会破坏数据顺序（如 P2 插写一个字符后 P1 读到 "1BA"）。容量满时写阻塞、空时读阻塞，分别由对方读走数据/写入数据唤醒；所有读端关闭后管道可撤销。读操作会使数据失效，故读写必须互斥。

> **易错点**：管道 = 生产者消费者 + 循环队列；两个阻塞队列（写满、读空）。

## 管道的数据结构

[03:20:00 - 03:22:00]

管道的数据结构应含：内核缓冲区（管道本体）、读指针与写指针（对应循环队列头尾）、两个阻塞队列（写满阻塞、读空阻塞）、互斥锁（保证读写互斥）。

## 线程的独占与共享资源

[03:22:00 - 03:26:00]

线程独占：PC、通用寄存器组、栈（用户栈与内核栈各一）。线程共享：地址空间（即共享页表）、代码段、全局数据、打开文件等。例：P1(T1,T2) 与 P2(T3,T4) 都对虚拟地址 10086 处的数据加一，只有 T1、T2 通过 P1 的页表命中变量 a，故最终 a=2，T3、T4 访问的是各自进程的另一物理页。

> **易错点**："共享地址空间"的实质是共享页表；不同进程的同一虚拟地址指向不同物理地址。

## 用户级线程与内核级线程

[03:26:00 - 03:29:00]

用户级线程由库函数在用户态实现，内核不知其存在，故内核中没有它的 TCB（用户态库中可有）；内核级线程由内核管理，必有 TCB。切换开销：用户级小（用户态内完成），内核级大（需陷入内核）。一个用户级线程被阻塞，内核看到的是整个进程被阻塞，同进程其他线程也无法运行；内核级线程则其他线程仍可运行。

## 模拟题：用户级与内核级线程辨析

[03:29:00 - 03:33:00]

错误项是"两者都以线程为基本单位向 OS 申请 CPU 时间"——用户级线程对内核不可见，OS 只按进程分配时间片。正确项包括：用户级线程不支持跨进程的线程切换（切换由本进程调用的库函数完成，跨进程只能是进程切换）；用户级切换更快、内核级并发度更高；用户级线程可运行在不支持线程机制的操作系统上。

## 真题：父子进程的关系

[03:38:00 - 03:46:42]

父子进程可并发执行；各自有独立的 PCB（是两个进程）；不能同时使用同一临界资源。错误项是"共享虚拟地址空间"：子进程创建时是**复制**父进程地址空间（各自一份，此后互不影响），而不是共享（共享是同一份数据互相可见）。

> **易错点**："复制"≠"共享"：复制后两份独立，共享则一方修改另一方可见。
