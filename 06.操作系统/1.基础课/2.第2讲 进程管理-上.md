# 操作系统基础课 第2讲 进程管理-上

## 进程的本质：程序执行中内部状态信息的总和

[00:00:00 - 00:23:00]

程序是存放在磁盘上的指令和数据，要执行必须先把它们装入内存，并由操作系统分配 CPU、堆栈等资源。以一段只有四条指令的小程序为例：每条指令执行后，S0 寄存器、PC 以及内存中的变量 a 都会变化，因此"程序执行到哪一步"完全可以由一组具体的数值刻画出来。设想此刻强行关机再开机，只要把内存中的代码、数据、堆栈原样写回，并把 PC、S0、SP 等寄存器改回当时的值，程序就能沿着原来的轨迹继续执行。由此得到比教材更本质的刻画：进程是程序执行过程中某一时刻（某条指令刚执行完时）计算机内部状态信息的总和。教材所说"进程是程序的一次执行/执行中的程序"，是这一理解的粗粒度表述。

> **定义**：进程是程序执行过程中某一时刻程序内部（计算机内部）状态信息的总和。它包括内存空间（代码、数据、堆、栈）、CPU 内部状态（PC、SP、通用寄存器、PSW）以及正在占用的资源（打开的文件、设备等）。
> **易错点**：进程 ≠ 程序。程序是静态的指令与数据集合，进程是动态执行中的实体，可以用"某一时刻的状态快照"来完整保存与恢复。

## PCB：进程存在的唯一标识

[00:23:00 - 00:24:00]

用来保存上述全部状态信息的结构就是进程控制块 PCB。PCB 中记录进程此刻的全部内部状态信息，以及 PID 等附加信息。正因为只要拿到 PCB 就能把进程原样恢复出来，所以 PCB 是进程存在的唯一标识——PCB 存在，进程就存在。

## 逻辑地址与地址空间：虚拟地址到物理地址的映射

[00:24:00 - 00:33:00]

进程访问的都是逻辑（虚拟）地址。程序当然希望自己的地址从 0 连续编到 n-1，但物理内存并非它独占，操作系统只能把空闲的物理单元分配给它：例如 P1 的逻辑单元 0~4 被映射到物理单元 5、8、4、6、2，P2 的逻辑单元 0~4 被映射到物理单元 1、3、7、9、11。矛盾依靠地址映射机构解决，进程必须维护"逻辑地址→物理地址"的映射关系。于是两个进程可以拥有完全相同的逻辑地址 0~4，却落在完全不同的物理内存上。地址空间 = 虚拟地址范围 + 物理地址范围 + 二者之间的映射关系，其中核心是映射关系；页表、段表、段页式等具体实现留到内存管理部分。

> **定义**：逻辑地址（虚拟地址）是进程视角下使用的地址；地址空间指进程的虚拟地址范围、与之对应的物理地址范围，以及两者之间的映射关系。
> **易错点**：不同进程的逻辑地址可以完全相同（都从 0 开始编号），区分它们的是各自的映射表，而不是地址值本身。

## 地址映射的作用与进程状态的完整保存

[00:33:00 - 00:42:00]

有了映射表，PC 中存放逻辑地址即可，指令在物理内存中不再需要连续存放，计算机按映射自动找到真实位置。因此保存进程时，除寄存器状态外还必须保存该进程独有的映射关系。切换进程的实质就是换一张映射表：逻辑地址随之指向另一块物理内存，而被换下进程的代码和数据仍留在内存中、并未被销毁，切回来时把表换回即可。所以进程的完整刻画 = 计算机内部状态 + 各自的地址映射关系，映射关系同样由 PCB 保存；而内存中的代码和数据本身不需要搬进 PCB（它们常驻内存，PCB 只需记住"如何找到它们"）。

> **易错点**：PCB 里保存的是寄存器状态与地址映射关系，不是进程的代码和数据本身。内存不足时换出进程，本质上换出的是这些"现场信息"。

## PCB 的组成与组织方式

[00:42:00 - 00:45:00]

PCB 中包含 PC、SP 等寄存器状态，以及 PID、调度优先级、打开文件列表等信息。其中 PID 即进程标识符，可理解为进程编号，用来区分每个 PCB 属于哪个进程、并据此检索。系统中同时存在多个进程，每个都有自己的 PCB，因此需要把它们组织起来，常见方式有：在内核区中开辟数组存放 PCB、用链表链接 PCB、以及用 PID 索引 PCB 的索引表。这三种组织方式本身不是重点。

## 进程的特征

[00:45:00 - 00:48:00]

动态性：进程有创建、活动、暂停、终止的生命周期，是动态产生、变化和消亡的，这是进程最基本的特征。并发性：系统中多个进程在一段时间内交替执行，宏观上仿佛同时运行。独立性：进程实体是能独立运行、独立获取资源、独立接受调度的基本单位，PCB 是它的唯一标识。异步性：各进程相互制约，导致执行结果不可再现，因此需要配套的同步机制。这几个特征了解含义即可，考频不高。

> **易错点**：并发 ≠ 并行。单 CPU 系统中各进程无法并行执行，只能在一段时间内交错执行（并发）。

## 用户态/内核态切换不改变进程

[00:48:00 - 00:56:00]

进程的虚拟地址空间同样包含用户空间与内核空间：用户空间只能在用户态访问，内核空间必须在内核态访问，但二者位于同一个地址空间中、是连在一起的。进程在用户态响应中断或异常时，只发生特权级变化，映射关系丝毫不变：占着 CPU 的仍然是 P1，只是 P1 获得了内核空间的访问权限，执行流在自己的地址空间内跳到内核代码去执行。只有地址映射关系改变（换成另一进程的映射表）才叫进程发生变化。所以"内核进程/中断处理进程接管了 CPU"这类表述是错的，准确说法是"P1 处于内核态"或"操作系统接管了 CPU"。此外，不同进程的一小段内核空间映射到同一块操作系统物理内存，即内核空间是共享的，这一点下节课细讲。

> **易错点**：中断、异常只改变特权级，不改变地址空间，因此不发生进程切换；这是很多教材表述容易造成的误解。

## 五状态模型及各状态含义

[00:56:00 - 01:01:00]

五状态模型包含创建态、就绪态、运行态、阻塞态（等待态）、退出态。创建态：PCB 已分配，正在分配除 CPU 以外的资源，主要就是内存（以及页表等）。就绪态：除 CPU 以外的所有条件均已满足，万事俱备、只欠 CPU。运行态：进程正占用 CPU 执行。阻塞态：等待某个事件发生或等待 CPU 以外的资源（缺内存、缺 I/O 设备等），满足后才能运行。退出态：进程终止，归还所占资源并回收 PCB；退出方式有正常结束、主动退出（系统调用）、致命错误被强制终止、被更高权限者杀死四种。408 范围内常见的阻塞原因：发起 I/O 并等待设备分配或完成、对小于等于 0 的信号量执行 P 操作、管程条件变量 wait、创建进程时申请不到足够资源（内存不足）。

> **易错点**：就绪态缺的只是 CPU；阻塞态缺的是 CPU 以外的资源或所需事件尚未发生。"万事俱备只欠 CPU"是就绪，"等资源/等事件"是阻塞。

## 五状态之间的转换

[01:01:00 - 01:07:00]

创建→就绪：创建完成即进入就绪队列。就绪→运行：调度程序选中该进程。运行→阻塞：进程执行中请求资源或等待事件未满足，只能由运行态发起，因为只有进程自己执行到那一步才知道要等什么，其他进程无法替它预判并剥夺。运行→就绪：时间片用完，或被更高优先级的就绪进程抢占 CPU。阻塞→就绪：等待的事件发生（多由中断触发检测），进程回到就绪队列。运行→退出：执行完毕、出错或被杀。此外，进程也会因等待资源而由运行进入阻塞，待事件发生后再回到就绪，如此循环。

> **易错点**：不存在"就绪→阻塞"。进程没运行就没有发现自己缺资源的时机，操作系统也不会把未运行的进程标记为缺资源。阻塞只能转到就绪，不能直接转到运行，即使优先级最高也要重新被调度。

> ⚠️ **需回看视频 [01:03:00]**：口误/表述存疑——老师讲到"运行→就绪"时说"这个其实有有点问题啊，有点问题，不知道啥"，随后直接按"被抢占→就绪"继续，转写未交代"问题"具体所指 —— "然后第四个就是运行它有可能到就绪，这个其实有有点问题啊，有点问题，不知道啥。"

## 课间答疑：地址空间与内核空间

[01:07:00 - 01:14:00]

地址空间就是进程使用的虚拟地址范围、物理地址范围以及二者之间的映射关系，核心是映射关系；因此映射关系变即地址空间变、即进程变。各进程的内核空间映射到同一块存放操作系统的物理内存，所以内核空间是共享的。共享库属于用户进程的资源，不属于内核空间（其机制在内存管理的动态链接部分再讲）。

## 进程的完整生命周期

[01:14:00 - 01:16:00]

计算机启动后创建新进程，进程进入创建态；创建完成进入就绪队列；被调度程序选中后进入运行态；运行中时间片用完或被抢占则退回就绪态；请求资源得不到满足则进入阻塞态，事件发生后回到就绪态；执行完毕、出错或被操作系统杀死则进入退出态并回收资源。这条闭环就是五状态模型下进程从创建到消亡的全过程。

## 七状态模型：挂起与激活

[01:16:00 - 01:20:00]

内存空间不足时，操作系统把短期内不会执行的进程换出到外存，这个操作叫挂起；把外存中更可能执行的进程换入内存，叫激活。能被挂起的是就绪态和阻塞态进程，于是新增就绪挂起、阻塞挂起两个状态：阻塞挂起指进程既在等待事件、又身在外存；就绪挂起指进程身在外存，一旦调入内存并分到 CPU 即可运行。新增的转换为：就绪↔就绪挂起、阻塞↔阻塞挂起、阻塞挂起→就绪挂起（等待的事件发生）。挂起由内存不够触发，激活由内存空出触发；挂起进程必须先激活进入内存中的就绪态，才可能被调度执行。

> **易错点**：阻塞挂起状态下事件发生后，进程先转为就绪挂起（仍在外存），而不是直接变成就绪；必须再经激活调入内存。

## 进程调度与进程切换

[01:20:00 - 01:22:00]

在多道程序系统中，内存中有多道程序相互争夺处理机。处理机调度就是从就绪队列中按一定算法选择一个进程，把 CPU 分配给它，以实现进程的并发执行。触发时机是：当前运行的进程因阻塞或时间片用完等原因让出 CPU，需要从就绪队列中另选一个进程上 CPU。进程切换则是"P1 下 CPU、P2 上 CPU"的实际动作，它不能直接发生，必须先做准备工作：切换前保存当前进程的上下文，切换后恢复目标进程的上下文，并保证切换足够快。进程切换意味着从一个地址空间换到另一个地址空间，因此要切换内存地址空间以及 PCB 中保存的寄存器与 CPU 状态。

## 上下文的保存与恢复

[01:22:00 - 01:26:00]

保存上下文：P1 处于运行态时，把 CPU 内部状态（PC、寄存器等）和地址空间（映射关系）写入 P1 的 PCB，以便将来能回到此刻继续执行。恢复上下文：把 PCB 中的映射关系装回，使 CPU 能访问 P1 的物理内存，再把 PC 和各寄存器写回，执行流就能从上次被打断的那条指令之后接续。P0→P1 切换时把 P0 的状态存入 PCB0、从 PCB1 取出 P1 的状态；运行一段时间后切回 P0，则保存到 PCB1、从 PCB0 恢复。保存与恢复上下文是进程能够被反复切换却仍能接续执行的保证。

## 进程切换前后都处于内核态

[01:26:00 - 01:30:00]

进程切换不可能在用户态发起：决定"当前进程是否该被换下"的是操作系统，用户态下运行的进程根本没有这个概念。因此 P0 被切换的前提是它已因其他原因（时钟中断、系统调用等）进入内核态。典型过程：P0 在用户态运行时发生时时钟中断，保存断点后进入内核态执行中断服务程序；在中断处理中检查时间片，发现 P0 已不适合继续占用 CPU，于是在内核态调用调度程序选中 P1。所以进程调度发生的时刻处于内核态；切换前 P0 在内核态，切换后 P1 也处于内核态（它同样是被中断/系统调用打断后才被换下的，正等待内核恢复现场）。宏观上看到的是"用户态 P0 → 用户态 P1"，实际路径是 P0 用户态→P0 内核态→切换→P1 内核态→P1 用户态。

> **易错点**：进程切换是"内核态→内核态"，进程调度也发生在内核态；"用户态→用户态"只是宏观表象。

## 进程切换的完整过程

[01:30:00 - 01:37:00]

完整链条：P0 在用户态执行 → 时钟中断/异常/系统调用 → 保存断点、进入内核态执行处理程序 → 检测出 P0 不宜继续占用 CPU → 在内核态调用调度程序选中 P1 → 把 P0 的上下文（地址空间、各寄存器、内核栈等）保存到 PCB0 → 从 PCB1 恢复 P1 的上下文并切换地址空间 → P1 从自己上次被换下时的内核态位置继续执行 → 处理完内核中的事务后恢复 P1 的用户态断点 → 回到 P1 用户态。反方向切换（P1→P0）是完全对称的逆过程。进程正常结束时也类似：进入内核态销毁自身，再切换到新进程。

> **易错点**：P1 被恢复后先在其内核态继续执行未完成的中断处理，全部处理完才返回用户态；因此"切换后直接执行用户代码"是错的。

## 中断处理与进程切换的上下文切换区别

[01:37:00 - 01:46:00]

一次调度过程中会出现两次上下文保存/恢复：一次是中断响应保存用户态现场（存到内核栈），一次是进程切换保存内核态现场（存到 PCB）。四点是区别：①中断处理中上下文的保存与恢复是分开的，分别在中断响应和中断返回时进行；进程切换的保存与恢复紧接着成对完成。②中断处理保存的是中断发生前进程的用户态上下文；进程切换保存的一定是内核态上下文。③中断处理本身不切换地址空间（除非过程中发生了进程切换），进程切换必然切换地址空间。④中断处理可能发生特权级切换（用户态→内核态），进程切换全程在内核态，只有内核态→内核态。之所以需要两次，是因为两次被改变的"现场"层次不同：外层是用户态断点，内层是内核态执行现场。

> **易错点**：中断响应（硬件）只保存断点，即 PC 与 PSW；通用寄存器等其余上下文由中断处理程序保存。中断处理 ≠ 中断响应，后者仅指硬件响应那一步。

> ⚠️ **需回看视频 [01:38:00]**：转写零散、术语边界不清——涉及"断点具体保存哪些内容"以及运行态与就绪/阻塞态 PCB 的差异（状态字段 running/ready/blocking），现场为问答且语句碎片化 —— "保存断点是保存了哪些东西你只需要去回到上一次课去再好好看一看，其实就是PC和PSW，然后还有这里个中断服务程序里面还有个保存上下文。"

> ⚠️ **需回看视频 [01:44:00]**：口误后更正，转写中两种说法混杂——老师中途把对比表中的"中断响应"统一改为"中断处理"，但转写前后仍混用，第四条的适用对象需确认 —— "这里其实中断响应这个说法不对，我把它全改了吧。是中断处理，中断响应它只管断点，对吧？"

## 进程创建

[01:46:00 - 01:49:00]

进程由进程创建，创建者 A 为父进程，被创建的 B 为 A 的子进程。创建步骤：①申请 PID 和空白 PCB，成功后进程进入创建态；若连 PCB 都申请不到（系统可容纳进程数已满），本次创建失败。②申请进程所需的其他资源（内存、文件、I/O 设备等），可从操作系统获得，也可从父进程获得。③初始化 PCB，把申请到的资源（如页表、地址映射）与 PCB 关联起来。④把新 PCB 插入就绪队列，进程进入就绪态。

> **易错点**：只有 PCB 申请失败才导致创建失败。其他资源不足不会使创建失败——PCB 已存在即进程已存在（处于创建态），此时是阻塞父进程，等资源满足后再继续。

## 进程终止

[01:49:00 - 01:50:00]

终止以 PID 为参数：通过 PID 检索到对应 PCB → 将进程状态置为退出态 → 若该进程正在运行，则需进行调度，让新进程上 CPU → 归还进程占用的全部资源 → 回收其 PCB。注意不同系统对终止的处理不完全相同：例如"父进程终止则其子进程一并终止"只在 Windows 下成立，Linux 并非如此，不能当作通用结论（真题曾考查过这种绝对化表述）。

## 进程阻塞与唤醒

[01:50:00 - 01:52:00]

阻塞同样以 PID 为参数：检索 PCB → 把 PCB 中的状态字段由运行（running）改为阻塞（blocking）→ 把该 PCB 插入对应事件的阻塞队列 → 进行处理器调度并切换进程。每个阻塞原因（事件）都对应一个阻塞队列。唤醒是逆过程：事件发生时，操作系统从该事件的阻塞队列中取出一个 PCB，将其移出阻塞队列、状态由阻塞改为就绪，再插入就绪队列等待调度。阻塞与唤醒通常由系统调用触发，成对出现。

## 父进程与子进程

[01:52:00 - 01:55:00]

A 创建 B，则 A 是父进程、B 是子进程。多数系统中父子进程共享部分全局资源，并存在继承关系：父进程已打开的文件、创建的管道、设备等可被子进程继承，子进程通常也继承父进程对这些资源的访问权限（文件、管道部分后续课再展开）。但父子进程不共享地址空间：虚拟地址到物理地址的映射关系不继承，同一虚拟地址在两者中指向不同物理内存。某些系统（如 Linux 的 fork）会复制父进程的虚拟地址空间，但"复制"不等于"共享"：复制是各拿一张纸抄一份，此后互不影响；共享是共用一张纸，一方修改另一方立即可见。

> **易错点**：fork 后子进程复制父进程的地址空间但并不共享内存；"子进程修改父进程数据会影响父进程"的说法不成立。可能被继承的是文件、管道等资源。

## 进程的隔离性与线程的引入

[01:55:00 - 02:00:00]

进程最核心的特点是拥有自己独立的地址空间：每个进程都有自己的"领地"，P1 碰不到 P2，彼此互不影响。但完全隔离在需要协作时会变成枷锁。以 MP3 播放软件为例，它有三个核心功能——从文件读数据（用 I/O 设备）、解压缩（用 CPU）、播放解压后的数据，三者本可重叠进行（边读后面的、边解压前面的、边播放已解压的）以提高效率。若做成三个进程，读出的数据只能待在自己进程的内存里，P2 拿不到 P1 的数据、P3 也拿不到 P2 的结果，地址隔离反而阻断了接力。于是需要引入一种"可并发执行、但共享地址空间"的实体——线程。

## 线程的定义与共享/私有资源

[02:00:00 - 02:03:00]

线程是进程内部的一类实体：它们之间可以并发执行，并且共享所属进程的地址空间——相同的虚拟地址一定访问到相同的物理地址。一个进程的所有任务指令都放在该进程的代码段中，各线程分别执行其中不同的代码、协同完成工作。线程共享代码段、数据段、堆以及打开的文件等进程级资源；但每个线程需要自己独立的栈（保存局部变量）、PC 和通用寄存器，因为各自的指令流和执行位置不同。

> **定义**：线程是进程内可并发执行、并共享进程地址空间的执行实体，是处理机（CPU）调度的基本单位。
> **易错点**：线程共享地址空间、代码、数据和堆，但不共享栈与寄存器组；把"栈共享"当成线程特征是常见错误。

## 进程与线程的比较

[02:03:00 - 02:04:00]

进程是资源分配单位：内存、文件、管道等资源都以进程为单位申请；线程是 CPU 调度单位：真正执行任务、占用 CPU 的是线程。进程提供一个完整的资源平台，线程独享的只有指令执行所需的寄存器和栈。线程也有就绪、运行、阻塞三种基本状态。线程能减少并发执行的时间与空间开销：创建比进程快（无需分配内存等资源）、终止更快、切换更快（不必切换地址空间），同进程内各线程共享内存与文件资源，可不经内核直接通信。与 PCB 对应，线程有独立的控制数据结构 TCB。

## 用户级线程

[02:04:00 - 02:09:00]

用户级线程由用户空间的线程库实现和管理，内核完全不知道其存在：内核只按 PCB 管理进程、以进程为单位分配 CPU 时间，进程内部再用线程库函数把任务切成多个执行实体。类比：政府（内核）只按户（进程）拨款，家里有几口人（线程）、钱怎么分，全由家庭自己决定，政府对每个人是"透明"的。特点：不依赖操作系统内核、可用于本身不支持线程的多进程系统、每个进程自己维护线程表并由线程库函数管理、同一进程内线程切换在用户空间完成（无需用户态/内核态切换）因而很快、每个进程可拥有自己的线程调度算法。不足：一个线程发起系统调用而阻塞时，整个进程都被阻塞（内核视角下只有进程）；且不支持基于线程的处理器抢占，CPU 时间只能按进程分配。

> **易错点**：用户级线程"切换快"的根源是不陷入内核；代价是一个线程阻塞会拖垮整个进程，且无法按线程抢占 CPU。

> ⚠️ **需回看视频 [02:08:00]**：疑似 ASR 术语识别错误——用户级线程的线程控制块应为 TCB，转写多处写成"TCP" —— "然后每个进程有自己的TCP列表，每个进程自己维护TCP，然后由线程库函数维护。"

## 内核级线程

[02:09:00 - 02:11:00]

内核级线程由内核维护 TCB，内核知道每个线程的存在，能对线程逐个创建、终止、管理和调度。沿用上面的类比：政府变成"以人为本"，直接按每个人（线程）拨款，人对政府不再透明。优点：一个线程阻塞只阻塞该线程，同进程的其他线程仍可执行；可以线程为单位分配 CPU 时间。缺点：创建、终止、切换都要由内核完成，需陷入内核态再返回用户态，开销较大。混合方式则是一部分线程由用户线程库实现，一部分由内核管理。

## 多线程模型

[02:11:00 - 02:15:00]

按用户线程与内核线程的对应关系分三类。多对一：同一进程的所有用户线程映射到同一个内核线程，效果与用户级线程类似——一个线程阻塞则全部阻塞，切换开销小。一对一：每个用户线程对应一个内核线程，效果与内核级线程类似——创建与切换开销大，但一个线程阻塞不影响其他线程。多对多：m 个用户线程对应 n 个内核线程（多路复用），由这 n 个内核线程统筹管理这些用户线程。考频不高，掌握"哪些内核线程管理哪些用户线程"这一对应关系即可。

> ⚠️ **需回看视频 [02:14:00]**：转写内容残缺、语义不通——多对多（多路复用）模型的说明只剩零散词句，无法确认准确表述 —— "多路复用就是多个用户级线程同样数量，就是它有可能就是这些线程，然后由这些内核线程然后统筹管理。"

## 课后答疑：若干易错点澄清

[02:15:00 - 02:24:23]

①父子进程不共享地址空间，未做特殊共享处理时，"子进程修改父进程共享内容"的前提不成立；可继承的是已打开文件等资源，具体依系统设计而定。②PCB 中设有专门字段记录进程状态（running/ready/blocking），这就是运行态与就绪态、阻塞态 PCB 的主要区别。③上下文切换不等于"只对 PCB 操作"，它还包含与寄存器等计算机内部状态的交互。④只有进程真正运行过、并在执行中发现缺少资源，操作系统才会把它标记为阻塞；"客观上缺资源"不算。创建后尚未运行的进程只能是就绪态，因此没有"创建态→阻塞态"这条转换。⑤单核处理器上，即使一个进程内有多个线程，同一时刻也只能有一个线程执行。⑥普通系统调用与异常处理一般不引起进程切换，只有满足调度条件才会切换；只有创建进程等特定系统调用才产生新进程。

> **易错点**：状态是否"缺资源"由操作系统认定，而认定的唯一时机是进程运行中执行到请求资源那一步；未运行就谈不上阻塞。
