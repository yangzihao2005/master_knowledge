# 第12讲 输入输出系统（I/O）

## 【视频01】导学：什么是 I/O，本讲学什么

[00:00:00 - 00:03:00]

本讲讲 I/O，内容较多但难度不大，考查方式较集中。`I/O` 是输入输出组织（Input/Output）的简称，本讲在原有知识点之外先补充"IO 学什么"。全讲围绕"一个硬件、两个模型"展开：硬件指 `IO接口`，两个模型指外设与 CPU、外设与内存之间的数据传送模型。后续内容都围绕这三个点凝聚展开。

> **定义**：`I/O` 即输入输出组织，是控制外设与内存、外设与 CPU 之间数据交换的软硬件结合子系统。

## 【视频01】I/O 系统的功能与要解决的四个问题

[00:03:00 - 00:06:00]

`I/O` 即输入输出组织，它只干两件事：一是控制外设与内存之间的数据交换，二是控制外设与 CPU 之间的数据交换。通常把外部设备及其接口、I/O 控制部件以及 I/O 软件统称为输入输出系统，其中 I/O 软件部分属于操作系统内容，组原侧重外设接口与 I/O 控制部件的特性。

实现输入输出功能要解决四个问题：①如何在 CPU、主存与外设之间建立高效的信息传送通路（本讲重点，三星）；②如何把用户的 I/O 请求转换为设备控制命令（重点，次之）；③如何对外设编址以便 CPU 查找外设；④ I/O 接口与软件如何协调完成主机与外设间数据传送（多结合操作系统考查）。组原重点在前三个，其中①②是重中之重。

> **定义**：输入输出系统 = 外部设备及其接口 + I/O 控制部件 + I/O 软件。

## 【视频01】一个硬件、两个模型；最基础 I/O 系统的构成

[00:06:00 - 00:11:00]

本讲三大重点：一个硬件——`IO接口`；两个模型——外设与 CPU 的数据交换（`中断`方式）、外设与内存的数据交换（`DMA`方式）。

最基础的 I/O 系统由三部分构成：`CPU`、`IO接口`、`外设`。CPU 与 IO 接口经一根系统总线相连，IO 接口再连接外设。现实主板上能看到多个 IO 接口（USB、网口、音频口等），现代还常用专门的 IO 芯片统一管理各设备接口；但 408 考查的是 CPU 直接控制 IO 接口的最基础结构。

> **易错点**：主板实物上多个插口可能同属一个 IO 接口硬件的不同逻辑分支，不要一个插口算一个接口。

## 【视频01】两个数据传送模型：中断方式与 DMA 方式

[00:11:00 - 00:13:00]

模型一：外设经 `IO接口` 与 `CPU` 交换数据，采用 `中断`方式——外设通过 IO 接口与 CPU 进行数据交互。模型二：外设与 `主存` 交换数据，经 `DMA控制器`（又称 DMA 接口）完成数据传送，典型如磁盘与主存之间的数据交互。

因此本讲虽内容多但很凝聚：一个硬件（IO 接口的功能、组成）加两个模型（`中断`模型、`DMA`模型）。

## 【视频01】什么是 I/O 接口（设备控制器），内部接口与外部接口

[00:13:00 - 00:17:00]

主机部件（CPU、内存）是高速元器件，而大多数外设是低速设备，二者技术特性差异大、各有独立时钟与时序控制，多采用异步工作方式；408 只考异步方式（同步方式理论上存在但实际不用）。

`IO接口` 又叫 `设备控制器`，是连接外设与 CPU 的中间件：CPU 把数据传给中间件，中间件再交给外设，反之亦然。它在主机侧和外设侧各有一个接口——主机侧称内部接口（与 CPU、内存相连），外设侧称外部接口（经 USB 线、网线等接口线缆连外设）。一个 IO 接口硬件内部可分出多个具体逻辑口。

> **易错点**：CPU 与外设时钟不一致，二者之间采用异步方式；考试不会考同步方式。

## 【视频01】I/O 接口的内部组成及各部分功能

[00:17:00 - 00:23:00]

`IO接口` 硬件内部主要由三部分组成：① `数据缓冲寄存器`，暂存 CPU 发来的数据和设备送来的数据；② `状态控制寄存器`，保存 CPU 控制设备的控制指令（命令字）以及设备反馈给 CPU 的状态信息；③ 地址译码和 I/O 控制逻辑，对访问的 IO 寄存器号进行译码并生成控制信号。

命令字（控制指令）由一串比特构成，经系统总线的数据线送入控制状态寄存器，再由地址译码和 IO 控制逻辑译码，经外设界面控制逻辑把控制信号送给外设。控制线主要传送控制/状态信号（如 `read`、`write`、握手信号 `ready`、寄存器清零等），数据线则传送具体数据以及 CPU 给出的命令字。

## 【视频01】例：CPU 对打印机执行开机的完整流程

[00:23:00 - 00:26:00]

CPU 对打印机执行开机：① CPU 把开机控制命令（命令字，类似指令但不等同）经数据线送到 IO 接口的状态控制寄存器；② 地址译码和 IO 控制逻辑对该命令字译码，并把译码得到的控制信号经外设界面控制逻辑送到外设；③ 打印机收到控制信号后执行开机操作；④ 开机后设备把设备状态以 `状态字` 形式送回控制状态寄存器，再经数据线送回 CPU。

状态字由多个比特构成，类似前面讲的 `PSW` 中保存的状态信息，例如打印机是否已开机、是否有纸张、墨盒墨量是否足够等。

## 【视频01】I/O 端口及其两种编址方式（统一编址与独立编址）

[00:26:00 - 00:34:00]

`IO端口` 指的是 IO 接口中的寄存器：数据缓冲寄存器即数据端口，控制状态寄存器即控制状态端口。为便于 CPU 快速选择设备与寻址，需对 IO 接口中各可访问寄存器编址，有两种方式。

`统一编址`：IO 地址空间与主存地址空间统一编址，IO 端口占用主存地址空间、被视为存储单元，可用 `load`/`store` 等访存指令直接读写，所有主存寻址方式都适用于 IO 端口；靠地址范围区分访问的是 IO 端口还是主存单元，无需专门 IO 指令。例：CPU 先送数据 `1234H`，再送"开始打印"命令字，经地址译码和 IO 逻辑生成控制信号后打印机打印该数据。

`独立编址`：所有 IO 端口单独编号，形成独立的 IO 地址空间；指令系统中需有专门的 IO 指令，指令的地址码部分给出 IO 端口号。两地址空间无法从地址码形式区分，须用专门 IO 指令访问，如 x86 的 `in`、`out`。

两者区别：① 地址空间是否与主存统一；② 访问指令（访存指令 vs 专门 IO 指令）；③ 区分依据（地址范围 vs IO 指令操作码）。

> **易错点**：独立编址下 `load`/`store` 不能访问 IO 端口，必须用专门 IO 指令。

## 【视频01】程序查询方式：独占查询与定时查询及工作过程

[00:34:00 - 00:44:00]

CPU 处理 IO 请求有三种方式：`程序查询`、`中断`、`DMA`，后两者是重点。`程序查询`（又称异步传送方式）下信息交换完全由 CPU 执行程序控制，IO 接口中设数据缓冲寄存器和设备状态寄存器，主机先发询问信号读取设备状态，再据状态决定传送还是等待。

按查询启动方式分两种：`独占查询`——CPU 被独占用于某设备 IO，花费 100% 时间在 IO 操作上，外设与 CPU 完全串行；`定时查询`——周期性查询接口状态，每次查询等到满足条件才传送数据，传送完返回用户程序，查询时间间隔与设备数据传输率有关。

例（打印机开机）：① CPU 执行初始化程序，把开机命令字经总线送到 IO 接口，IO 接口译码后把信号发给打印机；② CPU 执行类似 `while` 循环的查询程序，循环检查 IO 接口是否收到外设给出的 `ready` 信号，不等于 ready 就一直查；③ ready 到达后退出循环；④ 执行后续数据传送程序；⑤ 返回。

缺点：查询期间 CPU 无法执行其他工作，时间大量耗费在等待慢速外设上，这也促成了后来 `中断`方式的提出。

> **易错点**：组原中程序查询方式唯一考过的是 `定时查询`；`独占查询` 分量在同操作系统结合进程时才考。

## 【视频01】定时查询真题与 K/M/G 单位区别

[00:44:00 - 00:49:00]

2011 统考真题：处理器主频 `50MHz`，采用定时查询方式控制设备 A 的 IO，查询程序运行一次至少 `500` 个时钟周期，为保证数据不丢失每秒至少查询 IO 接口 `200` 次。用于设备 A 的 IO 时间占比 = `(500 × 200) / 50M`。题意是每次查询约 `500` 周期、每秒 `200` 次，故占比很小。

关于 `K/M/G`：表示容量时为 1024 进制（`1024` / `1024²` / `1024³`）；表示速率时为 1000 进制（`1000` / `1000²` / `1000³`）。本题主频属速率，故按 1000 进制换算。

> **公式**：CPU 用于设备 IO 的时间占比 = 每秒查询次数 × 每次查询时钟周期数 ÷ 主频对应时钟周期数。

## 【视频01】中断控制方式的思想与三个核心问题

[00:49:00 - 01:09:00]

现代计算机都配有完善的异常和中断处理系统：CPU 数据通路中含异常与中断的检测和响应逻辑，外设接口中含中断请求和控制逻辑。即中断请求由 `IO接口` 发出、中断响应由 `CPU` 执行，配合操作系统中的 `中断服务程序` 共同完成处理，故又称程序中断 IO 方式。

`程序查询`方式下（无论独占式还是定时式）CPU 与外设都是串行工作，CPU 时间被花在等待慢速外设上。`中断`方式的思想是：CPU 执行主程序指令时，在每条指令的中断周期检查是否有外部设备产生的中断信号，有则暂停下一条指令、经硬件处理的中断响应周期转去执行中断服务程序，无则继续执行原程序。

中断方式下要研究三个问题：① 什么时候响应中断（在指令的中断周期）；② 同时检测到多个中断信号时先响应谁；③ 执行中断服务程序过程中又出现新中断时如何处理。

> **易错点**：一条指令的机器周期常划为取指、间址、执行、中断四个周期，中断只在**中断周期**被响应，即使信号在取指/间址/执行周期就已到达。

## 【视频01】中断响应的硬件实现；中断产生与中断响应的区别

[01:09:00 - 01:22:00]

答疑要点：中断响应不是执行一段程序，而是由 `硬件` 完成的三个步骤——关中断、保存断点（保存 `PC` 和 `PSW`）、识别中断服务程序（识别中断源）。这三步都是硬件操作，与 CPU 执行程序无关。

须区分中断**产生**与中断**响应**：中断的产生是随机的（何时按键、何时动鼠标由人决定，CPU 无法控制），而中断的响应有规范——只能在一条指令的中断周期响应；真题中"执行完指令后再响应中断""一条指令结束后响应中断"（2017 年出现过）都是同一意思。响应的主体是 CPU，产生的主体是人的动作/外设。

> **易错点**：CPU 不能决定中断何时产生，但能决定何时响应；响应永远发生在中断周期。

## 【视频01】例：键盘传送字符 A 与中断请求寄存器

[01:22:00 - 01:29:00]

以键盘传送字符 `A` 为例：① 键盘把字符 A 经通信线送到 IO 接口的数据缓冲寄存器；② 每当 IO 接口内的数据缓冲寄存器收到数据，就由 `IO接口` 产生中断信号给 CPU（**重点**：中断信号不是外设产生的，外设只提供数据）；③ CPU 不会立即响应，因为信号到达时刻随机，可能正处于取指/间址/执行/中断任一周期，只有在中断周期才响应；④ 响应后执行数据读入程序，把数据从 IO 接口读入 CPU；⑤ 执行完毕返回。键盘每传送一个字符就发起一次中断、调用一次中断服务程序。

`中断服务程序` 运行在 CPU 与 IO 接口之间（从 IO 接口读数据给 CPU，或把 CPU 数据写回 IO 接口），与外设无关。由于中断信号随机，CPU 内部设 `中断请求寄存器`：记录各种类型的中断请求信号，并在每条指令指定的中断周期采样中断请求引脚进行检测，发现请求时决定是否响应及响应哪一个。

> **易错点**：中断的发出者是 IO 接口而非外设；中断服务程序的两端是 CPU 和 IO 接口。

## 【视频01】中断响应优先级、不可屏蔽中断与内部异常

[01:29:00 - 01:41:00]

`中断响应优先级`：在执行主程序的中断周期采集到多个中断源时，决定先响应谁。它由 `硬件` 决定、CPU 出厂即固定（中断判优电路实现），每种外设都有对应的响应优先级。四条规则：① `不可屏蔽中断` > 内部异常 > 可屏蔽中断；② 内部异常中，硬件故障 > 软件中断；③ `DMA` 中断 > IO 设备中断；④ IO 传送类中断中，高速设备 < 低速设备，输入设备 > 输出设备，实时设备 > 普通设备。

`不可屏蔽中断`（NMI）由硬件故障或其他严重错误引起，无法被处理器屏蔽或禁用，优先级最高，如电源波动、芯片接触不良、CPU 过热——CPU 过热会强制关机，任何状态都挡不住。

内部异常举例：硬件故障——如存储单元损坏，`load` 指令本身没错、地址也对，但取出的数据通不过校验，错误源于主存硬件；软件中断——如整数除零（`a = 5 / 0`），由指令本身引发，程序被强制中止。

> **易错点**：`中断响应优先级` 与后面的 `中断处理优先级` 极易混淆；响应优先级的作用场景是"执行主程序"时。

## 【视频01】中断响应条件、中断隐指令与中断向量

[01:41:00 - 01:56:00]

2020 真题：外部中断包括不可屏蔽中断和可屏蔽中断，错误项为"一旦可屏蔽中断请求信号有效，CPU 要立即响应"——CPU 只在中断周期响应。

`中断响应` 三个条件：① CPU 处于 `开中断` 状态；② 至少有一个未被屏蔽的中断请求；③ 当前指令刚执行完、刚进入中断周期。中断响应周期是特殊机器周期，完全由硬件实现——硬件自动执行一条 `中断隐指令`（408 只考硬件判优法），完成三件事：① 关中断（屏蔽所有可屏蔽中断，NMI 仍可响应）；② 保护断点（保存 `PC` 和 `PSW`，注意进入中断周期时 PC 已是后继指令地址）；③ 识别中断源并转中断服务程序（把中断服务程序首地址与初始 `PSW` 送入 PC、PSW）。

硬件判优法：由中断判优电路和编码器选出当前未屏蔽中断请求中响应优先级最高者的标识（如 `IRQ1`），CPU 据此查表。向量中断方式下，把中断服务程序的首地址（PC）和初始 `PSW` 合称 `中断向量`，所有中断向量统一存放在 `中断向量表` 中；向量在表中的位置称中断向量地址。

> **公式**：`中断向量地址 = 中断类型号 × 单个中断向量字节数 + 中断向量表基地址`（如一个向量 4 字节，`IRQ1` 即基地址 + `4 × 1`）；单个向量大小依题目而定，8 字节就乘 8。

## 【视频01】中断服务程序的执行过程与 CPU 时间占比真题

[01:56:00 - 02:11:00]

执行 `中断服务程序` 由 CPU 完成，过程为：① 保存现场和屏蔽字（现场指通用寄存器组的内容，另存屏蔽字）；② 进入开中断；③ 执行中断服务程序；④ 关中断；⑤ 恢复现场（还原通用寄存器）；⑥ 开中断；⑦ 中断返回（复原 PC 和 PSW）。其中中断响应由硬件完成，保存现场起才由 CPU 执行。

2014 真题：设备中断请求的响应与处理合计 `100ns`，每 `400ns` 发出一次中断请求，中断响应允许最长延迟 `50ns`，问 CPU 用于该设备 IO 的时间占比。理想情况下每 `400ns` 内有 `100ns` 处理中断；即使存在延迟（50ns 或 20ns），在一个 `400ns` 区间内仍是 `100ns` 用于中断，故占比 = `100 / 400 = 25%`。

2019 真题（同款）：CPU 主频 `1GHz`，设备接口数据缓冲寄存器 `32位`，设备数据传输速率 `50KB/s`，每次中断开销 `1000` 个时钟周期，求 CPU 用于该设备 IO 的时间占比。外设每秒产生 `50K` 字节数据，缓冲寄存器每满一次发一次中断，故每秒中断次数 = `50K ÷ 4`，占比 = `(50K ÷ 4) × 1000 / 1G`（选 A）。

> **公式**：每秒中断次数 = 传输速率 ÷ 数据缓冲寄存器字节数；占用比例 = 每秒中断次数 × 每次中断开销时钟数 ÷ 主频对应时钟周期数。

## 【视频01】多重中断嵌套、中断处理优先级与中断屏蔽字

[02:11:00 - 02:48:00]

`中断嵌套`：中断系统允许 CPU 执行某个中断服务程序时被新的中断请求打断；但重要紧急事件可通过 `中断屏蔽` 机制设为不可被某些中断打断。中断屏蔽机制使每个中断可设置允许被哪些中断打断、不允许被哪些打断，由 `中断屏蔽字` 实现，屏蔽字中每一位对应一个外设中断源。

`中断处理优先级` 由 `中断屏蔽字` 实现，作用于"执行中断服务程序"时其指令的中断周期检测到的新中断，决定是否响应新中断还是继续执行。屏蔽字中该位为 1 表示屏蔽对应中断源。例：4 个中断源，处理优先级 `1>4>3>2`，则屏蔽字（按 1、2、3、4 位排列）分别为 `1111`、`0111`、`0011`、`0001`——高处理优先级者可屏蔽更多中断源。

与 `中断响应优先级` 的区别（易混）：响应优先级发生在**执行主程序**时，主程序指令的中断周期检测到多个中断源，据响应优先级决定先响应谁；处理优先级发生在**执行中断服务程序**时，据中断屏蔽字决定是否被新中断打断。响应优先级原则由硬件定好；处理优先级由屏蔽字定。另注：关中断、恢复现场、开中断、中断返回这四个是"操作"不是"指令"，没有中断周期，故在执行中断服务程序时未响应的中断，到这些步骤也无法再被响应。

例（原书例题）：响应优先级 `1>2>3>4`，处理优先级 `1>4>3>2`。执行主程序时中断源 1、3、4 同时请求——按响应优先级先响应 1；执行 1 的中断服务程序时其指令中断周期检测到 3、4，但 1 的处理优先级最高（屏蔽三、四）继续执行；1 服务程序执行完中断返回至主程序断点；主程序下一条指令的中断周期检测到 3、4，按响应优先级选 3；执行 3 时检测到 2、4，按处理优先级（`4>3>2`）转去执行 4；执行 4 时检测到 2，因 4 处理优先级高于 2 不响应，继续执行 4 后中断返回至 3 的下一条指令；3 继续执行（3 处理优先级 > 2），执行完返回主程序；主程序下一条指令的中断周期才响应 2。结论：中断服务程序执行期间未响应的高优先级以外中断，之后仍会按响应优先级被响应，但需等到下一处指令的中断周期。

真题：关于多重中断系统的描述，错误项为"中断处理期间 CPU 处于关中断状态"（执行中断服务程序时应为开中断）。2018 真题正确项为"处于中断允许状态时才能响应外部设备的中断请求"（鼠标、键盘等外设中断一般为可屏蔽中断）；错误项包括"中断控制器按接收中断请求先后次序进行优先级排序""响应中断时执行中断隐指令完成对通用寄存器的保护"（隐指令保护的是 PC 和 PSW）"有中断请求时 CPU 立即暂停当前指令执行"。

> **公式**：处理优先级越高者，其屏蔽字中可置 1 的位数越多（可屏蔽的中断源越多），从而不被低处理优先级中断打断。

> **易错点**：响应优先级看"执行主程序→主程序指令的中断周期"，处理优先级看"执行中断服务程序→其指令的中断周期"。

## 【视频01】异常与中断：内部异常的分类与响应

[02:48:00 - 03:01:00]

408 中提到的"中断"一般代指 `可屏蔽中断`，即外设通过主板上的 `IO接口` 产生的可屏蔽中断；`内部异常` 是程序执行过程中引起的意外事件，又称硬件故障和程序性异常。可屏蔽中断由外设随机产生，内部异常在程序执行（指令执行）过程中产生。

异常分三类：`故障`——在引起故障的指令启动后、执行结束前被检测到（如非法操作码、缺页、整数除零），缺页等可处理后续回到该指令继续执行，而非法操作码、保护错、除零无法恢复则必须终止程序；`自陷`——预先安排的异常事件（如系统调用/陷阱指令），CPU 执行完自陷指令后按陷阱类型处理，通常返回自陷指令的下一条指令（若是控制指令则返回转移目标）；`终止`——使机器无法继续执行的硬件故障（如电源断电、线路故障），转中断服务程序重启系统。

异常与中断的关键区别：异常由 CPU 自身的数据通路/电路检测、在指令的执行周期取指/间址/执行阶段产生并立即响应；中断由外设或时钟产生、随机、与任何指令不关联，必须等到中断周期才响应，且 CPU 需通过外部中断请求线采样获取。8086 不区分异常与中断，统称为中断：CPU 内部产生的称内中断（均为不可屏蔽中断），通过中断请求线从外部来的称外中断（`INTR` 发可屏蔽中断、`NMI` 发不可屏蔽中断，不可屏蔽中断处理优先级最高）。

真题（内部异常错误项）：错误项为"内部异常的处理有返回，返回到发生异常的指令继续执行"——并非所有内部异常都能返回。

> **易错点**：中断产生随机、必须在中断周期响应；异常在指令执行过程中产生、产生即响应。

> ⚠️ **需回看视频 [02:52:00]**：异常三分类被转写为"自陷、故障和中断"（"中断"应为"终止"），且"取指周期"被转写成"区域周期"，疑似 ASR 错字，需回看确认 —— "异常呢，又可以分成三类，分成这个自陷、故障和中断";"指令的区域周期、间周期和执行周期"

## 【视频01】DMA 控制方式与 DMA 控制器的组成

[03:01:00 - 03:11:00]

`DMA` 控制方式由专门的 DMA 接口（`DMA控制器`）硬件控制外设与主存之间的直接数据交换，用于解决模型二：外设与内存的数据传送。数据传输阶段数据不经 CPU，CPU 完全不用管数据的传送，主存经 DMA 控制器直接给外设（反之亦然），因此 DMA 数据传送是硬件控制的。

DMA 控制器与 `IO接口`（IO 设备控制器）师出同源、功能相近但略有升级，其功能部件前三个与 IO 接口完全一致（数据缓冲寄存器暂存主存与设备的数据；状态控制寄存器保存 CPU 控制 DMA 的控制字与设备反馈的状态），另多两个部件：`主存地址寄存器`（保存主存地址，正向反向都适用）和传送长度（控制长度）计数器（保存要传送的字节数，可实现从某地址起连续多个存储单元的数据收发）。

DMA 传送时 CPU 让出 `存储器总线` 的控制权，由 DMA 控制器控制存储器总线，最常见的做法是挪用一个存储周期完成主存与 DMA 控制器之间一次数据交换，也可独占若干存储周期完成一批数据交换。DMA 主要用于磁盘等高速块设备（网卡的数据也经 DMA 控制器与主存交互）。

例：CPU 想把主存中从 `00H` 起的 `24` 个字节送到磁盘——① CPU 做预处理，把 `00H` 存入主存地址寄存器、把 `24` 存入传送长度寄存器，再发启动命令；② 传送由 DMA 控制器完成，CPU 不参与；③ 每完成一次传送就把计数值减一、修改主存地址，计数值为 0 时结束并进入后处理。

> **易错点**：传送过程由 DMA 控制器硬件完成，但传送前（主存首地址、字节数、方向等参数设置）和传送后（数据校验）必须由 CPU 参与。

## 【视频01】DMA 的三种传送方式与 DMA 操作三步骤

[03:11:00 - 03:24:00]

2015 真题：采用 `中断`方式控制打印机输出时，CPU 与打印控制接口中的 IO 端口之间传输的信息不可能是"主存地址"——中断方式下 CPU 把数据给 IO 接口、IO 接口再给外设，全程不涉及主存；只有 `DMA` 方式下才需要主存地址。

DMA 数据传送的三种方式：① `CPU停止法`——DMA 传送时由 DMA 控制器发出停止信号，使 CPU 脱离总线、停止访问主存，直到传送完一块数据（了解概念即可，未考过）；② `周期挪用`（周期挪用法，重点、必背）——DMA 传输时 CPU 让出一个 `总线事务周期`，由 DMA 控制器挪用一个主存周期访问主存，传送完一个数据立即释放总线，属单字传送方式；③ `交替访问法`——每个存取周期分成两个时间片，一个给 CPU、一个给 DMA，类似存储器的分散刷新思想，每个存取周期都能访问存储器。

DMA 操作三步骤：① `DMA控制器的初始化`（CPU 执行处理程序，操作系统称驱动程序：准备内存区、设置传送参数——主存首地址、字节数、传送方向，再发送启动 DMA 传送的命令，之后 CPU 可执行其他程序）；② `数据传送`（完全由 DMA 控制器硬件完成，不需要 CPU 参与，每传送一次字计数值减一、修改主存地址，为 0 时完成全部传送）；③ `后处理`（计数值为 0 时 DMA 控制器/接口向 CPU 发出 DMA 结束的 `中断请求信号`，CPU 响应后转入中断服务程序做数据校验等后处理，不再传送数据）。

三种数据传送方式中，408 最常见、必须掌握的是 `周期挪用`；第一种和第三种了解概念即可。

> **易错点**：周期挪用（挪用一个存储周期、CPU 让出总线事务周期）与 CPU 停止法（CPU 停止访问主存直到整块传完）不可混淆。

## 【视频01】中断与 DMA 的区别、真题与本讲总结

[03:24:00 - 03:40:11]

中断与 DMA 的区别：① 数据传送方式——中断由 CPU 执行 `中断服务程序` 完成数据传送（软件控制，CPU 全程参与），DMA 由硬件完成传送（CPU 只做初始化和后处理）；② 与 CPU 争用的资源——中断争用的是 CPU 的处理时间，DMA 争用的是 `存储器总线` 的控制权；③ 优先级——DMA 与 CPU 同时产生访存请求时 DMA 优先级更高，DMA 传送完成后发出的中断请求与外设中断请求同时发生时 DMA 请求优先级更高。

2013 真题（错误项）："中断 I/O 方式适用于所有外部设备，DMA 方式仅适用于快速设备"——错误并非因 DMA 仅适用快速设备，而在于中断方式并非适用所有外设；值得考究的是"中断响应发生在一条指令执行结束后""DMA 响应发生在总线事务完成后"（说"机器周期"不严谨，因为执行周期可能不包含总线事务，如 `add R1, R2, R3` 不访存）。DMA 不能打断 CPU 正进行的总线事务，必须等该总线事务完成后再申请存储器总线控制权。

2019 真题（ABCD 全对）：DMA 传送前由设备驱动程序设置传送参数、数据传送前由 DMA 控制器请求总线使用权、数据传送由 DMA 控制器直接控制总线完成、传送结束后的后处理由中断服务程序完成。

2020 真题（错误项）：采用周期挪用、每次传送 512 字节、IO 接口有 32 位数据缓冲寄存器，错误项为"在整块数据传送过程中 CPU 不可以访问存储器"——这是把 `CPU停止法` 的概念偷换过来了；周期挪用下 CPU 仍可访存。

本讲总结：I/O 内容多但难度不大、知识点集中，围绕一个硬件（`IO接口`）与两个模型（`中断`、`DMA`）；概念题（尤其中断的响应优先级、处理优先级、中断屏蔽字、何时响应）是重中之重。
