# 计算机网络强化课 第1讲 以太网+IPv4

## 本讲框架：访问 Web 服务器的综合模型

[00:00:00 - 00:12:00]

强化课改用自顶向下的组织方式，用两个综合模型把五层知识串起来：本讲与下一讲是"访问 Web 服务器"，最后一讲是"访问 FTP 服务器"。近五年真题中应用层与传输层的占比明显上升，且新知识点（如 2023 年的 UDP 校验、FTP 细节、网络层的 OSPF/BGP）多出现在这两层，常见套路是以应用层为切入点、向下联合传输层与网络层考查。因此本讲以 Wireshark 抓包实例，从浏览器输入 URL 到收到全部数据，逐段拆解 ARP、DNS、TCP、HTTP 的出现顺序与细节。

> **易错点**：强化课不是重背协议定义，而是能把"某一个协议在整条链路中的位置、封装关系、先后顺序"讲清楚，这正是 2021 年 47 题第一问（主机访问 HTTP 之外还运行哪些应用层协议、各层如何封装）的考法。

## 一次 Web 访问的完整事件序列

[00:12:00 - 00:15:00]

输入域名回车后，链路上依次出现：① ARP 获取网关 MAC 地址；② DNS 完成域名解析；③ TCP 三次握手建立连接；④ 发送 HTTP GET 请求；⑤ 数据传输（流水线方式下受 TCP 拥塞窗口约束）；⑥ 接收数据并 TCP 断开连接。这条主线就是本讲所有考点的挂载点。

> **易错点**：每一环都能单独命题——DNS 要辨析递归/迭代、主机与本地域名服务器各发起几次请求；HTTP 要辨析持久/非持久、流水线/非流水线；TCP 断开连接五年内至少考了三次。

## MSS 与三次握手时的最大段长协商

[00:15:00 - 00:18:00]

MSS 是 TCP 报文段**数据部分**的最大长度，不含 TCP 首部。抓包中第 8 条（SYN）与第 9 条（SYN+ACK）都带 MSS 选项，说明双方在建立连接时就互相通告了自己的 MSS（本例为 1460 字节），此后每个 TCP 段的数据部分都不会超过该值。这也是后续"传输层分段"计算的依据。

> **公式**：MSS = MTU − IP 首部（20B）− TCP 首部（20B），以太网 MTU=1500 时 MSS=1460。
> **易错点**：MSS 只限制数据部分，不是整个 TCP 报文段的长度。

## ARP：先拿到网关的 MAC 地址

[00:18:00 - 00:25:00]

主机与本地域名服务器不在同一子网，DNS 查询必须交给网关转发，所以链路上最先出现的是 ARP 而不是 DNS。ARP 请求帧的目的 MAC 为全 F 广播，帧内携带 sender MAC/IP 与 target IP（192.168.31.1），target MAC 未知填 0。抓包中出现多条 ARP 只是实验时两台主机都操作过，考试中按一条计。

> **定义**：ARP 用于在同一局域网内由 IP 地址求出对应的 MAC 地址，请求用广播、响应用单播。
> **易错点**：DNS 报文的封装顺序是 DNS → UDP → IP → 以太网帧，其中**目的 MAC 是网关**、目的 IP 才是 DNS 服务器，两者不要混。

## ARP 响应、NAT 改写与逐跳转发

[00:25:00 - 00:30:00]

网关以单播 ARP 响应把自己端口的 MAC（005056F94285）告知主机，主机随后才发出封装 DNS 查询的以太网帧：源 MAC=主机、目的 MAC=网关、源 IP=192.168.31.104、目的 IP=114.114.114.114。该帧经 NAT 后，DNS 服务器看到的源 IP 已变成公网地址 203.10.2.5。

> **易错点**：整个转发过程中**目的 IP 不变、MAC 逐跳改变**；每经过一台路由器都要为下一跳重新发起一次 ARP。

## DNS 查询报文的封装与抓包细节

[00:30:00 - 00:34:00]

DNS 是应用层协议，报文封装在 UDP 中，再封装进 IP 数据报与以太网帧；抓包中可逐层展开看到以太网（MAC）、IP（源/目的 IP）、UDP（源/目的端口）三段首部。真实抓包里出现两组 DNS 请求/应答是百度服务器自身配置导致的，408 中一次解析只有一次请求、一次应答。

> **易错点**：不要用真实抓包的"多请求"去套考试题，考试按一问一答计算。

## DNS 的四类出题点与三种组合考法

[00:34:00 - 00:39:00]

单点考法有四个：辨析递归查询与迭代查询；给定域名求解析次数（主机发起几次、本地域名服务器发起几次）；求最长/最短解析时延；区分"本地域名服务器的往返次数"与"主机的往返次数"。组合考法有三种：DNS+HTTP（+TCP 数据传输）求总时间；DNS+实际网络拓扑（常附"ARP 转发表为空"）求时延；两者再叠加成 DNS+ARP+HTTP+TCP 的综合题。

> **易错点**：看到"ARP 转发表为空"就必须把获取 MAC 的 ARP 时延算进去；题目没提就不用管。

## 真题（2020）：DNS+HTTP+TCP 的最短与最长时延

[00:39:00 - 00:47:00]

题设：本地域名服务器只提供递归服务，其他域名服务器只提供迭代服务；局域网主机访问因特网服务器往返 1 RTT，其余时延忽略（含局域网内部时延为 0）。最短：本地域名服务器有缓存，DNS 时延为 0，加上"第三次握手携带 GET + 数据返回"共 2 RTT，即 20 ms。最长：迭代解析 3 RTT，加连接与数据 2 RTT，共 5 RTT，即 50 ms。

> **公式**：最短 = 2 RTT；最长 = 3 RTT（解析）+ 2 RTT（连接与数据）= 5 RTT。
> **易错点**：主机把请求交给本地域名服务器这一段在本题中时延为 **0**，不是 1 RTT。

## TCP 连接与断开的三大考点、第三次握手是否携带数据

[00:47:00 - 01:03:00]

考点一：三次握手与四次挥手的时序及"何时彻底关闭"，五年内至少考三次；考点二：拥塞窗口的增减与丢包后的快重传/超时处理；考点三：给出接收窗口判断还能发送的字节范围。第三次握手既可以携带数据（考研多数情形，数据放在 ACK 的载荷里），也可以不携带——不携带时不消耗序号，紧随其后的 HTTP GET 报文段 SEQ 与第三次握手相同（2012 年大题即此情形）。

> **易错点**：SYN 与 FIN 即使不携带数据，也各消耗一个序号；纯 ACK 不消耗序号。

## 抓包看三次握手与以太网最小帧填充

[01:03:00 - 01:08:00]

第 8/9 条为 SYN 与 SYN+ACK（互告 MSS=1460），第 10 条为第三次握手，len=0，紧接着第 11 条才发 GET。第三次握手的 IP 数据报总长仅 40 字节（20 IP + 20 TCP），不足以太网帧数据字段的最小 46 字节，链路层补 6 字节填充后成帧。

> **公式**：以太网帧最小 64B（首部 14B + 数据 46B + FCS 4B）；填充长度 = 46 − IP 数据报总长。
> **易错点**：填充只发生在链路层，IP 首部的"总长度"字段仍是 40。

> ⚠️ **需回看视频 [01:07:00]**：最小帧长与填充字节数的表述前后跳跃（先说数据部分最少 46 又改口 64，又说"添加了八个，呃，六个字节"），需确认填充量 —— "它的数据部分呢，最少是四十六字节，数据部分。啊，最少是六十四字节啊……它添加了八个，呃，六个字节的一个填充"

## HTTP 的考点、报文首部与 cookie

[01:08:00 - 01:18:00]

Web 服务器的熟知端口是 80，GET 请求经 TCP 封装后再进 IP。请求报文首部关注请求行（方法 GET、URL、版本 HTTP/1.1）、Host（所请求的主机）、Connection（close 表示非持久连接）；响应报文的 200 OK 表示该资源已全部发送完毕。HTTP/1.0 默认非持久连接，1.1 默认持久连接（再分流水线与非流水线）。

> **定义**：cookie 是服务器首次访问时分配给客户的标识，客户再次请求时在首部携带。
> **易错点**：408 只考"该网站近期是否被访问过"——首部带 cookie 即为访问过；200 OK 出现在资源的最后一个报文，收到它才允许发 FIN。

## 服务器先回纯 ACK，再发数据

[01:18:00 - 01:21:00]

实际抓包中，服务器收到 GET 后先发一个 len=0 的纯确认（第 12 条），随后才发携带数据的报文段（第 13、14 条）。纯确认报文不消耗序号，因此报文 A 与随后的数据报文 B 的 SEQ 相同。

> **易错点**：计算序号推进时，纯 ACK 不能当作占一个字节的数据段。

## 传输层分段与 IP 分片的区别

[01:21:00 - 01:33:00]

应用层数据超过 MSS 时，TCP 在传输层就切成多个段，每段各自加 TCP 首部再封装成**独立的 IP 数据报**，这些 IP 报的标识字段互不相同，所以不是 IP 分片。抓包中 2781 字节的数据被切成 1460 与 1321 两段（第 13、14 条），重组长度 2781。UDP 不设 MSS，应用层给多少就装多少，只有在超过 MTU 时才由 IP 层分片（各分片标识字段相同）。

> **公式**：分段数 = ⌈应用层数据 / MSS⌉；每个 IP 数据报总长 = 本段数据 + 20 + 20。
> **易错点**：题目已给 MSS 且传输层为 TCP 时，不能再"先凑一个超大 TCP 段、再让 IP 去分片"；只有 UDP，或 TCP 但未给 MSS 时才可以。

## 四次挥手的抓包细节与序号消耗

[01:33:00 - 01:41:00]

客户机先发 FIN（seq=78，不携带数据），服务器回 ACK=79；服务器随后发的 FIN 其 SEQ 与上一个纯 ACK 相同（2782），因为该 ACK 不携带数据；客户机最后的 ACK=79，比第一个 FIN 的 SEQ 大 1——说明 FIN 即使不带数据也消耗一个序号。最快情形是第二步与第三步合并，服务器直接回 FIN+ACK。

> **易错点**：客户机只有收到 200 OK、确认资源收全后才会发 FIN；服务器未发完数据前不会出现 FIN。

> ⚠️ **需回看视频 [01:38:00]**：第二、三次挥手的 SEQ 数值前后不一致（"278" 与 "2782"），SEQ 是否消耗的结论可靠但具体数字需核对 —— "第二次挥手的 sequence 是什么？是2782……第三次挥手，它的SEQ是谁？2782"

## 断开连接的状态名与关闭时刻

[01:41:00 - 01:43:00]

常考"客户机何时进入 CLOSED、服务器何时进入 CLOSED"，但出题人可能改问"客户机何时进入 TIME_WAIT、服务器何时进入 LAST_ACK"，因此四次挥手图中每个状态的英文名都要会写。

> **公式**：客户机 CLOSED 时刻 = 发出最后 ACK 的时刻 + 2MSL；服务器收到最后 ACK 即 CLOSED。
> **易错点**：主动关闭方在 TIME_WAIT 等待 2MSL，被动关闭方发完 FIN 后处于 LAST_ACK。

## 例题 1：DNS 解析的最短/最长时延与 ARP 是否计入

[01:43:00 - 01:46:00]

互联网与局域网往返均为 1 RTT，求点击链接到收到 DNS 返回的 IP 地址的时间。最短：本地域名服务器有缓存，直接返回，1 RTT。最长：本地域名服务器无缓存，依次访问根、com、一级域名服务器，3 RTT。题目未给"ARP 转发表为空"，故不计 ARP 时延。

> **公式**：迭代解析最长 = 3 RTT（根 → com → 权威），最短 = 1 RTT。
> **易错点**：若题干补一句"ARP 转发表为空"，则还要加上主机向网关、本地域名服务器向网关各自一次 ARP 的时延。

## 例题 2：HTTP/1.1 持久连接下流水线与非流水线的时间

[01:46:00 - 01:52:00]

网页含 5 张图片，采用 HTTP/1.1 持久连接。最短取流水线：受拥塞窗口约束，cwnd 依次 1、2、4，第 4 轮本应发 4 个但只剩 3 个资源，故连接建立加数据共 4 RTT，再加 DNS 的 1 RTT，合计 5 RTT。最长取非流水线：6 个资源逐个请求应答，加握手 1 RTT 共 7 RTT，再加 DNS 的 4 RTT，合计 11 RTT。

> **易错点**：流水线不是"一口气把所有资源全发出去"，发送节奏完全由 TCP 拥塞窗口决定（2022 年 40 题、2023 年 47 题均考此点）；每个资源按 1 MSS 计。

> ⚠️ **需回看视频 [01:47:00]**：本例 DNS 最长时延被说成 4 RTT，与例题 1 的 3 RTT 口径不一致，需确认是否另有题设 —— "最慢的话，慢是，是这个DNS解析，是什么？4RTT"

## 例题 3：ARP 广播帧的计数

[01:52:00 - 01:57:00]

所有主机与交换机的 ARP 表、DNS 缓存均为空，求点击链接到收到数据期间 H1 收到多少个 IP 广播帧。全过程产生三个 ARP 请求：H1 请求本地域名服务器 MAC、本地域名服务器请求网关 MAC、H1 请求网关 MAC（访问公网 Web 服务器）。三个请求都是链路层广播，同子网所有主机都能收到。

> **易错点**：交换机不隔离广播，H1 能收到同子网另一台主机发出的每个 ARP 广播帧；ARP 请求帧的 IP 广播地址与 MAC 全 F 都要能认。

## 例题 4：NAT 转换表与 FTP 的两个连接

[01:57:00 - 02:00:00]

控制连接：内网 192.168.1.3:1234H ↔ 外网 203.10.2.5:4321H，客户端 TCP 报文的目的端口为 21。数据连接：内网 192.168.1.3:5678H ↔ 外网 203.10.2.5:8765H。FTP 用 21 号端口建立控制连接，客户通过控制连接告知自己的数据端口，再由服务器的 20 号端口发起数据连接。

> **易错点**：两条 NAT 表项要按"内网 IP/端口 + 外网 IP/端口"成对配置，外网端口沿用题目给定值，不能自行改写。

> ⚠️ **需回看视频 [01:59:00]**：数据连接的外网端口被读成"786H""876H"并自称"说反了"，需确认应为 8765H —— "外网端口是 786H 啊，876H 啊，说反了啊"

## 例题 5：IP 分片与 ICMP 差错报文的计数

[02:00:00 - 02:05:00]

MSS=3200，应用层 3200 字节加 20 字节 TCP 首部得 3220，再加 20 字节 IP 首部得 3240，超过 MTU=1500，只能由 IP 分片：数据部分切成 1480+1480+260，各自加 20 字节首部，得到 1500/1500/280 三个分片。若三个分片到达 R2 时 TTL 均为 1，路由器先减 1 变 0 即丢弃并回 ICMP 超时报文；分片场景下**只对第一个分片**回 ICMP。

> **公式**：每片数据长度须为 8 的倍数；分片总长 = 片数据 + 20；分片数 = ⌈3220/1480⌉ = 3。
> **易错点**：三个分片被丢弃只产生 1 个 ICMP 报文，不是 3 个；这里是 IP 分片（标识相同），不是传输层分段。

## 例题 6：慢开始与拥塞避免的发送轮次

[02:05:00 - 02:08:00]

29200 字节按 MSS=1460 恰好 20 段，ssthresh=8，全程无丢包无拥塞。轮次依次为 cwnd=1、2、4、8，四轮共发 15 段，第 5 轮 cwnd 本应到 9 但只剩 5 段，实际只发 5 段，故共 5 个轮次。

> **公式**：慢开始阶段 cwnd 每轮翻倍，达到 ssthresh 后每轮 +1（拥塞避免）。
> **易错点**：最后一轮按剩余段数计，不能按 cwnd 上限计。

## 例题 7：快重传与超时后的窗口变化

[02:08:00 - 02:16:00]

第 3 轮第 1 个报文丢失、收到 3 个冗余 ACK 时立即快重传；下一轮 ssthresh 减半为 2，cwnd 取 2，直接进入拥塞避免。若该报文是**超时**而非冗余 ACK，则下一轮 ssthresh 同样减半为 2，但 cwnd 必须回到 1 重新慢开始，之后依次 1、2、3、4……，剩余 14 段需 5 轮发完。

> **公式**：快重传后 ssthresh = cwnd/2，下一轮 cwnd = ssthresh（拥塞避免）；超时后 ssthresh = cwnd/2，下一轮 cwnd = 1（慢开始）。
> **易错点**：区分触发条件——同轮内收到 3 个冗余 ACK 才是快重传；已超时则一律慢开始，不能"快重传后继续拥塞避免"。

## 例题 8：接收窗口与可继续发送的字节范围

[02:16:00 - 02:20:00]

T0 时刻发出 SEQ=18720、数据 1440 字节，占用 18720~20159。随后收到 ACK=18720、窗口 4320，说明接收方还能从 18720 起接收 4320 字节，即可到 23039。扣除已发未确认的 1440 字节，还可继续发送 20160~23039，共 2880 字节。

> **公式**：可发上限 = ACK 号 + 窗口 − 1；剩余可发 = 窗口 − 已发未确认字节数。
> **易错点**：窗口以"确认号所指的尚未收到的第一个字节"为起点，不是以上次发送的末字节为起点。

## 例题 9：挥手的 SEQ 与服务器主动断开的时间

[02:20:00 - 02:27:00]

服务器发完 29200 字节（20 段，5 轮）后主动断开，则第一次挥手的 SEQ = 10000 + 29200 = 39200。最快情形下第二、三次挥手合并：客户机收到 FIN+ACK 后回最后 ACK，于 6.5 RTT（65 ms）进入 CLOSED；服务器需再等 2MSL，于 6 RTT + 200 ms = 260 ms 进入 CLOSED。

> **公式**：主动关闭方 CLOSED 时刻 = 数据发送完毕 + 1.5 RTT + 2MSL；被动关闭方 CLOSED 时刻 = 数据完毕 + 1.5 RTT。
> **易错点**：主动关闭方是"发最后 ACK 后等 2MSL"，不是"发完 FIN 就关"；若问 TIME_WAIT/LAST_ACK 要换成对应状态名。

> ⚠️ **需回看视频 [02:20:00]**：例题编号在 T6/T8 之间反复改口，题干基准需确认 —— "这应该是T八啊……不过这个T6也可以，T6也行啊，没事，不影响"

## 例题 10：TCP 与 UDP 获取资源的时延对比

[02:27:00 - 02:29:00]

TCP 方式：握手 1 RTT，第三次握手携带 GET 并返回数据 1 RTT，共 2 RTT（20 ms）。UDP 方式：无连接，直接发请求、收响应，共 1 RTT（10 ms）。

> **易错点**：UDP 省掉的只是连接建立，请求与响应本身仍要一个往返。

## 流水线传输受拥塞窗口约束（答疑补充）

[02:29:00 - 02:48:00]

流水线只是"不必等上一个响应就能发下一个请求"，实际发送节奏仍取决于 TCP 拥塞窗口：cwnd=1 时只能发 1 个段，随 cwnd 增长逐轮推进，2022 年 40 题、2023 年 47 题都按此判分。另外，ARP 请求帧是链路层广播，同一子网内所有主机都能收到，因此"另一台主机发出了几个 ARP 请求"就等于"本机收到几个广播帧"。真题中资源大小通常明确给出，如 2022 年题为 HTML 1 MSS、每张图像 3 MSS。

> **易错点**：切勿按"一次性把全部资源发完"计算最短时延；也不要忽略 ARP 广播的可见范围。

## 电子邮件系统的收发流程与 MIME

[02:48:00 - 02:52:00]

六步流程：发信人调用用户代理编辑邮件 → 用户代理用 SMTP 客户进程把邮件送到发送方邮件服务器 → 邮件进入发送方服务器的缓存队列 → 发送方 SMTP 客户进程发现待发邮件后与接收方 SMTP 服务器建立 TCP 连接并发送 → 接收方 SMTP 服务器把邮件放入收件人邮箱 → 收件人用用户代理以 POP3 从邮箱取回。SMTP 只能传送一定长度的 ASCII 码邮件，无法传送非英语文字与可执行文件、二进制对象，故在其上增加 MIME，定义非 ASCII 内容的编码规则。

> **定义**：MIME 是在 SMTP 基础上定义的非 ASCII 数据（多媒体、二进制）编码规则，使原有邮件体系仍可传输。
> **易错点**：取信方向用的是 POP3（或基于 Web 的 HTTP），不是 SMTP；SMTP 只负责"推送"。

## SMTP 的三个阶段与命令/响应码

[02:52:00 - 02:59:00]

SMTP 使用 TCP，熟知端口 25，客户/服务器方式，通信分连接建立、邮件传送、连接释放三个阶段。连接建立：TCP 三次握手后服务器回 220 Service Ready，客户发 HELO（HELLO）并附主机名。传送：MAIL FROM → 250 OK；RCPT TO（可多个，逐个确认）→ 250 OK；DATA 后服务器确认，再传邮件正文（正文发送同样受 TCP 拥塞窗口与阈值控制）。释放：邮件发完发 QUIT，服务器回 221 服务关闭，随后进入 TCP 断开。

> **易错点**：220 是连接建立就绪、250 是命令接受、221 是服务关闭，三者对应不同阶段，别张冠李戴。

> ⚠️ **需回看视频 [02:55:00]**：连接建立后的就绪响应码被转写为"202 ready"，通行值是 220 Service Ready，需确认 —— "就返回一个叫202 ready的一个信息"

## SMTP 的可能考法与 POP3、基于万维网的电子邮件

[02:59:00 - 03:05:00]

应用层已考过 HTTP、DNS、FTP，邮件系统是剩余的可创新点；但完整的建立过程（HELO/RCPT/DATA）较繁琐，出题人若考计算，多半从"数据发送完毕 → QUIT → 221 服务关闭 → TCP 断开"切入，问 SMTP 客户机与服务器分别何时进入 CLOSED。POP3 使用 TCP 110 端口，采用拉（pull）方式，有"下载并保留"和"下载并删除"两种工作方式。基于万维网的电子邮件（如 QQ 邮箱）中，用户浏览器与邮件服务器之间用 HTTP，不同邮件服务器之间才用 SMTP。

> **易错点**：区分"用户代理 ↔ 邮件服务器"（HTTP/POP3）与"邮件服务器 ↔ 邮件服务器"（SMTP）两段所用协议。

## 真题回顾：SMTP 能直接传送的内容

[03:05:00 - 03:09:00]

2013 年真题判断 SMTP 的性质：只支持传输 7 位 ASCII 码内容（对）；支持邮箱服务器之间转发（对）；支持用户代理向邮箱服务器发送邮件（对）；支持邮箱服务器向用户代理发送（错，那是 POP3）。2018 年真题问"无需转换即可由 SMTP 直接传送"的对象，答案为 ASCII 码文本。本讲例题 2 的题干已在课上更正为"网页含一张图片、大小为 5 MSS"。

> **易错点**：SMTP 是"推"，POP3 是"拉"；凡是"服务器把邮件送给用户代理"的表述都不属于 SMTP。

## 收尾答疑：真题中的 MSS 条件与 TCP/UDP 时延

[03:09:00 - 03:15:08]

2016 年 41 题、2022 年 40 题、2023 年 47 题等大题基本都会明确给出 MSS（如 1000 字节），因为命题意图是考拥塞窗口；只有在未给 MSS 时才可能退化到 IP 分片思路。再次确认时延结论：UDP 取资源 1 RTT，TCP 至少 2 RTT。

> **易错点**：见到"未给 MSS"先判断传输层协议，再决定用分段还是分片模型。
