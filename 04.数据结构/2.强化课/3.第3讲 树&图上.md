# 数据结构强化课 第3讲 树&图上

## 二叉树基本术语：深度、高度、度与路径

[00:00:00 - 00:13:00]

（前 11 分钟为设备调试与课前答疑，无知识点内容，按规范并入本段时间。）深度与高度方向相反：高度自下往上看，叶子节点高度为 1，逐层向上累加；深度自上往下看，根节点深度为 1，叶子节点在最深处。少数教材把根节点深度定义为 0，做题时以题干括号中的约定为准。节点的度等于其子树（孩子）个数，直观上就是节点下方所连线的条数；整棵树的度为所有节点度的最大值，例如图中 A、E 的度均为 3，故该树是度为 3 的树。节点间关系有双亲/孩子与祖先/子孙之分；路径是由节点组成的序列（按从根往下的方向书写），路径长度等于路径上的边数。

> **易错点**：深度与高度的计数起点因教材而异（根节点深度可能从 0 或 1 开始），必须读题干给出的约定，不能凭习惯作答。

## 二叉树的性质与本章知识框架

[00:13:00 - 00:17:00]

n 个节点的二叉树，其树高由两端极端形态夹住：最矮取完全二叉树，最高取单支（单链）树。节点总数满足 n = n0 + n1 + n2，又等于"分支数 + 1"= n1 + 2n2 + 1；两者代换即得二叉树最重要的性质 n0 = n2 + 1。本章知识框架：满二叉树与完全二叉树各五条性质、完全二叉树高度公式、四种遍历（先序/中序/后序/层序，各含递归与迭代实现；层序推荐迭代加队列，模板可迁移到大量题目）、三种线索二叉树。报考自命题的考生还需掌握"二叉树与度为 2 的有序树的区别"这类简答题。

> **公式**：n0 = n2 + 1；节点总数 n = n1 + 2n2 + 1；单支树时树高最大为 n。
> **易错点**：树高范围中的最小值只有完全二叉树能取到，最大值是每层只有一个节点的单支树。

## 满二叉树的性质（五条）

[00:17:00 - 00:20:00]

高 h 的满二叉树：节点总数为 2^h − 1（由等比数列 2^0 + … + 2^(h−1) 求和得到，减 1 不在指数上）；第 i 层恰有 2^(i−1) 个节点；叶子节点全部位于最后一层，因此树中只有度为 2 和度为 0 的节点，不存在度为 1 的节点；按从上到下、从左到右从 1 开始编号时，节点 i 的双亲为 ⌊i/2⌋、左孩子为 2i、右孩子为 2i+1。编号关系在选择题的计算题中可用于快速排除选项。

> **公式**：满二叉树节点数 = 2^h − 1；编号 i：双亲 ⌊i/2⌋，左孩子 2i，右孩子 2i+1。
> **易错点**：若题目从 0 开始编号，则左孩子为 2i+1、右孩子为 2i+2，不能照搬 2i/2i+1；"所有叶子都在最后一层"看似显然，却是判断"树中只有度 0 和度 2 的节点"时最常被忽略的前提。

## 完全二叉树的性质（五条）

[00:20:00 - 00:24:00]

完全二叉树的定义：与同高满二叉树的前 n 个节点在位置上完全一一对应、中间不能有空缺。有 n 个节点时，编号 i > ⌊n/2⌋ 的节点必为叶子，否则必为分支节点，即最后一个分支节点的编号为 ⌊n/2⌋（堆排序初始建堆正是从该节点开始向下调整）。叶子只可能出现在最后两层。树中至多存在一个度为 1 的节点，且该节点必为倒数第二层的最后一个分支节点、只有左孩子没有右孩子。节点数 n 为奇数时不存在度为 1 的节点（除叶子外全是度 2）；n 为偶数时必定存在且仅存在一个度为 1 的节点。

> **公式**：最后一个分支节点编号 = ⌊n/2⌋；i ≤ ⌊n/2⌋ 为分支节点，i > ⌊n/2⌋ 为叶子。
> **易错点**：n 为偶数 ⟺ 恰有一个度为 1 的节点；n 为奇数 ⟺ 没有度为 1 的节点。

## 完全二叉树高度公式的推导

[00:24:00 - 00:28:00]

设完全二叉树高为 h，用"最少/最多"两种极端夹逼：最少时前 h−1 层为满二叉树、第 h 层只有一个节点，故 n > 2^(h−1) − 1（取等号时树高就不是 h，所以是严格大于）；最多时第 h 层铺满，故 n ≤ 2^h − 1（可以取等）。两式反解得到 h = ⌈log₂(n+1)⌉，等价于 ⌊log₂n⌋ + 1。所有"已知节点数求高度（或反之）"的选择题都要回到这套夹逼分析，不能只背结论。

> **公式**：2^(h−1) − 1 < n ≤ 2^h − 1 ⟹ h = ⌈log₂(n+1)⌉ = ⌊log₂n⌋ + 1。

> ⚠️ **需回看视频 [00:27:00]**（ASR 表述残缺、公式无法确认）：反解结论被口述为"向上取整"和"向下取整"两种写法，与教材公式的对应关系不明 —— "上面这个呢，就得到了一个啊log n加一向上取整，下边这个就得到了一个log n加一向下取整"

## 迭代法实现先序遍历（借助栈）

[00:28:00 - 00:40:00]

先序（根左右）迭代的核心是"遇新节点即访问，并用栈记住来时的祖先"。循环条件为"栈不空 || 工作指针 node 非空"：栈空可能已遍历结束，node 为空表示正在回溯。if 分支（node 非空）：立即访问 node（写入结果数组）→ 入栈 → node = node->left；else 分支（node 为空）：出栈回溯 node = stack[--top] → node = node->right。栈中元素类型是 TreeNode，栈顶指针与操作配套：初始为 0 则用 top++，初始为 −1 则用 ++top。题干给出的节点结构定义可直接使用；未给出时必须自己写 typedef，否则代码不完整。

> **易错点**：空树（root == NULL）永远是第一个要处理的边界条件；结果数组通常要自行声明与初始化，题目参数里的 returnSize/index 只是接口，可视为待写入的下标。

## 迭代法实现中序遍历与后序迭代的难点

[00:40:00 - 00:44:00]

中序迭代与先序迭代的代码结构完全相同，唯一区别是把"访问"这一行从 if 分支（发现即访问）挪到 else 分支（出栈后再访问），即"入栈一路向左 → 栈顶出栈并访问 → 转向右子树"，对应左根右。后序迭代结构差别较大：回溯时无法直接判断是"从左子树回来"还是"从右子树回来"，必须分别处理，因此代码明显更长；先序与中序遍历的回溯都必然来自左子树，故可统一处理。先序/中序遍历中"从左子树返回并访问完才转向右子树"这一点，是后序必须额外区分的根源。后序迭代重要性低，讲义中提供代码、课上不展开；考试不会规定必须用递归或某种次序，掌握的实现方式越多，可选解法越多。

> **易错点**：三种遍历在迭代法中同样只是"访问时机"不同，记一套骨架即可，不要分别死记三段代码。

## 线索二叉树概述与 ltag/rtag 的含义

[00:44:00 - 00:46:00]

线索二叉树利用二叉链表中大量空闲指针，记录节点在前/中/后序遍历下的前驱或后继。ltag = 1 表示左孩子为空、lchild 已被线索化，指向该次序下的前驱；rtag = 1 表示右孩子为空、rchild 指向后继；tag = 0 时指针仍是普通的孩子指针。部分情形可以沿线索在 O(1) 时间内取到前驱/后继，部分情形线索失效，只能回溯（借助栈）。真题例："下列关于线索二叉树的遍历依旧需要借助栈完成的是"，答案为先序线索二叉树找先序前驱。

> **易错点**：线索只借用"空指针"的位置，一旦该指针原本指向真实孩子，线索就不存在，此时不能凭空用线索取前驱/后继。

## 先序线索二叉树找前驱（必须回溯）

[00:46:00 - 00:53:00]

分四种情况：①ltag = 1 → lchild 直接就是先序前驱，O(1)；②ltag = 0、有双亲且自身是双亲的左孩子 → 前驱是双亲；③ltag = 0、自身是双亲的右孩子且双亲没有左子树 → 前驱是双亲；④ltag = 0、自身是双亲的右孩子且双亲有左子树 → 前驱是双亲左子树先序遍历的最后一个节点，在树形上表现为该子树"最右下"的节点。只要 ltag = 0（有左孩子），三种情形都无法借助线索，必须回溯并沿二叉树结构迭代，因此先序线索找前驱无法靠线索有效解决。"最右下"只描述方位，并不要求该节点是叶子或某种度；可用"把二叉树投影到一条数轴上，左右次序严格确定"的图景辅助判断，其性质与二叉排序树左小右大完全一致。

> **易错点**：只有 ltag = 1 才能用线索，其余三种必须回溯——这正是"哪种线索遍历仍需栈"这类选择题的答案来源。

> ⚠️ **需回看视频 [00:50:00]**（老师口误并当堂更正，前后表述冲突）：第④种情形先被表述为"双亲左子树最右下的节点"，随后更正为"双亲左子树先序遍历的最后一个节点"（图中应为 D），两处说法不一致 —— "这里应该描述为前驱为双亲左子树上面先序遍历的最后一个节点才对啊"

## 先序线索二叉树找后继（无需栈）

[00:53:00 - 00:56:00]

分三种情况：①rtag = 1 → rchild 即后继；②rtag = 0 且左孩子不空 → 后继就是左孩子（根左右中根之后紧接左子树根）；③rtag = 0 且左孩子为空 → 后继就是右孩子。三种情形都只需靠线索或孩子指针一步取得，不需要回溯、不需要栈。此类题常有两种问法：能否借助线索找到、能否只用指针一步步迭代找到，两者都不需要栈。

> **易错点**：先序线索"找前驱"必须借助栈、"找后继"不需要栈，两个结论正好相反，最容易记混。

## 中序线索二叉树找前驱与后继

[00:56:00 - 01:00:00]

找前驱：ltag = 1 → lchild 即前驱（O(1)）；ltag = 0（有左孩子）→ 前驱为左子树"最右下"的节点，也就是左子树中序遍历的最后一个节点（可由指针迭代走到）。找后继：rtag = 1 → rchild 即后继；rtag = 0（有右孩子）→ 后继为右子树"最左下"的节点，更严谨的说法是"当前节点右子树中序遍历访问的第一个节点"。结论：中序线索二叉树找前驱、找后继都不需要回溯、不需要栈。

> **易错点**：左右方向容易记反，说不清"最左下/最右下"时改说"右子树中序访问的第一个节点"，语义等价且不易错。

## 后序线索二叉树找前驱（无需栈）

[01:00:00 - 01:02:00]

三种情况：①ltag = 1 → lchild 即前驱；②ltag = 0 且右孩子不空 → 前驱为右子树后序遍历的最后一个节点，也就是右孩子本身；③ltag = 0 且右孩子为空 → 前驱为左子树后序遍历的最后一个节点，也就是左孩子本身。三种情形都能通过线索或指针在 O(1) 内取得，不需要栈。

## 后序线索二叉树找后继（必须回溯）

[01:02:00 - 01:18:00]

分四种情况：①rtag = 1 → rchild 即后继；②rtag = 0、有双亲且自身是双亲的右孩子 → 后继是双亲；③rtag = 0、有双亲且是双亲的左孩子、双亲没有右孩子 → 后继是双亲；④rtag = 0、有双亲且是双亲的左孩子、双亲有右孩子 → 后继是双亲右子树中后序遍历的第一个节点（左根右序下即右子树最左下的节点，描述时以"遍历的第一个节点"最稳妥）。根节点没有后继。凡 rtag = 0 的情形都要先回溯找到双亲，因此后序线索找后继必须借助栈。本时段含约 13 分钟课间休息（老师修改讲义图、答疑练习量与复习安排），按规范并入本知识点时间段。

> **易错点**：全表中只有"先序线索找前驱"和"后序线索找后继"这两类必须借助栈，其余六种都可以只靠线索或指针完成。

## 线索二叉树四种情形总结

[01:18:00 - 01:19:00]

表格总结：只有"先序线索树找前驱"和"后序线索树找后继"必须回溯（借助栈）；其余六种（先序找后继、中序找前驱、中序找后继、后序找前驱）都不需要借助栈。不需要栈的完成方式又分三类：①直接利用线索取到；②线索失效但用 lchild/rchild 指针一步取到；③沿树形结构用指针逐步迭代取到。

## 树的五种存储结构

[01:19:00 - 01:23:00]

顺序存储（数组）：支持随机存取，是堆排序的基础，但空节点多、空间利用率低。二叉链表（指针）：空间利用率较高，仍存在空指针，n 个节点的二叉树共 n+1 个空指针。孩子兄弟表示法（左孩子右兄弟）：左指针指向第一个孩子、右指针指向兄弟，便于树/森林与二叉树相互转化，但不便于找双亲。双亲表示法（数组，类似静态链表）：便于求双亲，不便于求孩子。孩子表示法（数组 + 单链表，形式类似图的邻接表）：便于求孩子，不便于求双亲。

> **公式**：n 个节点的 k 叉树用链式存储时，空指针数 = nk − (n−1) = n(k−1) + 1。
> **易错点**：空指针数 = 总指针数 − 有用指针数；n 个节点中除根节点外每个节点被一条指针指到，故有用指针恰为 n−1 条。

## 由遍历序列确定二叉树结构

[01:23:00 - 01:27:00]

先序序列与中序序列相同 → 树中没有左子树，只能是右单支树（每层一个节点的链）；中序与后序相同 → 没有右子树，只能是左单支树；先序与后序相同 → 左右子树都不存在，只能是空树或仅含根节点；前、中、后序全部相同 → 同样是空树或单节点。这类题的通用做法是画图找特例。题目若未写明"非空二叉树"，必须把空树计入答案。

> **易错点**：遇到"某两种序列相同"的条件，先想"砍掉哪一支"，两支都砍不掉时就只剩一个节点；空树是最高频的漏解。

## 层序遍历求二叉树深度

[01:27:00 - 01:35:00]

层序求深度的关键在于分辨层与层，办法是用 last 记录"当前层的最后一个节点"。准备工作：front、rear 初始化为 −1（便于用 front == last 判断层末），last 初始为 0（根节点所在位置），level 初始为 0；二叉树节点类型的数组模拟队列；根节点先入队。循环体：队首元素出队（front 先加后取）；把当前节点的非空左右孩子依次入队；当 front == last 时说明已处理到本层最后一个节点，此时 level++ 并将 last 更新为 rear（本层所有孩子入队后的队尾，即下一层最后一个节点）。不能用"last = 当前节点的右孩子"来更新——右孩子可能为空，会做出无效标记。

> **易错点**：空树深度为 0，必须先作为边界条件返回；last 只能用 rear 更新，不能指向某个具体孩子指针。

## 层序遍历算法模板

[01:35:00 - 01:37:00]

模板五段式：①边界条件处理；②声明队列（front、rear）以及题目需要的变量（深度、宽度等相关记录量）；③声明工作指针；④根节点入队；⑤while(队列非空) { 取队首元素并出队；当前节点的非空左右孩子入队；visit 操作 }。其中只有②的附加变量和⑤的 visit 需要按题意修改，其余可无脑照抄。队列建议用数组模拟（栈、队列同理）：STL 能否使用取决于各省改卷标准，往年有人用不扣分、也有人被扣分，数组模拟只多几个 int 指针，更稳妥。

> **易错点**：根节点入队、左右孩子入队这两步在任何层序题目里都不能省；确认变量全部有初值（否则结果不可预期）。

## 层序模板应用：求节点最多那一层的层数

[01:37:00 - 01:43:00]

在模板基础上增加 count（当前层节点数）、level（当前层号）、maxCount（已知最宽层宽度）、maxLevel（对应层号）。count++ 写在队首出队之后（每出队一个节点记一次）；当 front == last 时：level++ → 若 count > maxCount 则同时更新 maxCount 与 maxLevel → 把 count 归零 → last = rear。循环结束后释放队列，返回 maxLevel。注意返回的是"最宽那一层的层号"，不是树的深度。

> **易错点**：换层时忘记把 count 归零，count 就退化为"已遍历节点总数"，会持续增长，最终返回的其实是树的层数；变量多时务必写注释标明用途。

## 层序模板的三个变量细节

[01:43:00 - 01:46:00]

细节一：front、rear 初始化为 −1 时层末判断只需 front == last（last 初值 0），若初始化为 0 则各处加取操作都要对应改写。细节二：count++ 必须写在出队之后，不能写进"到层末"的分支里，否则只统计到每层最后一个节点。细节三：level++ 的位置要与 level 初值配套——level 初值 0 时应"先 level++ 再比较"，若挪到后面，maxLevel 会延迟一层（最宽层恰在最后一层时会错记成倒数第二层）；若 level 初值取 1，则 level++ 必须放到后面，放前面会导致层数永远多算一层。

> **易错点**：这类题的失分大多不在整体逻辑，而在变量初值与自增语句的位置，改题的这几行要逐行核对。

## 层序遍历模板的适用范围

[01:46:00 - 01:48:00]

凡具备"逐层"特征的题目都能套模板：逆层序遍历（队列输出后接一个栈即可从下到上、从右到左输出）、求二叉树宽度（最宽一层）、求高度/深度或指定节点的深度、求最小叶子深度（层序遇到的第一个叶子节点深度最小，找到可直接 return）、求分支节点（度为 1 与度为 2）的个数、判断完全二叉树、求左视图/右视图等。使用时通常只需替换 visit 部分。

## 层序模板应用：判断完全二叉树

[01:48:00 - 01:52:00]

判据：完全二叉树不允许出现"孩子空缺"，即所有分支节点的左右孩子都不能为空；等价地说，节点之间不能有间隔。做法：把入队时"非空才入队"的判断去掉，无论孩子是否为空一律入队（空指针同样是 TreeNode 类型，可以入队）；当出队取到第一个空节点时停止遍历，检查队列中剩余元素是否全为空——全空则是完全二叉树，只要后面还存在非空节点就不是。这样无需计算节点数与层数的关系。

> **易错点**：关键改动只在"入队不再判空"，visit 部分几乎为空内容；出队遇到第一个空节点即可停止，不必遍历完整棵树。

## 层序模板应用：求二叉树的右视图

[01:52:00 - 01:56:00]

题目要求站在树的左侧向右看（左视图，只能看到每层第一个节点），要求设计算法求出右视图，即每层最后一个节点。做法：层序遍历模板，visit 处改为"当 front == last（到达本层最后一个节点）时，把该节点的值写入 result 数组（index++）"，最后返回 result。用递归反而不易写，套模板只需改一行，力扣上的中等题用模板做相当于简单题。

> **易错点**：注意题目到底问右视图还是左视图——右视图取每层最后一个节点，左视图取每层第一个节点，方向弄反整题皆错。

## 递归求二叉树节点数

[01:56:00 - 01:59:00]

递归函数由递归体加递归出口构成。设计顺序：先想最小规模，即空树如何（出口），再想只有一个节点如何，最后把左右子树整体递归给函数、汇总结果再加上自己。求节点数：if (root == NULL) return 0；否则 return count(root->left) + count(root->right) + 1。能执行到 +1 一步，说明当前节点必非空（空节点已在上一步返回），因此直接加 1 是正确的。大部分递归题用先序思想即可完成。

> **易错点**：不要先摆出一棵完整大树再自顶向下拆解，也不要同时兼顾空、叶子、单分支、双分支所有情形，那样会产生大量重复判断；从空树出发自底向上更清晰。

## 递归判断两棵树是否相同

[01:59:00 - 02:03:00]

判断两棵树是否相同（形状一致且对应位置节点值相同），参数为两个根指针 p、q。出口：p 与 q 同时为空 → true；只有一个为空 → false；两者值不相等 → false。递归体：return same(p->left, q->left) && same(p->right, q->right)。三处出口把所有"不可能相同"的情形排除后，剩下的情况只需递归比较左右孩子。

> **易错点**：必须同时判断"是否为空"与"值是否相等"；由于涉及两棵树，要对比着看，出口需覆盖同时空、单空、值不等三种。

## 递归函数设计套路总结

[02:03:00 - 02:05:00]

套路：自底向上，从二叉树的"发源"（空树）→ 单节点 → 稍复杂的左右结构逐层归纳，而不是先想出一棵很大很完整的树再拆解。若题目问的是单分支/双分支节点的个数这类与左右形态有关的量，需要额外检查当前节点的左右孩子是否为空；除此之外，把左右两坨整体递归交给函数，最后汇总并算上自己即可。这一套先序思想能解决大部分递归题。

## 树、森林与二叉树的相互转换及遍历对应

[02:05:00 - 02:07:00]

树用孩子兄弟表示法转成二叉树后：二叉树的先序遍历 = 树的先根遍历，二叉树的中序遍历 = 树的后根遍历。森林转成二叉树后：二叉树的先序 = 森林的先序，二叉树的中序 = 森林的中序。因为转化后只有两种对应关系，所以树和森林本质上都只有两种遍历方式（先根/后根），只是不同教材或题干对森林的叫法不同。

> **易错点**：对应关系是"二叉树先序 ↔ 先根、二叉树中序 ↔ 后根"，并不存在"二叉树后序 ↔ 树的某遍历"的对应。

## 真题：树转二叉树后无右孩子节点数（特殊值法）

[02:07:00 - 02:10:00]

题目：一棵有 2011 个节点、116 个叶子的树，用孩子兄弟表示法转成二叉树后，没有右子树的节点共有多少个。特殊值法：画出一棵满足题干节点数与叶子数的最简树（一条纵向链，底层挂 116 个叶子），则分支节点数 = 2011 − 116 = 1895；转换后每个分支节点的最后一个孩子都成为二叉树中没有右子树的节点，再加上根节点（它没有兄弟，也无右子树），得到 1895 + 1 = 1896。这是考场上最快的做法，但课下要把题目背后的规律挖透，因为同一规律可以换形式再考。

> **易错点**：构造的特殊值树必须合法——分支节点数与叶子数要同时满足题干；漏掉根节点会少 1。

## 树转二叉树的规律：最后一个孩子对应无右子树

[02:10:00 - 02:15:00]

转换规则（左孩子右兄弟）：把树中除"每个节点连向第一个孩子"之外的指针全部断开，再让被断开的节点连到本层左侧紧邻的兄弟上。由此可得：树中没有右兄弟的节点（即每个双亲的最后一个孩子，独生子也属于此类）在二叉树中都没有右子树。于是"二叉树中没有右子树的节点数" = 树中分支节点数 + 1（根节点），本题即 1895 + 1 = 1896。

> **公式**：树转二叉树后无右子树节点数 = (n − 叶子数) + 1。
> **易错点**：判定只看"有没有右兄弟"，与节点有几个孩子无关；根节点永远不在任何兄弟序列中，必须单独加一。

> ⚠️ **需回看视频 [02:11:00]**（ASR 转写混乱，转换步骤描述不成句）：断指针并重新连线的操作被转写成"把他们都下边，下一层，下一层之后，让他连上他在这一层左边紧邻的这个兄弟头上"，具体操作顺序与指向无法确认 —— "全部都断掉之后呢，让他们都下边，下一层……"

## 树→二叉树时节点形态的映射规律

[02:15:00 - 02:20:00]

把树中节点按"有无孩子"和"有无右兄弟"分类，转成二叉树后的形态为：无孩子且无右兄弟（独生或最后一个孩子）→ 叶子 N0；有孩子且无右兄弟 → 只有左子树 N1左；无孩子但有右兄弟 → 只有右子树 N1右；有孩子且有右兄弟（长子）→ 双分支 N2。把八种细分情形归并后得到的统一判据是：二叉树中"没有右子树"完全等价于树中该节点"没有右兄弟"。

> **公式**：树中无孩子 ⟺ 二叉树中是 N0 或 N1右；树中有孩子且无右兄弟 → N1左（有右兄弟则为 N2）。
> **易错点**：整棵树的根节点没有兄弟，转成二叉树后永远只有左子树，是最容易看漏的特例。

## 用节点数目关系求解无右子树节点数

[02:20:00 - 02:24:00]

设二叉树四类节点数：N0（叶子）、N1左（度为 1 且只有左子树）、N1右（度为 1 且只有右子树）、N2（双分支）。N0 + N1左 + N1右 + N2 = 2011（转换前后节点数不变）。树中的叶子对应 N0 + N1右 = 116。树中的分支节点 = N1左 + N2 = 2011 − 116 = 1895。二叉树中没有右孩子的节点 = N0 + N1左，再由 N0 = N2 + 1 得 = (N1左 + N2) + 1 = 1895 + 1 = 1896，与特殊值法、规律法结论一致。

> **公式**：无右孩子节点数 = N1左 + N2 + 1（N1左 + N2 即树的分支节点数）。
> **易错点**：树中叶子由"N0 + N1右"两部分构成，不能只等于二叉树的 N0。

## 由层序序列与中序序列还原二叉树

[02:24:00 - 02:28:00]

步骤：层序序列的第一个节点必是整棵树的根，拿它到中序序列中把树划分为左右两段；层序序列的第二个节点（在左子树非空时）是左子树的根，再拿它去中序对应段继续划分；如此按层序顺序逐个取节点，用中序序列"左根右"的先后位置判断它是上一层哪个节点的左孩子还是右孩子，并对其所在区段继续划分，直到所有节点定位完毕。层序负责按"每层从左到右"的顺序提供各子树的根，中序负责确定左右归属。

> **易错点**：层序的第二个节点不一定是左子树根（左子树可能为空），必须先由中序的划分结果确认该侧是否存在子树。

## 二叉树还原为森林

[02:28:00 - 02:30:00]

还原方法：断开所有指向右孩子的指针，右链上被断开出来的节点上移一层，连到其原先的祖先节点上；原二叉树根节点右子树上的那一串节点成为森林中其他树的根（依次向右排列）。各棵树的先根遍历合起来即森林的先序遍历，与原二叉树的先序序列完全一致；森林的中序与原二叉树的中序也一致。

> **易错点**：二叉树中的左孩子对应树中的孩子、右孩子对应树中的兄弟；被断开的是"右兄弟链"，还原后它们属于同一棵树而不是各成一棵。

## 表达式树：定义与构造

[02:30:00 - 02:33:00]

表达式树是一棵二叉树：叶子节点全是操作数，分支节点全是操作符，根节点把整个算式一分为二。构造方法：选一个操作符作根，将表达式分成左右两个子表达式，再对子表达式递归划分。当存在多个同优先级操作符（如减号）时，必须选"最后一个参与运算"的操作符作根：例如 a − b − c 应取后一个减号，若取前一个减号，相当于给后面强行加了括号，而括号前是减号时括号内还要变号，会改变运算结果。

> **易错点**：含减号、除号时不能随意选取根部操作符，取错会使中序遍历得到的中缀式丢失原有运算顺序。

## 表达式树与中缀、后缀表达式

[02:33:00 - 02:34:00]

对表达式树做中序遍历得到中缀表达式；为保证运算次序，可在退出每棵子树时补一对括号（最外层不加），这样输出的中缀式与原始算式等价。对表达式树做后序遍历直接得到逆波兰式（后缀表达式），后缀式本身没有歧义，不需要任何括号。已知中缀表达式求后缀表达式时，用表达式树比双栈法更快：站在"上帝视角"画出表达式树，再做一次后序遍历即可，属于必须掌握的方法，且真题考过"给表达式树求后缀表达式/求值"。

## 表达式树的递归实现

[02:34:00 - 02:37:00]

输出中缀表达式：空节点直接 return；若当前节点左右孩子都为空，则是操作数，直接输出该字符（注意用 %c 而不是 %d）；否则是分支节点，进入子树前输出左括号、递归左子树、输出当前操作符、递归右子树，从子树退出后输出右括号。为使最外层不加括号，递归函数额外传入 level 参数，主函数传入 1，只有 level > 1 时才加括号。输出后缀表达式：空节点 return，否则递归左、递归右、输出根，不需要括号与任何附加判断。

> **易错点**：表达式树中的操作数与操作符都是 char，printf 用 %c；括号"进子树前加左、出子树后加右"与 level 判断缺一不可。

## 哈夫曼编码、WPL 与加权平均长度

[02:37:00 - 02:40:00]

构造哈夫曼树：每次取权值最小的两个节点合并，新生成的节点必须放回集合重新参与选择（不能让它在一旁等待），否则结果可能出错。编码约定通常为左 0 右 1，若采用左 1 右 0 必须在大题中写明，否则可能被扣分甚至判零。WPL = Σ(权值 × 路径长度)，大题必须用该定义式求解；"所有分支节点的权值之和等于 WPL"只是便于验算的规律，不能作为答题依据。加权平均长度 = WPL ÷ 各频次之和（即各权之和），是真题中新出现的概念。

> **公式**：WPL = Σ wᵢ·lᵢ；加权平均长度 = WPL / Σwᵢ。
> **易错点**：合并出的新节点要立刻参与后续选择；左 0 右 1 的约定必须写明。

## 并查集的基本结构与 find/union

[02:40:00 - 02:42:00]

用 pre[] 数组存放每个元素的代表元（父亲）。查找 find(x)：若 pre[x] == x 则 x 即代表元，否则递归 return find(pre[x])，沿链向上直到根。合并 union：把一个集合的根挂到另一个集合的根上。并查集天然是一棵"孩子指向双亲"的树（与普通树方向相反），根节点自己代表自己。并查集到目前为止真题尚未考过，考察概率与红黑树一样在上升，但考察形式未知，只能多练。

## 并查集大题：普通合并与数组（非显式）表示

[02:42:00 - 02:44:00]

题目约定 union(i, j) 表示把节点 j 的根更新为 i（即 j 所在集合挂到 i 上）。依次执行 union(1,2)、union(2,3)、union(4,6)、union(3,4)、union(6,7) 后，代表元关系为：1 代表自己，2 的代表元是 1，3 的代表元是 2，6 的代表元是 4，7 的代表元是 6，5 代表自己。非显式表示就是用数组写出"每个节点的代表元"（显式表示则画成树）；初值各元素自己代表自己，题干若规定统一写 −1 就写 −1，否则写自身下标也可以。

> **易错点**：数组里存的是"直接代表元"而非集合内所有元素；要区分显式表示（画树）与非显式表示（数组）。

## 并查集优化一：按集合规模合并

[02:44:00 - 02:48:00]

不加优化时合并可能退化成单链，查找最坏达到 O(n)。优化思路：合并时把规模小的集合并到规模大的集合上，为此约定树根处存储"该集合节点总数的相反数"，这样查一眼根节点的值就能比较规模。例：union(4,5) 后 4 处为 −2、5 指向 4；union(6,7) 后 6 处为 −2；union(4,6) 时两集合规模相等，按默认让 6 合到 4（4 处变为 −4）；union(3,4) 时 3 处为 −1（规模 1）、4 处为 −4（规模 4），此时不能再把大集合挂到小集合上，而应把 3 挂到 4 上。

> **易错点**：启用该优化后，"union(i,j) 一律把 j 挂到 i 上"不再成立，必须先比较两集合规模再决定方向。

## 并查集优化二：按集合高度（秩）合并

[02:48:00 - 02:50:00]

同样是在 union 阶段优化：把高度小的集合合并到高度大的集合上，约定树根存储"高度的相反数"。例：union(1,2) 时两树高度相等，按默认 2 合到 1；union(3,2) 时 3 的高度较小、2 所在集合更高，故把 3 合到 2 上；union(7,1) 时 1 所在集合高于 7，故把 7 合并到 1 上。树根存 −height，其余节点存直接代表元。

> **易错点**：只有两棵树高度相等时才按默认方向合并；高度不等时矮树必须并入高树。

## 并查集优化三：路径压缩

[02:50:00 - 02:52:00]

路径压缩在 find 过程中完成：把从 x 到根路径上的所有节点的双亲直接改为根。例：find(3) 时路径为 3→2→1，压缩后 3 直接指向 1，查找长度由 2 降为 1；find(6) 时路径为 6→4→3→1，压缩后把 4 与 6 都直接指向 1。三种优化可归为两类：合并时优化（按规模、按高度）与查找时优化（路径压缩）。各优化组合后的查找时间复杂度证明非常复杂（超出考纲，可参考算法导论，了解即可）。

> **易错点**：必须把路径上"每一个"节点的双亲都改到根上，只改终点节点等于没有优化。

## 时间复杂度回顾与动态顺序表扩容

[02:52:00 - 02:55:00]

以顺序表按值查找为例：目标在表首为最好情况 O(1)，在表尾为最坏情况 O(n)，数据结构中通常把最坏情况视作平均情况，即 O(n)。动态顺序表在插满后再插入不会溢出，而是扩容：若后面恰好有连续空闲空间则就地分配，更常见的是重新开辟 2n 大小的空间，把原 n 个元素逐个搬过去再插入，单次代价 O(n)。但在这 n+1 次插入中，实际只有最后一次消耗 O(n)，其余 n 次都是 O(1)，用 O(n) 描述整串操作并不公平，由此引出摊还（均摊）分析。

> **定义**：摊还分析（聚合分析）是对一个操作序列（通常为 O(n) 量级）整体评估平均代价，而不是只看某一条指令的最坏、最好或平均代价。

## 摊还分析的计算

[02:55:00 - 03:02:00]

工业实现（vector 等）：装填因子大于 0.75 时按 1.5 倍或 2 倍扩容；装填因子小于等于 0.5 时缩容至一半，从而支持动态增长。聚合分析：设容量为 n 的动态表，第 i 次插入的代价 cᵢ = 1（普通插入）或 1 + i（i = 2^k 时发生扩容，需要搬运 i 个元素）。n 次插入的总代价 = n（每次插入都含的那 1）+ Σ_{j=0}^{log n} 2^j ≤ n + 2n = 3n，摊到 n+1 次操作上每次不超过 3，故均摊时间复杂度为 O(1)。例：容量 1 时插入第 2 个元素需扩容至 2（1 次转移 + 1 次插入 = 2 次操作）；容量 4 插满后再插入需扩容至 8（4 次转移 + 1 次插入 = 5 次）；容量 8 插满后扩容至 16 需 9 次操作。摊还分析共三种方法，考纲不要求，了解即可。

> **公式**：Σcᵢ = n + (1 + 2 + 4 + … + n) ≤ 3n ⟹ 均摊每次 O(1)。
> **易错点**：摊还分析不改变单次操作的最坏代价（仍是 O(n)），它描述的是整串操作的均摊代价；迁移操作本身不算在总次数的 n 次插入里，要单独累加。

## 复杂度震荡与延迟缩容

[03:02:00 - 03:05:20]

若装填因子一降到 0.5 就立即缩容，则反复插入、删除会造成"扩容—缩容—扩容"的抖动，即复杂度震荡，此时摊还下来每次操作的代价都是 O(n) 量级。解决办法是延迟缩容：不要求装填因子一降到 0.5 就立刻缩容，而是等它降到更低的阈值（如 0.45）或连续删除若干次之后再统一缩容，从而避免频繁的内存分配与释放。本讲内容到此结束，下一讲为图与查找。
