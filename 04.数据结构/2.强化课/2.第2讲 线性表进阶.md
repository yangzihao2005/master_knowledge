## 数据结构三要素与四种存储结构

[00:18:00 - 00:22:00]

数据结构三要素为逻辑结构、存储（物理）结构、数据运算。逻辑结构分两类：线性结构（线性表，含顺序表与链表；操作受限的线性表即栈和队列；推广形式为广义表）与非线性结构（集合/并查集、树形结构、图）。存储结构有四种：顺序结构（逻辑相邻则物理必相邻）、链式结构（逻辑相邻物理不一定相邻）、散列结构（由哈希函数计算关键字位置）、索引存储。数据类型包含原子类型、结构类型与抽象数据类型 ADT。

> **易错点**：链式结构的"不一定相邻"包含"恰好也相邻"的情形，因此"逻辑相邻且物理也相邻"不能反推为链式结构；只有"逻辑相邻则物理一定相邻"才能断定是顺序结构。

## "线性表描述逻辑结构还是存储结构"辨析

[00:22:00 - 00:25:00]

判据只有一条：看该名词的物理实现是否唯一。物理结构唯一，则该名词侧重描述存储（物理）结构；物理结构不唯一，则侧重描述逻辑结构。线性表有顺序存储和链式存储两种实现，故描述的是逻辑结构；单链表、线索二叉树只有链式存储这一种实现（线索二叉树依赖空指针，顺序存储没有指针），故描述的是物理结构。

> **易错点**：这是一道有争议的题，王道资料曾把答案从"物理结构"改成"逻辑结构"。考场按上述判据作答，不要死记选项。

## 算法的定义、特性与设计目标

[00:25:00 - 00:28:00]

算法是对特定问题求解步骤的准确而完整的描述。代码题第一问通常要求写算法思想，可用伪代码（汉字描述，或汉字与 C 语言混合）表达。算法五个特性：有穷性（有限时间内结束）、确定性（输出唯一确定）、可行性、输入、输出。四个设计目标：正确性、可读性、健壮性、高效性（时间与空间）。

> **定义**：空间复杂度只计算算法运行所需的**额外**存储空间；形参传入的长度为 n 的数组、以及用于存放输入输出的空间都不计入。
> **易错点**：变量命名为 a、b、c 且全程无注释，可读性极差，会直接影响卷面评分；健壮性即对边界条件的正确处理能力。

## 定义法求时间复杂度（三重循环实例）

[00:28:00 - 00:38:00]

方法：从最外层向内层依次列求和式（从外向里写、从左向右写），每个求和号下方写循环变量的取值域，严格照 for 循环条件书写；求解时由内向外（从右向左）。例题外层 i=1..n 步长 1，中层 j=1,3,9,…（每次乘 3，直到 j=i 退出），内层 k=1..j 步长 1，核心语句 sum++ 每次执行 1 次。含义驱动求和：内层对 k 求和得 j 次，中层对 j 求和是公比 q=3 的等比数列（项数为 m+1，其中 3^m=i），外层再对 i 求等差数列和。

> **公式**：Σ(i=1..n) Σ(j=1,3,9,…,i) j = Σ(i=1..n) (3i−1)/2 ≈ 3n²/4 + O(n) = **O(n²)**
> **易错点**：等比数列求和的项数是 m+1 而不是 m；循环变量相互依赖（j 的上界由 i 决定）时项数最容易数错；循环条件写 `<n` 还是 `<=n` 不影响最终的大 O 阶。

> ⚠️ **需回看视频 [00:33:00]**（疑似 ASR 识别错误／公式残缺）：逐层求和的系数与末项被口述得较含糊，"四分之三 n 方加 n"的线性项与推导结果不完全吻合，只需确认结论 O(n²) —— "最后呢就等于一个四分之三n方加n。所以说刚才这个题目它的时间复杂度就是O n方"

## 线性表的定义与顺序表基本操作复杂度

[00:38:00 - 00:43:00]

线性表是 n 个相同数据类型元素的有限序列，除首元素（只有后继）和尾元素（只有前驱）外，每个元素有唯一的直接前驱和直接后继，这里的相邻关系是逻辑关系。顺序表：按号查找利用随机存取为 O(1)，按值查找需顺序扫描为 O(n)；插入 = 找位置 + 后继元素后移，O(n)；修改按号 O(1)、按值需先查再改为 O(n)；删除 = 查找 + 前移，O(n)。

> **易错点**：必须看清题干问的是"第 i 个位置"还是"值为 x 的元素"，前者 O(1)、后者 O(n)；顺序表访问写作 `L.data[i-1]`，数组写作 `a[i]`，手写代码时不要混用。

## 循环双链表表尾插入（模拟法）

[00:43:00 - 00:47:00]

在循环双链表 L 的表尾插入 p，需完成四个指针动作：原尾结点 `next=p`、`p->prior=原尾`、`p->next=L`、`L->prior=p`。这类题没有捷径，只能逐项画图模拟；错误选项的共同特征是"先改了后面还要用的指针"，例如先执行 `L->prior=p` 再执行 `p->prior=L->prior`，此时 `L->prior` 已指向 p，会形成自环。

> **易错点**：操作前后必须保持数据结构的合法性——既不能断链，也不能破坏循环结构；模拟类选择题答案常在最后两个选项，考场上可从 D 开始看以节省时间。

## 第一个缺失的正整数（映射思想）

[00:47:00 - 00:57:00]

题干给出"元素值不超过表长"这一条件，暗示可用下标做映射：申请大小为 n+1 的辅助数组并全部置 0，扫描顺序表，值为正则令 `result[值]=1`（或 ++），负数忽略；再从 1 扫到 n，第一个值为 0 的下标即为答案。时间 O(n)、空间 O(n)，是典型的空间换时间解法；若允许修改原表，还存在 O(n) 时间、O(1) 空间的原地做法。

> **易错点**：元素最大值可能恰好等于表长 n，故数组必须开 n+1；扫描映射数组要从 1 开始（0 不是正整数）；题干说"时间上最优"意味着允许用空间，说"原地"才限制 O(1) 空间。

## 链表基本操作复杂度与静态链表

[00:57:00 - 01:01:00]

链表没有随机存取，按值查找和按号查找都只能顺序扫描，均为 O(n)。删除、插入若指"整个操作过程"（含查找）是 O(n)，若只指"已知结点后的纯指针改向"则是 O(1)。静态链表用数组加游标 cur 实现：data 域存数据，cur 域存后继结点在数组中的下标。虽然由数组承载，但它逻辑上相邻的元素物理上不一定相邻，因此仍属于链式存储结构。

> **易错点**：存储结构的判定取决于实现方法而非载体形式——"用数组实现"的静态链表依然是链式存储，这是本章最大的概念陷阱。

> ⚠️ **需回看视频 [00:58:00]**（疑似口误／ASR 识别错误）：静态链表的实现被说成"二维数组"，与教材"一维结构体数组（data + cur 两个域）"的通行表述不一致，需确认板书 —— "静态链表呢，它是由一个二维数组，哎，由一个二维数组来实现的。前面呢放的是这个 data 预"

## 合并两个升序单链表（原地合并）

[01:01:00 - 01:11:00]

不带头结点时先申请 dummy head 统一操作；直接以 list1、list2 作为工作指针（无需另设 p、q），pre 指向新表尾以支持尾插。循环条件是两个表都非空（`list1 && list2`），取较小者尾插（相等时取 list1），插入后 pre 前移。循环结束用三元表达式把 `pre->next` 直接接到未合并完的那条链表的表头，剩余部分一次接上，无需逐个搬运。

> **公式**：时间 O(m+n)，空间 O(1)（只允许常数个辅助指针）
> **易错点**：与顺序表合并不同，这里的循环条件是"与"而不是"或"；尾插必须持续更新 pre；摘结点时要先保存后继防断链；408 的链表题只能用链表操作，不允许用数组模拟链表。

## 合并线性表的四类情形与比较次数

[01:11:00 - 01:31:00]

四类：升序顺序表→升序、升序顺序表→降序、升序链表→升序、升序链表→降序。最好情况都是"一表的表首元素大于另一表的表尾元素"，最坏情况都是两表元素交错。顺序表两种方向：比较次数分别为 min(m,n) 与 m+n−1，但时间复杂度恒为 O(m+n)，因为剩余元素仍要逐个搬运。链表升序→升序：最好 min(m,n) 次比较、时间 O(min(m,n))（剩余部分直接挂上）；最坏 m+n−1 次、O(m+n)。链表升序→降序必须用头插法，剩余元素也要逐个头插，时间恒为 O(m+n)。

> **易错点**：升序链表合并成降序若用尾插会得到升序，必须头插；顺序表升序→降序可从表尾向前比较，谁大谁先放到结果表尾部。

> ⚠️ **需回看视频 [01:20:00]**（口误后更正／表述前后不一致）：升序链表合并为升序时最好情况的时间复杂度被口述为 O(min(m,n))，与"链表不存在 log 级"等上下文表述衔接不清，且当场有"掉了个一"的更正 —— "它的比较次数呢和前面一样是 min 的一个 m n。而时间复杂度呢，同理，它也是一个大 O 的一个 min m n，它不是一个 m 加 n"

## 删除倒数第 n 个结点（快慢指针）

[01:31:00 - 01:39:00]

fast 先走 n 步，随后 fast、slow 同步前进；当 fast 走到空时，slow 恰好指向倒数第 n 个结点。用 pre 记录 slow 的前驱，删除时执行 `pre->next = slow->next`，保证不断链。加 dummy head 可让首元结点的删除与普通结点统一处理。时间 O(n)、空间 O(1)。

> **易错点**：当 n 等于表长（删除首元结点）时，若不加 dummy head 会因 pre 尚未移动而出错，需单独返回 `head->next`；快指针先走的步数就是题干给的 n，不必先求表长。

## 手写代码自检（self debug）方法

[01:39:00 - 01:45:00]

流程：先按一般情况（两个链表不等长等）写出通用解，再逐一补边界——空表、单结点、n 等于表长、k 等于 0。重点核对三处：count 的初值（0 配 `count<n`，1 配 `count<=n`，两种流派必须自洽）、while 的退出条件（写 `fast` 还是 `fast->next` 会改变快指针应领先的步数）、指针的连接顺序。写完用 1~2 个结点的小例子手推一遍，能过即认为正确，不必强求和标准答案逐字一致。

> **易错点**：不要用"先求 length 再算"的笨办法代替画图推演；`fast && fast->next` 的书写顺序依赖 C 的短路求值，写成 `fast->next && fast` 在 fast 为空时会空指针异常。

> ⚠️ **需回看视频 [01:41:00]**（不确定表述／写法细节含糊）：count 初值 0 或 1 与 `count<n`／`count<=n` 的配对关系只给了结论，中间推导"只差一个"的说法不够清晰 —— "如果写的 count 小于 n 的话，它俩最后中间就会只差一个，啊，就会只差一个"

## 找链表中间结点（快慢指针）

[01:45:00 - 01:54:00]

slow 每次走一步、fast 每次走两步。循环条件必须是 `fast && fast->next`：fast 走到空说明结点数为奇数，slow 即正中间结点；fast 停在最后一个结点（`fast->next` 为空）说明为偶数，此时中间有两个结点，按题干要求返回 `slow->next`（中间偏右者）。判断奇偶不必求表长，直接用退出时 fast 是否为空区分即可。

> **易错点**：偶数个结点时执行 `fast->next->next` 会对空指针取 next，编译期不报错、运行期崩溃；题干若要求返回中间偏左结点，则偶数时应返回 slow。

## 链表循环右移 k 个位置

[01:54:00 - 02:05:00]

新表头就是原表的倒数第 k 个结点。做法：先求表长 len，令 `k %= len`（k 为 0 直接返回原表，避免 k 远大于表长时快指针先走就走出链表）；再令快指针先走 k 步，slow 与 fast 同步走，条件用 `fast->next != NULL`，从而 fast 停在原表尾、slow 停在断点前驱，`slow->next` 即 new head。最后 `fast->next = head`（接环）、`slow->next = NULL`（断链），再 `head = slow->next`。

> **易错点**：更新 head 必须在 `slow->next` 置空之前，否则拿到的是 NULL；k 必须先对表长取模；断链步骤漏掉会返回一个带环的链表。

> ⚠️ **需回看视频 [02:01:00]**（疑似 ASR 识别错误／口误）：边界判断处把"k 大于表长"说成"k 是大于 head"，语句不成句 —— "如果 k 是大于 head 的话，那也 OK，最后把这个 k 呢重新赋值为一个对len取余的一个结果"

## 判断回文链表

[02:05:00 - 02:16:00]

步骤：快慢指针找中点并断开；逆置其中一半（头插法，需 pre 与 next 双指针防断链）；两半逐结点比较，任一不同返回 false，全部走完返回 true。**逆置后半部分优于逆置前半部分**：可省去求 length、省去奇数时跳过中心结点的特判，代码量显著减少。

> **易错点**：奇数个结点时后半比前半多一个结点，若逆置前半则必须跳过中心结点（它是前半头插后的第一个结点），否则长度不等必然判 false。

## 线性表存储方式的选择

[02:16:00 - 02:19:00]

顺序表支持随机存取，按号查找与修改快、实现简单、存储密度高，但需预分配空间、插入删除要移动元素。链表动态分配、插入删除只改指针、灵活性好，但查找必须顺序扫描且有指针域开销。例题"最常用操作是在表尾插入和删除表首"：单链表、仅有头指针的单循环链表、双链表都因缺尾指针而至少一侧为 O(n)，**仅有尾指针的单循环链表**两项均为 O(1)，最优。

> **易错点**：仅有头指针的单循环链表删除表首仍需遍历到表尾改指针，是 O(n) 而非 O(1)；顺序表还要额外面对存储空间是否足够的扩容问题。

## 栈的定义与三种实现

[02:19:00 - 02:23:00]

栈是只允许在同一端进行插入和删除的线性表，特点是后进先出（LIFO）。顺序栈用数组实现，需预分配空间，入栈前判满、出栈前判空。链栈用链表实现，动态分配，理论上不会上溢，但出栈仍需判空。共享栈用一片数组空间供两个栈相向增长（S1 栈底在 0、top 递增；S2 栈底在 MaxSize−1、top 递减），只有两栈顶相遇才上溢，从而**降低了上溢的概率**并提高了空间利用率。

> ⚠️ **需回看视频 [02:22:00]**（表述前后不一致）：共享栈两个栈底指针的初值在同一段里先说"一个置为 0、一个置为 MaxSize−1"，随后又说"置为 −1、置为 MaxSize"，两种约定的判空判满公式不同，需确认板书 —— "一个呢置为零，一个呢置为max size减一……这两个top它置为负一，它置为max size，或者它置为零，它置为max size"

## 出栈序列合法性与 top 初值的影响

[02:23:00 - 02:26:00]

容量为 3、入栈序列 1..5 的合法性判断只能逐项模拟：某序列先出 4，说明 4 入栈时栈内已有 1、2、3，栈深至少 4，超过容量即错；先出 1 后第二个出 5，意味着 2、3、4 必须在栈中积压后再压 5，同样超容。top 初值决定操作次序：top=0 时入栈为"先赋值再 top++"，非空时 top 指向栈顶元素的**下一个**位置，出栈先 top--；top=−1 时入栈"先 top++ 再赋值"，非空时 top 指向**当前栈顶元素**，出栈先取元素再 top--。

> **易错点**：top 的两种初值对应两套完全不同的入栈、出栈、判空、判满写法，混用必错；题干给出"最多容纳 k 个元素"时必须检查中间过程的栈深，而不只看最终序列。

## 队列的定义与实现分类

[02:26:00 - 02:29:00]

队列一端插入、另一端删除，先进先出（FIFO）。顺序队列用顺序存储，存在"假上溢"；循环队列通过 front、rear 对 MaxSize 取模解决假上溢，判空判满有三种实现：增设 tag 标志、增设 size 计数、牺牲一个存储单元。链式队列用链表实现，front、rear 的位置无固定要求，只要入队端与出队端和指针设置自洽即可。双端队列两端都可入队、出队，考试以逐情况模拟为主。

> **易错点**：循环队列的"环"是逻辑上的臆想结构，物理上仍是顺序存储，其逻辑结构是线性而非环形。

## 循环队列长度计算

[02:29:00 - 02:35:00]

题干两个坑：数组 `a[8]` 的下标是 0~7（不是 0~8）；非空状态下 front 指向队首元素的**前一个**位置、rear 指向**队尾元素**。长度由两段拼成：front 之后到数组末尾的元素数 + 从 0 到 rear 的元素数。front=5、rear=2 时长度 = (8−5−1) + (2−0+1) = 5。记不住公式时，画一个 MaxSize 很小的图数出结果，再推广到一般情况。

> **公式**：length = (rear − front + MaxSize) % MaxSize；本题 (2−5+8)%8 = 5
> **易错点**：front/rear 的具体含义（指向元素本身还是元素的前/后一格）不同，判满条件不同，套公式前先确认约定；用下标算个数时注意从 0 开始要额外加 1。

## 中缀表达式转后缀表达式

[02:35:00 - 02:41:00]

不需要背优先级表，只按小学数学的计算顺序推导。准备 result（存后缀序列）与 OP（暂存运算符）两个栈，从左到右扫描：操作数直接进 result；左括号直接入 OP；遇右括号则把 OP 中直到左括号为止的运算符全部弹出（左括号弹出后丢弃，右括号本身不入栈）；遇运算符时，只要栈顶运算符的优先级不低于当前运算符就弹出，直到栈顶优先级更低再入栈（同级视为栈内在左，先算）。扫描结束后把 OP 中剩余符号全部弹出。

> **易错点**：同级运算符也要弹栈，否则左结合顺序被破坏；右括号不入栈；最后别忘记清空 OP 栈。

## 后缀表达式求值

[02:41:00 - 02:44:00]

操作数入栈，运算符不入栈。遇运算符时连续弹出两个元素：先弹出记为 A，后弹出记为 B，计算 `B op A` 后将结果压回栈。最终栈中剩下的唯一元素就是表达式值。

> **公式**：先出栈的是右操作数 A，后出栈的是左操作数 B，结果为 B op A
> **易错点**：减法与除法顺序写反必错（8/4=2，而 4/8=0.5）；加法乘法虽可交换，也统一按 B op A 写。

## 两个栈模拟队列

[02:44:00 - 02:52:00]

S1 负责入队、S2 负责出队（两次后进后出叠成先进先出）。入队分三种情况：S1 不满直接 push；S1 满且 S2 非空 → 队满，返回失败；S1 满且 S2 空 → 把 S1 中**全部**元素倒入 S2 后再 push。出队分三种情况：S2 非空直接 pop；S2 空且 S1 非空则全部倒入 S2 后 pop；两栈皆空即队空。判空即两栈都空。

> **易错点**：S1 满时必须整体倒空，只倒出一部分会让新元素插到旧元素前面，破坏先进先出；S2 非空时绝不能把 S1 倒进去。

## 字符串转正整数（迭代与递归）

[02:52:00 - 02:56:00]

迭代核心一行：`sum = sum * 10 + (s[i] - '0')`，遍历 n 位即可。递归版每次只处理一位，用 position 记录当前处理位置，递归出口判断位置是否越界。字符与数字互转无需查 ASCII 表：`s[i] - '0'` 得整数，`x + '0'` 得数字字符。

> **易错点**：递归实现中累加变量 sum 必须定义在递归函数之外或通过参数/返回值传递，若写成函数内部局部变量，每次递归都会重置，结果错误。

## 数组与特殊矩阵的压缩存储

[02:56:00 - 03:01:00]

对称矩阵满足 a[i][j]=a[j][i]，只需存上三角或下三角。三角矩阵除三角区外其余元素为同一常数，需额外一个存储单元保存该常数，不能默认它是 0。三对角（带状）矩阵只有主对角线及其上下各一条对角线非零：第一行 2 个、其余每行 3 个。稀疏矩阵用三元组（行号、列号、值）压缩，并且必须额外记录原矩阵的总行数 m 与总列数 n，否则无法还原。

> **公式**：三对角矩阵按行优先，前 i−1 行共 2 + 3(i−2) 个元素，本行内偏移为 j−i+2（j−i ∈ {−1,0,1}），故序号 k = 2i + j − 3，数组下标为 k−1。
> **易错点**：上/下三角的"常数"不一定是 0，必须单独存储；三元组不存 m、n 就无法确定矩阵形状。

## 二维数组的地址计算

[03:01:00 - 03:05:00]

行优先下 `addr(a[i][j]) = addr(a[0][0]) + (i*n + j) * L`，n 为列数。题目只给 a[0][0]=780、a[4][6]=1146 时，可反推两个未知量：元素个数 = 1146−780+1 = 367（两端都含，属植树问题要加 1），其中第 4 行自身占 7 个，前 4 行共 367−7 = 360 个，故 n = 360/4 = 90。于是 addr(a[6][20]) = 780 + (6×90 + 20) = 1340。

> **易错点**：减法求元素个数时忘记加一（前后都算）；行号从 0 开始时偏移量直接是 i*n+j，若题中下标从 1 开始则要先各减 1。

## KMP 的 next 数组与失配滑动距离

[03:05:00 - 03:11:00]

next 由 PM（最长相同前后缀长度）整体右移一位、首位补 −1 得到。若 next 从 −1 起，则串从 0 编号；若 next 从 0 起，则串从 1 编号，两者必须配套。匹配过程中失配时 j 回退到 next[j]，模式串相对主串的右移距离恒为 `j − next[j]`。例题：主串与模式串的匹配共进行三轮比较、发生两次失配，每次滑动距离由当时的 j 与 next[j] 之差算出。

> **公式**：右移距离 = j − next[j]
> **易错点**：next 起点与字符串编号必须一致，一边加一一边从 0 编号必错；滑动距离不是 next[j]+1。

> ⚠️ **需回看视频 [03:09:00]**（疑似 ASR 识别错误）：例题中 j 与 next[j] 的具体数值转写含糊，滑动距离"三个距离"的推导与所示下标对不上 —— "你会看这里的j是不是，呃，这是几来着？012345，它是不是等于5啊？它是不是等于二呀"

## 改进 KMP 与 nextval（改进 PM 法）

[03:11:00 - 03:19:00]

nextval 的本质是避免"同一个字符在同一处反复失配"的无效回退。判据：某个相同前后缀后面紧邻的字符，若等于上一轮失配的字符，则回退到该位置必然再次失配，属于无效回退。求法：从最长的相同前后缀开始检查，有效则取其长度作为改进 PM；无效则退到次长继续，直到有效；空集视为长度 0 的最长相同前后缀（可当作通配符）；连空集都无效时取 −1。改进 PM 右移一位、首位补 −1 即得 nextval。

> **易错点**：首字符 A 的前后缀均为空集，其改进 PM 可能为 0（空集后字符与失配字符不同，构成有效回退），也可能为 −1（二者相同），这是最高频错点；考试中 next 与 nextval 可以各自独立求解，但 next 求错则 nextval 必错。

> ⚠️ **需回看视频 [03:16:00]**（表述含糊／疑似 ASR 识别错误）：逐字符求改进 PM 的举例中，"既没有相同前后缀、空集也不行、所以为 −1"对应的具体子串未说清 —— "这里的话就是既没有相同的前后缀啊，空集的话也不行，空集后的紧邻字符是A，A和上一轮失配的A相同，所以说这里呢就是一个负一"

## 杨辉三角的输出

[03:19:00 - 03:26:00]

规律：第 i 行（i 从 0 起）共 i+1 个元素，首尾均为 1，其余元素等于肩上两数之和。C 实现要点：返回二维数组，先 `malloc(n * sizeof(int*))` 只建立第一维（数组的数组），再在循环里为第 i 行 `malloc((i+1) * sizeof(int))`；内层 j 只处理 1 到 i−1。

> **公式**：`a[i][0] = a[i][i] = 1`；`a[i][j] = a[i-1][j-1] + a[i-1][j]`（1 ≤ j ≤ i−1）
> **易错点**：第一维申请完不等于二维数组建好，每行还要单独开辟；内层循环若不跳过首尾会覆盖已置 1 的边界值甚至越界。
