# 操作系统基础课 第1讲 操作系统概述

## 课程导学：操作系统在 408 中的地位与本讲框架

[00:00:00 - 00:10:00]

操作系统是四门课中综合性最强、难度最大的一科：机组难在"学"，考试多为单知识点；而操作系统的大题常跨章节、跨知识点，甚至把机组内容一并拉进来考。好处是它也是失分最少的科目，方法得当基本可以做到满分或只扣一两分。本讲是"综述 + 导学"，先建框架（程序与任务 → 进程线程 → 内存 → 文件 → I/O），再补前置知识（指令系统边界、编译链接、程序内存映像、特权级、中断、系统调用），最后讲体系结构、虚拟机与操作系统发展史。第一遍只搭框架、知道每个模块"大概干什么"，不要一开始就钻实现细节。

> **易错点**：操作系统是"软件"，其作用范围的边界由指令系统（ISA）决定，这是理解全讲的出发点。

## 程序与任务：程序执行的资源需求

[00:10:00 - 00:20:00]

程序通过指令控制计算机执行，因此程序要运行，先要满足指令执行的条件：一部分内存装指令；CPU（PC 给出当前指令位置以控制执行顺序、IR 存放指令、CU 译码并发出控制信号、ALU 完成运算、通用/专用寄存器组）；还需要内存存放数据（如直接寻址指令要访问的变量）；函数调用还需要堆栈存放参数与局部变量。把程序的代码、数据连同程序头（含入口地址等执行信息）装入内存，再配上 CPU、I/O 等资源，程序才成为可被操作系统直接管理的任务。程序是静态的，存于磁盘的可执行文件中；任务是对"装入内存并分配资源后正在执行"这一动态形态的称呼。

> **定义**：程序——保存在磁盘中的可执行文件，由代码（指令）、数据和程序头（含入口地址等执行信息）三部分组成，是静态的。
> **定义**：任务——程序被装入内存并配备 CPU 及其他所需资源后形成的执行体，操作系统直接对任务进行管理。
> **易错点**：程序头中的入口地址不一定是第一条指令（C 程序从 main 开始，编译时即写入程序头）；程序必须装入内存才能执行，因为内存是 RAM，断电即失，而磁盘可持久保存。

## 多任务与并发：进程与线程

[00:20:00 - 00:26:00]

单 CPU 下一个任务独占 CPU，多任务只能"轮着来"；操作系统研究的第一个重点就是多任务如何在内存中同时存在并并发执行（各执行一小段时间、齐头并进）。方案一"进程"：每个任务拥有自己独立的内存（代码、数据、堆栈互不相交），CPU 轮流分配。方案二"线程"：多个执行流共享同一块内存中的代码与数据，但各自拥有独立的堆栈，CPU 同样轮流使用。

> **定义**：进程——内存相互隔离、数据不相交的执行体；线程——共享同一地址空间（代码与数据共享）、但堆栈独立的执行体。

## 调度与进程/线程切换

[00:26:00 - 00:29:00]

CPU 是唯一的独立资源，必须决定"当前给谁用"，这就是调度；任务放弃 CPU 后再回来必须能接着往下执行，这就是切换要解决的问题。老师用寄存器举例：进程一算出 R0=1，下一步要执行 R1=R0+1；此时切换到进程二并把 R0 改成 2，切回后进程一算出 R1=3，与程序设计意图不符。因此切换不能只是"把 CPU 交出去"，必须保存并恢复现场（寄存器等状态）。

> **易错点**：进程/线程切换的实质是保存现场与恢复现场，不是简单地更换 PC。

## 进程间通信与同步互斥

[00:29:00 - 00:31:00]

进程地址空间彼此隔离，P1 无法直接读写 P2 的数据，但进程之间经常需要传递数据，这就需要进程间通信（IPC）。线程共享同一区域时，若 T1 正在访问共享区，T2 必须等 T1 离开后才能进入，这是互斥访问；若 T1 负责写入、T2 负责读取，则二者存在严格先后顺序，需要同步机制来保证次序。

## 死锁

[00:31:00 - 00:33:00]

进程运行需要资源，若资源一被 P1 占用、资源二被 P2 占用，而 P1 又需要资源二、P2 又需要资源一，双方各抱一半、互断退路，就永远无法推进，这就是死锁。后续在进程管理部分会学死锁的形成条件与解决方法。

## 内存管理：空闲内存的管理、分配与回收

[00:33:00 - 00:35:00]

磁盘中的程序要变成任务，必须在内存中为它分配空间（装代码、装数据、申请堆栈），因此操作系统首先要能掌握"哪里有尚未使用的空闲内存"，其次要能把空闲内存分配出去，最后还要在进程结束后把内存回收、重新变为空闲。这三点构成内存分配与回收的基本功能。

## 虚拟地址与物理地址

[00:35:00 - 00:41:00]

若采用直接寻址，指令中的地址是写死的物理地址，数据必须被放到该物理地址上；一旦多个程序的指令都写了同一个地址，数据就会互相覆盖，而且位置被钉死、极不灵活。因此实际使用的是逻辑地址（虚拟地址）：程序只使用虚拟地址，运行时由系统维护的映射关系把虚拟地址转换为物理地址，不同进程的同一虚拟地址可映射到不同的物理地址。映射关系的维护方式即后续的段式管理、页式管理、段页式管理。

> **易错点**：指令中给出的操作数地址是虚拟（逻辑）地址，不是物理地址；地址转换由硬件与操作系统配合在程序运行过程中完成。

> ⚠️ **需回看视频 [00:38:00]**：老师先说"逻辑地址或者说虚拟地址"，随即又说"这里写的是虚拟地址"，两个术语在本课程中是否完全等同需确认 —— "我们正常情况下使用的是指令里面使用的是一种逻辑地址或者说虚拟地址"

## 虚拟存储技术

[00:41:00 - 00:42:00]

内存空间有限时，把大程序分段处理：先装入当前正在执行所需的那部分代码和数据，执行完暂时不用的部分换出，需要时再换入。实现这一点的技术叫虚拟存储器，而"换出谁"的策略对应页面置换算法。

## 文件系统的三大任务

[00:42:00 - 00:46:00]

文件系统只学三件事。一是目录系统：给定一个路径，如何把它确定为磁盘中的某一个文件（如"我的电脑 → D 盘 → 文件夹 → 文件"这一层层选择的过程）。二是文件的组织结构：文件的数据块在磁盘上可能分散各处，需要设计一种管理结构，把该文件在磁盘中的所有数据块关联起来，做到不重不漏地访问。三是文件操作：进程如何打开、关闭、读写文件，这些操作如何实现与维护。

## I/O 管理与设备抽象

[00:46:00 - 00:50:00]

设备数量有限而进程有多个，因此不能为每个进程固定绑定设备，需要由操作系统维护、分配和回收设备。另一件事是设备抽象：CPU 实际是通过访问 I/O 接口中的 I/O 端口（统一编址时用内存地址，独立编址时用端口号）并配合命令字来访问设备的，但对用户而言只希望有一个 `printf`/`print(path)` 这样的简单接口，操作系统就把这些与细节强相关的底层接口逐层抽象成统一、好用的功能接口。

## 内核、特权级与中断机制的引入

[00:50:00 - 00:52:00]

对进程、线程、内存、文件、设备进行管理的软件称为操作系统内核；内核与用户程序都要装入内存才能执行，于是必须防止用户程序反过来访问内核的代码和数据，这靠 CPU 的特权级机制实现：内核特权级高、用户程序特权级低。但用户程序又必须能使用内核提供的功能，这靠中断机制实现——在受管控的前提下进入内核。

## 实例：双击 EXE 到界面显示的完整流程

[00:52:00 - 00:55:00]

双击桌面上的微信，先由文件系统按其路径（桌面\微信.exe）找到该文件；再为它分配内存、装入代码与数据并创建进程；创建进程时要建立虚拟地址到物理地址的映射；进程运行中要弹出聊天窗口，需访问屏幕这一 I/O 设备并显示界面，由 I/O 管理模块负责。这个例子把各模块串成一条链，基础课结束时应当能回来把每一环补齐。

## 前置知识：操作系统的功能边界 = 指令系统的功能边界

[00:55:00 - 00:58:00]

操作系统是软件，而软件通过指令控制计算机，所以操作系统也是用指令来管控资源的——凡是 ISA 中的指令能够控制和看到的东西，都属于操作系统能管的范围；超出指令系统边界的部分就是纯硬件，与操作系统无关。因此"操作系统功能"与"软件功能"是同义的，都指可以用指令直接控制和管理的部分。

> **定义**：操作系统能够管控的范围边界，就是指令系统（ISA）功能的边界；边界之外是硬件自身的实现，对操作系统透明。

## 指令边界的具体体现：DMA、I/O 控制器与 Cache

[00:58:00 - 01:02:00]

指令对 DMA 只做初始化和启动，之后的块传输由 DMA 硬件自行完成，这一段不在指令控制范围内；指令负责把命令字、数据从通用寄存器送入 I/O 控制器的端口寄存器，而控制器与 I/O 设备之间的数据交换是纯硬件行为；访存时数据可能实际来自 Cache，但指令视角下只是"访问了某个内存单元"，Cache 与内存之间的数据交换属硬件功能。可见"哪里是指令边界"要逐条判断：边界内是操作系统的工作，边界外是硬件黑盒。

> ⚠️ **需回看视频 [01:01:00]**：Cache 是否对指令系统透明存在保留 —— "cache 完全，cache 完全透明这个说法可能也不合适，因为在某些架构下，指令系统它它有刷新 cache 这个功能"

## 透明性：代码与数据对谁可见

[01:02:00 - 01:16:00]

区分软件功能与硬件功能是学习操作系统的重中之重，硬件机制可以当黑盒直接用，而指令能控制的部分才是操作系统程序员真正的工作面。应用程序员可直接读写通用寄存器、内存、变址寄存器；系统程序员还可读写段基址寄存器、中断屏蔽字寄存器、I/O 端口等（须在内核态）。PSW 与 PC 属"汇编语言不透明但不能直接读写"，只能通过 J 这类指令间接修改——程序员知道它们存在，故不叫透明。指令系统边界以下（IR、Cache、MMU、地址转换、中断响应等 CPU 内部机制）对指令、对程序员都不可见。应用程序员与系统程序员都可能是"汇编程序员"（最终都要变成汇编、机器指令），区别只在特权级：系统程序员可用全部指令，应用程序员执行特权指令会直接出错。

> **易错点**：透明 = 使用者不知道它存在，而不是"它不存在"或"CPU 没有用到它"；Cache 就是典型——CPU 实际访问了 Cache，但用指令的人以为在访问内存。
> **易错点**：PC、PSW 不透明（程序员知道其存在、能间接改动），不要因为"不能直接读写"就判为透明。

> ⚠️ **需回看视频 [01:05:00]**：此处术语疑似 ASR 识别错误，应为 MMU/TLB 之类 —— "下面的这些IR啊、缓存、MAC啊、MID啊、地址转换、中断响应、CPU内部"

## 程序的编译与链接

[01:16:00 - 01:21:00]

磁盘中的程序由源文件一步步生成：预处理（展开宏、包含头文件，如把所有 `ONE` 替换为 `1`）→ 编译（高级语言源程序变成汇编文件）→ 汇编（汇编文件变成二进制机器指令）→ 链接（把多个独立的目标模块合并成一个可执行文件）。得到可执行文件后，才能分配内存、装入、建立执行环境并把 PC 指向入口。

> **易错点**："编译"有两种口径：高级语言→汇编，或高级语言直接→机器码（不经过汇编这一显式步骤），各教材不统一，真题考过。

## 程序的内存映像：代码段、数据段、BSS、堆与栈

[01:21:00 - 01:25:00]

程序装入内存后按属性分区存放：指令与只读常量放代码段；已初始化的全局变量（及静态变量）放数据段；未初始化的全局变量放 BSS 段（是否区分已/未初始化，不同设计可能统一并入数据段）；函数内的局部变量放栈；`malloc` 等运行期动态申请的空间放堆。堆由低地址向高地址生长，栈由高地址向低地址生长，二者共用一块区域，称堆栈区，相向生长。

> **易错点**：全局变量按"是否已初始化"分入数据段与 BSS 段；局部变量在栈中，不能与全局变量混为一谈。此知识点 2025 年真题刚考过大题。

## 计算机系统的层次结构与两类接口

[01:25:00 - 01:28:00]

自上而下为：应用程序（微信、QQ 等直接面向用户）→ 系统应用（数据库管理程序、网络服务程序等不直接给用户用的程序）→ 操作系统 → 计算机硬件；系统应用与操作系统合称系统软件。硬件向上提供的接口是 ISA（指令集体系结构，即指令系统），操作系统用这些指令向硬件发布命令；操作系统向上提供的接口是系统调用。

> **定义**：硬件↔操作系统的接口是 ISA（指令系统）；操作系统↔应用程序的接口是系统调用。

## CPU 特权级：用户态与内核态

[01:28:00 - 01:31:00]

408 中只有两级特权：用户态与内核态。用户程序运行时 CPU 处于用户态，操作系统运行时 CPU 处于内核态——这是描述 CPU 当前状态的动态属性；内存中的代码和数据也带特权标记，是静态属性。仅当 CPU 当前特权级 ≥ 被访问代码/数据的特权级时才允许访问，于是把用户程序的代码数据全标为用户态、内核全标为内核态，就能保证用户程序无法访问内核，而内核既能访问自己的也能访问用户的。

> **易错点**：访问规则是"CPU 的态 ≥ 被访问对象的态"，两级都要看；不是"内核空间可以访问用户空间"这种单向表述，而是 CPU 在内核态时才能访问内核空间。

> ⚠️ **需回看视频 [01:29:00]**：内核态访问用户态数据是否普遍成立，老师表述留有余地 —— "这里面它可能涉及到一些更复杂的情况啊。这以我们在统筹四零八来看的话，和大部分架构来看的话，这个它也是成立的，大家大概就这么记就行了"

## 用户空间与内核空间

[01:31:00 - 01:34:00]

每个用户程序运行前，操作系统都会把该程序与必要的内核代码链接成一个整体，形成统一的一整块地址空间；其中内核部分被标记为内核态代码和数据，用户部分标记为用户态。因此隔离不靠"地址不重叠"，而靠特权级：用户态下只能访问用户空间，一旦访问内核空间即出错；进入内核态后才能访问全部。

> **易错点**：用户空间与内核空间在同一地址空间内、逻辑上连成一体，靠特权标记隔离，不是两块互不相干的物理内存。

## 特权指令与特权级切换

[01:34:00 - 01:36:00]

特权指令是只能在内核态执行的指令，放在用户空间基本没有意义（用户态一执行就报错），故一般位于内核空间。用户态 → 内核态的唯一途径是中断或异常；内核态 → 用户态的唯一途径是中断/异常处理结束后返回（且原本是从用户态进来的才返回用户态）。

> **易错点**：特权级切换只有"中断/异常"这一条通道，没有别的指令可以直接改特权级。

## 用户栈与内核栈

[01:36:00 - 01:37:00]

用户空间与内核空间各自需要堆栈，因此设计上用户态使用用户栈、内核态使用内核栈；SP 始终指向当前栈顶，发生特权级切换时 SP 必须随之从用户栈切到内核栈，返回时再切回。

## 中断与异常的分类

[01:37:00 - 01:39:00]

外中断（中断）：信号来自 CPU 之外，如外设请求、人工干预。内中断（异常）：信号来自 CPU 内部，通常与正在执行的指令有关。异常分三类：故障（可被修复，如缺页异常，处理后重新执行该指令）、终止（不可修复的致命错误，通常终止该任务）、陷入（由访管/自陷指令主动引发，是系统调用的基础）。

## 中断源、中断号、中断向量与中断向量表

[01:39:00 - 01:44:00]

中断源是中断/异常的来源（键盘输入、时钟信号、除零等）；中断号是 CPU 为每个中断源编的号，CPU 据此辨识是哪一种中断。中断向量表是内存中一段连续存放的表，表项称中断向量，其首地址由专用寄存器 IDTR 记录；表项等长且按序号排列，本身不存索引，用下标访问即可，因此最适合用数组实现。中断向量中最重要的内容是服务地址，即该中断源处理程序的首地址。处理流程：中断源产生中断号 → CPU 经 IDTR 找到向量表 → 按号取中断向量 → 取出服务地址 → PC 置为该地址并跳转执行。

> **定义**：中断向量 = 中断向量表中的一个表项，存放对应中断源的中断服务程序首地址。
> **易错点**：中断向量表在内存中而非磁盘；表项中不含"编号"字段，编号由下标隐含。

## 中断响应与处理机制：硬件与软件的分工

[01:44:00 - 01:54:00]

硬件完成"中断响应"三部曲（不受指令控制）：关中断 → 保存断点（PC 与 PSW，x86 下压入内核栈）→ 跳转到中断服务程序（PC 置服务地址）；若中断来自用户态，硬件还要完成特权级切换与用户栈→内核栈的切换。随后进入软件阶段：保存现场和屏蔽字（通用寄存器等，硬件不做，必须由软件保存）→ 开中断 → 执行中断服务程序 → 关中断 → 恢复现场和屏蔽字 → 开中断 → 中断返回（返回用户态时再由硬件切回用户栈与用户态）。之所以把关中断放在保存断点之前、开中断放在保存现场之后，是因为"保存"必须在关中断环境下完成；恢复同理，被关/开中断夹住。

> **易错点**：保存断点（PC、PSW）是硬件做的，保存现场（通用寄存器、屏蔽字）是软件做的，这是最爱考的分工点。
> **易错点**：关中断与开中断之间必然是"保存"或"恢复"操作，不会夹别的内容。

> ⚠️ **需回看视频 [01:45:00]**：堆栈切换由硬件完成是否适用于所有架构，老师明确只保证 x86 —— "当然这个是我们的x86里面是这样，x86里面它有一个叫TSS的一个东西……但是有的架构不是……你认为它是硬件完成的是无伤大雅的"

## 中断机制的四个考点辨析

[01:54:00 - 01:56:00]

第一，中断不一定在用户态响应：内核态执行中断服务程序时也可再响应中断（中断嵌套），故响应与返回都不一定发生特权级切换，只有"用户态↔内核态"跨越时才有。第二，堆栈切换与特权级切换同步发生，x86 由硬件完成。第三，关中断与开中断之间必然只做保存或恢复（断点/现场/上下文）。第四，本模型是中断嵌套模型，因为执行服务程序时处于开中断状态；若题目说"单级中断"（不允许嵌套），则全过程关中断——只在开头关一次、结尾开一次。

## 中断的软硬件配合

[01:56:00 - 02:04:00]

硬件收到 K 号中断后会自动查表、按服务地址跳转，但表里的内容和目标处的程序都要操作系统提前准备：一是在内存中填写中断向量表，为 K 号中断向量写入正确的服务地址（指向内核空间某处）；二是在该地址提前编写好 K 号中断服务程序。两者都做好后，"硬件查表跳转 + 软件预先布置"即可完成整个中断处理。

> **定义**：中断向量表是硬件机制（硬件依规则查表跳转），其内容由操作系统在初始化时创建并填写，每次开机重新建立。

## 系统调用：与中断、异常的区别

[02:04:00 - 02:08:00]

系统调用是应用程序主动请求操作系统提供服务，处理过程必然进入内核态。与中断、异常的区别在于"是否本意"：中断是外部事件意外打断程序，异常是程序执行出错（如用户态执行特权指令触发越权异常）被动陷入，二者都不是程序想要发生的；系统调用则是程序有意识、有目的地请求内核代办。存储、I/O、文件等共享资源由操作系统统一掌管，用户程序只能通过系统调用获取。基本模型：用户程序按系统调用接口发起请求 → CPU 由用户态进入内核态处理 → 结果返回用户程序。

## 系统调用的执行过程（printf 例）

[02:08:00 - 02:15:00]

`printf` 是 C 标准库提供的函数，它并不符合系统调用的接口规范，故先由库函数把它转换成标准形式（如 `sys_write`：写、目标是屏幕、内容是 "123"）。随后用户程序主动触发一个类型为"系统调用"的异常——注意所有系统调用的异常类型都相同，不叫"写屏幕"；CPU 据此查中断向量表，跳到系统调用服务程序，同时把系统调用号与参数传进去。服务程序用系统调用号查系统调用表（表项是函数指针），定位到 `sys_write` 的实现并调用，参数即屏幕与 "123"；执行完把结果沿原路返回给应用程序。

> **易错点**：异常/中断号只表示"这是一次系统调用"这一类，具体是哪种系统调用由系统调用号区分；两者不能混。
> **易错点**：系统调用表存的是函数指针，中断向量表存的是服务程序首地址，二者不是同一张表。

> ⚠️ **需回看视频 [02:14:00]**：此处老师自述讲解有小问题，函数名与指针跳转的衔接需复核 —— "这个地方有点小问题。执行这个ciswrite这个函数。"

## 三类用户接口：命令接口、程序接口、图形接口

[02:15:00 - 02:18:00]

命令接口：用户在终端输入 `ls`、`cd` 等命令，内核并不认识这些字符串，需由命令解释程序翻译成一组系统调用再去执行（如 `ls /root/ab` 被翻译为若干 sys 调用）。程序接口：即系统调用，是操作系统暴露给用户程序使用的接口。图形接口：双击图标等图形操作，本质也是被解析成系统调用。三者殊途同归，最终都落到系统调用。

## 自陷指令与访管中断

[02:18:00 - 02:22:00]

系统调用依赖自陷指令：它在用户态执行，主动陷入内核态（x86 形式为 `int 0x80`，即触发 0x80 号异常）。同一事物在 408 中有多个名字：自陷指令 = trap 指令 = 陷阱指令 = 陷入指令 = 访管指令；由它引发的异常称访管中断。两个特点：其一，自陷指令只能在用户态使用（从用户态陷入内核态才叫自陷）；其二，触发异常时保存的断点是下一条指令的地址，否则返回后会重复执行该自陷指令，形成死循环。

> **易错点**：自陷指令的断点是"下一条指令地址"，而故障类异常的断点通常是"当前出错指令地址"（需重新执行）。

## 系统调用的实现（Linux int 0x80）

[02:22:00 - 02:30:00]

前置工作：操作系统在初始化时把 0x80 号中断向量的服务地址指向内核中专门处理系统调用的程序。调用时，用户在用户态先把系统调用号放入 AX、参数依次放入 BX、CX、DX——之所以用寄存器，是因为用户态与内核态共用同一套寄存器，而内存传递不便、栈更不能跨（用户栈与内核栈是两个栈）。随后执行 `int 0x80` 陷入内核，服务程序从寄存器取出系统调用号与各参数，按号查系统调用表得到函数指针，调用对应实现（如 `sys_read(fd, buf, count)`），再把返回值放入 AX，中断返回用户态后取回结果。流程可归纳为：传参（用户态）→ 自陷（用户态）→ 内核取参查表执行 → 返回结果（用户态）。

> **易错点**：断点、参数都在内核栈/寄存器中，用户栈的内容不能直接被内核当作参数来源。

> ⚠️ **需回看视频 [02:24:00]**：`sys_read` 的第三个参数被读作 "flag"，与常见 `count` 不符，疑为口误或 ASR 错误 —— "cis read，然后它需要的三个参数：fd、buff、flag"

## 补充辨析：自陷次数、断点保存位置与中断周期

[02:30:00 - 02:36:00]

一次系统调用只有一次自陷；程序中若有多处系统调用，就有多次"陷内核—回用户"的往返。断点（PC、PSW）在 x86 下压入内核栈，但不同架构不一定如此，故一般只表述为"保存断点"而不强调位置。中断周期只做硬件的三件事（关中断、保存断点、跳转服务程序）；系统调用引发的自陷发生在指令执行过程中（执行周期），并不发生在中断周期，不要混淆。所谓用户态/内核态，描述的是执行这些操作时 CPU 所处的状态。

## 第一类虚拟机

[02:36:00 - 02:41:00]

虚拟机的共同作用是模拟硬件，并在每份（虚拟）硬件上装一个操作系统。第一类虚拟机的虚拟机管理程序（VMM）直接运行在硬件上，把一份物理硬件切分成多份虚拟硬件（如 4GB 内存切成 4×1GB），每份虚拟硬件上跑一个操作系统，故每个虚拟机 = 虚拟硬件层 + 一个操作系统；技术足够时甚至能在 x86 上模拟出 MIPS、ARM 等不同架构。特点：高性能（直接跑在硬件上，无宿主操作系统干扰）、隔离性与安全性高、稳定性可靠性好；缺点是需专门硬件支持、成本高、实现复杂。

## 第二类虚拟机

[02:41:00 - 02:47:00]

第二类虚拟机的 VMM 是运行在宿主操作系统之上的一个普通应用程序，用宿主 OS 提供的功能"假装"出硬件——例如用一个 int 数组模拟内存，把某个 4B 元素"分配"给上层当内存用，再封装成 ISA 接口冒充硬件，上层操作系统看不出真相。最关键的一点：VMM 及其上运行的操作系统，在真实机器的视角下都处于用户态，它们自认为的内核态、ISA 都是模拟出来的。特点：部署方便、灵活性高（只是一个应用），但性能较低。

> **易错点**：第二类虚拟机中的"客户操作系统"在真机中运行在用户态，不能因为它自称内核态就判为内核态。

## 手工操作与批处理阶段

[02:47:00 - 02:50:00]

手工操作阶段：程序写在纸带/插板上，需人工装入、人工取出，任务串行、效率极低，尚未形成操作系统。批处理阶段：多个作业成批提交给系统，由系统逐个完成。批处理系统最重要的特征是与用户没有交互性，这一句是选择题最常设置错误选项的地方。单道批处理：内存中同时只有一道作业，一道完成才装入下一道，CPU 与 I/O 无法重叠，等待 I/O 时 CPU 空转。

> **易错点**：批处理系统"无交互性"是必背判断点，凡说批处理有良好交互性的选项一律错。

## 多道程序设计、实时、分时与分布式

[02:50:00 - 02:54:00]

多道程序（多任务）：内存中同时存在多道作业，一道因 I/O 让出 CPU 时切换另一道运行，CPU 与 I/O 得以重叠，CPU 不再空转，利用率提高；切换时主要工作就是修改 PC 等现场信息。实时操作系统：强调对高优先级任务响应快，一定是抢占式的、一定具有优先级；但抢占式系统不一定是实时系统。分时操作系统：各任务按时间片轮流占用 CPU（时间片轮转），依靠定时中断实现 CPU 复用。分布式操作系统：任务过大时用多台机器协同完成，需要一个网络层面的操作系统统筹分配与汇总。

## 操作系统的引导过程

[02:54:00 - 02:59:00]

引导的本质与运行普通程序相同：把操作系统从磁盘装入内存，并把 CPU 控制权交给它。三步：①执行 BIOS——BIOS 是存放在内存 ROM 区的固件（ROM 断电不丢），开机后 PC 指向其入口，完成简单自检并把磁盘第一个扇区（MBR）读入；②执行 MBR——MBR 中含磁盘分区表，据此列出各分区及是否为系统盘，选定分区后读取该分区第一个扇区（PBR）；③执行 PBR——把本分区内保存的操作系统镜像装入内存，PC 指向 OS 入口，操作系统正式接管。每次开机都会执行这三步。

> **易错点**：BIOS 只负责读取磁盘第一个扇区（MBR），它并不知道内核在哪个扇区；找内核是 PBR 的职责。

## 分层结构

[02:59:00 - 03:01:00]

操作系统按层组织：应用程序 → 非核心功能 → 核心功能（进程管理、内存管理、文件管理、中断管理等）→ 硬件抽象层 → 硬件；调用只能自上而下逐层进行，不能反向。优点是易于调试与验证（可逐层排查）、可扩展性强；缺点是层层传递信息，性能较低。

## 模块化结构

[03:01:00 - 03:02:00]

把内核划分为若干功能模块，模块间通过约定好的接口通信，模块内部还可再分子模块。与分层结构的核心区别是调用方向：分层只能自上层调用下层，模块化允许模块间互相调用（如进程管理调用内存管理提供的建页表接口）。

## 宏内核与微内核

[03:02:00 - 03:05:00]

宏内核：所有内核功能都运行在内核态、同一地址空间，模块间直接函数调用，性能高；但任一模块崩溃会导致整个内核崩溃，模块越多风险越大，安全性较差——408 题目若不特别说明，默认都是宏内核。微内核：内核态只保留最核心的功能，其余功能以独立进程的形式移到用户态；某模块崩溃只需杀掉该进程重建，不影响整个系统，故安全性与可扩展性更强。代价是各模块处于不同地址空间，模块间通信必须依靠 IPC，且同一功能被拆到用户态/内核态两侧，导致特权级切换频繁，性能低于宏内核。

> **易错点**：结论是"微内核安全性强、可扩展性强，性能低于宏内核"，不要反向记。

## 外核

[03:05:00 - 03:08:00]

外核把硬件资源直接切分给各用户程序独占使用，用户程序与外核（管理这部分硬件资源的接口）链接成一个整体、同在**内核态**运行，通过函数库直接使用未经抽象的硬件资源。因此外核设计中不需要系统调用，也不区分用户态与内核态；程序结束时该任务连同分配到的资源一起销毁并归还计算机。它常与虚拟机结合使用，典型实例是 Ulysses。

> **易错点**：外核中用户程序运行在内核态（因为它独占切分到的资源、不需要被保护），这与"用户程序一定在用户态"的常规印象相反。

## 本讲重点与答疑补充

[03:08:00 - 03:18:17]

本讲真正的核心是中断与系统调用：不理解中断和系统调用，后面进程、内存、文件的学习都会是"表面会、实际不会"。考点分布上，外核、微内核、分层/模块化等零散内容多以选择题出现，但每个点都可能考，时间允许应全部覆盖。程序的段归属（代码段/数据段/BSS/堆/栈）2025 年刚考过大题，必须记牢每类数据属于哪个段。中断向量表在操作系统初始化时创建（即 OS 装入内存、PC 指向其入口后做的第一批工作之一），每次开机重新建立；程序运行中会频繁经由系统调用、中断、异常在用户态与内核态之间往返。
