# 第5讲 高速缓存

## 【视频01】课程导学与考情分析

[00:00:00 - 00:06:00]

本讲是存储器三讲中的第二讲，专讲 Cache，第三讲（下周六）为存储器的综合。全讲分五节：Cache 基本知识、局部性原理、Cache 硬件结构、Cache 映射方法、Cache 写操作。按满分 5 分打分：`映射方法` 为 5 分（必考，几乎每年都考，选择题或大题都可能出现）；`硬件结构` 约 4 分（可能出选择题，且是映射方法的基础）；`写操作` 约 2～3 分（主要考脏位）；`局部性原理` 与 `基本知识` 是后面三部分的基础，必须先记牢。

> **易错点**：映射方法是本讲最高优先级内容，属于必须掌握的核心考点。

## 【视频01】为什么需要有 Cache（Cache 的目的）

[00:06:00 - 00:11:00]

现代主存（内存）与 CPU 交互时，读/写一个存储单元约需 `100ns`。而一个主频 `2GHz` 的 CPU 理想情况下每 `0.5ns` 就能产生一次访存请求，若所有访存都直接与主存交互，CPU 会被主存严重拖累。为缓解 CPU 与主存之间的速度不匹配，在 CPU 内部加入高速缓存 `Cache`，提供一个容量小但速度快的缓冲存储空间。主存把 CPU 近期常用的内容放入 Cache，CPU 先访问 Cache，命中则直接取用，未命中再访问主存，从而尽量减少主存的慢速拖累。

> **定义**：Cache（高速缓存）是位于 CPU 内部的硬件部件，用于缓解 CPU 与主存之间的速度差异。

## 【视频01】含 Cache 的访存过程与 Cache 的物理特性

[00:11:00 - 00:21:00]

以检索磁盘中的文件 A 为例：加入 Cache 后，主存会先把一个连续的数据块（如 `16字节`）放入 CPU 内部的 Cache，CPU 仍逐字节访问，但改为先查 Cache；命中即直接从 Cache 读入，未命中才访问主存，后续由主存完成相关工作。Cache 位于 CPU 内部，由 `SRAM` 半导体材料构成，因此具备三个特性：运行时必须时刻带电（断电即丢失全部信息）、读写速度非常快（近似等于 CPU 执行一条指令的时间）、只能小规模存储（SRAM 集成度低，无法像主存/磁盘那样大规模存储）。带 Cache 的完整访存定义：CPU 访问某存储单元时先把地址写入 `MDR`，优先检查 Cache 是否含该单元数据；含则把数据送入 CPU，不含则地址送主存，主存把该单元数据经数据总线送入 `MDR`，同时并行地按映射算法选中一个 Cache 行，把该存储单元所在的整个主存块也送入该 Cache 行。

> **易错点**：未命中时"把数据送回 CPU"与"把主存块送入 Cache"是并行完成的（袁春风教材口径）。

## 【视频01】主存块的由来，及数据块与程序块

[00:21:00 - 00:35:00]

CPU 与内存由不同厂商生产（CPU 多为 Intel/AMD，内存条为三星/海力士等），而 DRAM 芯片出厂时每个存储单元长度已被固定为 `1字节`，无法为不同字长的 CPU 定制；若 CPU 每次只按一个存储单元（1字节）取数又太慢。于是 CPU 通过内存控制器接口向内存提出一个"逻辑概念"——`主存块`：主存块大小由 CPU 决定（如奔腾系列规定为 `32字节`），主存取数时一次把组成该块的多个连续存储单元同时送给 CPU。主存块是一组地址连续的存储单元。若主存块中保存的是数据（如 int 数组的元素）就称为 `数据块`，若保存的是指令（机器码）就称为 `程序块`。

> **易错点**：存储单元长度在 DRAM 出厂时固定；主存块是 CPU 提出的逻辑概念，其大小由 CPU（及其 Cache 行）决定，而非由内存厂商决定。

## 【视频01】局部性原理及其在 DRAM 芯片与内存条中的应用

[00:35:00 - 00:50:00]

局部性原理含两部分，需背熟、多结合程序/代码考察：`时间局部性`——某数据现在被访问了，以后还有可能被访问；`空间局部性`——某数据现在被访问了，它周围的数据以后也有可能被访问。Cache 是空间局部性在硬件上的典型应用：把近期常用数据放入高速小容量的 Cache，使 CPU 访存大多针对 Cache。`主存块` 是空间局部性在单个 DRAM 芯片上的应用：它是地址连续的一组存储单元，且首个存储单元的地址对"块内存储单元个数"取余必须为 `0`（如 4 个连续单元成块，首地址须模 4 为 0）。在内存条上，多个 DRAM 芯片普遍采用 `交叉编址`（顺序编址基本不用）。408 默认规则：一个主存块包含的存储单元个数一般等于内存条中 DRAM 芯片（存储体）的个数；如 4 个存储体、每个存储单元 `4字节` 时，主存块常设为 `16字节`（即 `4×4`）。

> **公式**：主存块大小 = 存储体个数 × 每个存储单元的字节数（408 常见设定）。

## 【视频01】时间局部性举例与带 Cache 的访存步骤

[00:50:00 - 00:54:00]

时间局部性的典型例子是双重 `for` 循环：内层循环变量（如 `j`）在第 1、2、3…… 轮中被反复访问，即被访问过的数据以后还会被访问。主存块的设计思想正是空间局部性——块内某个存储单元被访问时，其周围单元也可能被访问。在 408 体系下，`MDR` 的长度与存储单元大小一致（MDR 一次保存一个存储单元），而 Cache 是按主存块为单位保存的。带 Cache 的 CPU 访问某存储单元的步骤为：①把该单元地址写入 `MDR`；②检查 Cache 是否保存了该单元数据，有则送入 CPU；③没有则地址送往主存，主存把该单元数据经数据总线送入 `MDR`，同时按映射算法选中一个 Cache 行，把该单元所在的主存块整个送入该 Cache 行。

## 【视频01】课间答疑：数据/指令 Cache、主存块大小的确定与未命中的并行处理

[00:54:00 - 01:13:00]

答疑一：CPU 如何区分数据块与程序块？其实 Cache 本身区分不了，所以 CPU 内部设置了两个 Cache——`数据 Cache` 与 `指令 Cache`，两者结构完全相同，数据放数据 Cache、指令放指令 Cache。答疑二：主存块是否等于机器字长？不是，CPU 设计比人想得更"贪心"：Cache 行（含数据部分，如奔腾为 `32字节`）在 CPU 出厂时就已固定，CPU 告诉主存的主存块大小，正是"一个 Cache 行能保存的数据字节数"，而非一个字长。答疑三：未命中后"更新 Cache"与"把数据写入 CPU"是否并行？袁春风教材把"送数据到 CPU"与"主存块复制到 Cache"两步并行；而 CSAPP、唐朔飞教材则是先把主存块送入 Cache，再访问 Cache 取数据（串行）。408 按并行方式（袁春风口径）命题（如 2013 年计组大题），考试最好按此书写；其余教材差异了解即可。

## 【视频01】Cache 硬件结构：数据/指令 Cache、Cache 行、标记阵列与有效位

[01:13:00 - 01:28:00]

现代计算机设两个结构完全相同、数据量相同的 Cache：`指令 Cache` 与 `数据 Cache`，用于解决指令与数据在 Cache 中存放的冲突。主存按区划分（程序代码区、堆区、栈区等）：程序代码区的主存块放入指令 Cache，堆区等数据的主存块放入数据 Cache。Cache 由若干个 `Cache 行` 构成，每行分数据区与控制信息区，行内数据取自一个主存块，且 Cache 行能保存的数据大小必须与主存块大小完全一致，主存块放入哪一行遵循 `映射规则`。全部数据侧合称 `数据阵列`，控制信息中保存 Tag 的部分合称 `标记阵列`；控制信息里最重要的是 `有效位`（1 比特，标志行内数据是否有效，删除数据时只把有效位置 0 而不真正抹除）与标记 `Tag`。其行为与总容量：若 Cache 能存 `256字节` 数据、主存块为 `8字节`，则 Cache 行数 = 256 / 8 = 32；Cache 总容量 = 数据区容量 + 所有控制信息容量，故总容量一定大于数据区容量。

> **公式**：`Cache 行数 = 数据区容量 / 主存块大小`；`Cache 总容量 = 数据区容量 + 控制信息总容量`。
> **易错点**：Cache 行（数据区）容量会用于计算，控制信息容量另计，切勿把 Cache 总容量当作数据区容量。

## 【视频01】控制信息四部分与三种映射方式的引入

[01:28:00 - 01:32:00]

Cache 行的控制信息共有四个部分：`Tag`、`有效位`（任何映射方式都必有）；`算法替换位`（全相联/组相联且采用 LRU 时才涉及）；`脏位`（写策略采用回写法时才涉及）。主存与 Cache 的映射方式共三种：`直接映射`、`全相联映射`、`组相联映射`。映射的时机：某存储单元的内容在 Cache 中无备份、发生 `Cache miss`（未命中）时，主存把该单元所在的主存块按映射规则送入 Cache。映射的依据是存储单元的地址——把地址做划分，一部分送到数据阵列以选定行，另一部分（Tag）送到标记阵列作为该主存块的标记。

## 【视频01】直接映射：思想、地址划分与例题

[01:32:00 - 01:44:00]

由于 Cache 容量远小于主存容量，Cache 行数也远少于主存块数（如奔腾的 Cache 总容量仅约 `2^13 字节`，远小于 `8GB` 主存的块数）。`直接映射` 采用取余思想：每个主存块只能映射到唯一一个 Cache 行，而一个 Cache 行可对应多个主存块。例：主存 `64KB`、按字节编址（地址 `16位`）、Cache 数据区 `16行`、主存块 `8字节`，问十进制 `248` 号存储单元映射到哪一行。人类算法：248 / 8 = 31 号主存块，31 mod 16 = 15，故映射到 `第15个 Cache 行`。计算机则采用地址划分法：直接映射把地址分成三段——`块内偏移`、`行号`、`Tag`。`块内偏移位数 = log2(块大小)`（8B→3 位），`行号位数 = log2(Cache 行数)`（16 行→4 位），`Tag = 地址总位数 − 行号位数 − 块内偏移位数`。将 248 写成二进制后，最低 3 位为块内偏移、中间 4 位为行号（=15）、其余为 Tag；该单元所在主存块的 8 个字节整体放入第 15 行，Tag 写入该行的标记位。

> **公式**：`块内偏移位数 = log2(块大小)`；`行号位数 = log2(Cache 行数)`；`Tag 位数 = 地址总位数 − 行号位数 − 块内偏移位数`。
> **易错点**：Cache 与主存的交互单位是主存块，求"某存储单元映射到哪一行"时须先用 `地址 / 块大小` 取整换算成主存块号。

## 【视频01】直接映射的命中判断、比较器、多路选择器与替换

[01:44:00 - 01:50:00]

读取流程：硬件先按地址的 `行号` 字段定位到某个 Cache 行，再查看该行 `有效位` 是否为 1。若有效位为 1，则用地址中的 `Tag` 字段与标记阵列中该行保存的 Tag 比较：两者都成立才算命中，命中后把数据送入 CPU 的 `MDR`；有效位为 0 或 Tag 不一致都产生 `Cache miss`。比较器：采用直接映射时只需 `1 个比较器`；一款 CPU 采用何种映射由出厂硬件决定，终生不可更改。多路选择器：根据 `块内偏移` 从命中的 Cache 行中选出具体的那一个字节送入 `MDR`。若未命中，则主存把该单元数据送入 MDR，同时把该单元所在主存块更新到对应的唯一 Cache 行；若该行已被占用，则先把旧数据置换出去再填入，并修改相应控制信息。

> ⚠️ **需回看视频 [01:44:00]**：命中判断处表述自相矛盾（"两个都成立"却称 `cache miss`，随后又说"命中之后"送 MDR），疑似口误或转写错误 —— "这两个都成立的时候，则 cache miss 啊，然后呢，命中之后将数据送到 CPU 中的 MDR"

## 【视频01】全相联映射：思想、地址划分与查找

[01:50:00 - 01:56:00]

`全相联映射` 的思想是"随便放"：一个主存块可放入 Cache 中任意一行（不考虑替换算法时），灵活度最大，块在 Cache 中没有固定位置。地址划分最简单，只需两段：`Tag` 与 `块内偏移`——块内偏移位数取决于块大小，其余全部为 Tag（全相联下 Tag 表示"第几个主存块"）。查找方式：从第 1 行开始逐行比较有效位与 Tag，一旦命中即停止；最坏情况需比较完全部行才发现未命中，因此速度慢。比较器个数存在两种设计：若每行设一个比较器则可并行比较（速度快、但功耗大）；若只用 1 个比较器则串行比较（功耗低、但速度慢）。考试一般不考该比较器个数，除非题目给出"不考虑功耗/最快"之类前提。

> ⚠️ **需回看视频 [01:51:00]**：此处口误，本应指"直接映射划分成三个部分"，却说成"组相联划分成了两个部分"，前后指代混乱 —— "那么我们前面组相联划分成了两个部分啊，这个这个主存地址划分成了两个部分"

## 【视频01】替换算法与 LRU 的基本思想、实现与规则

[01:56:00 - 02:07:00]

当 Cache 行装满而又要映射入新的主存块时，需用替换算法决定淘汰哪一行；直接映射因位置唯一，不含替换算法。三种替换算法：`随机替换法`（随机触发器产生一个行号，无局部性）、`先进先出 FIFO`（按队列淘汰最早装入的，无局部性）、`最近最少使用 LRU`（考试最常考）。LRU 基本思想：总是淘汰近期最少使用的主存块，符合时间局部性；相当于对每个 Cache 行按使用情况排序，访问越多者越不易被替换。实现方式：在标记阵列中为每行设一个计数器（即 `LRU 位`，若题目说明采用 LRU，则它就是 `算法替换位`），用计数值记录使用情况，淘汰时只需把被淘汰行的有效位清零；位数取决于行数，`n 行需 log2(n) 位`（16 行→4 位，32 行→5 位）。LRU 替换规则：①命中时，被访问行的计数器清零、比其低的计数器加 1、其余不变；②未命中且该组有空闲行时，新装入行计数器置 0、其余加 1；③未命中且该组无空闲行时，淘汰计数值最大（如 3）的那一行，新装入行置 0、其余加 1。

> **易错点**：LRU 三规则必须记清——命中时"被访问行清零、比其低者加 1、其余不变"，很多同学在此处容易混淆。
> ⚠️ **需回看视频 [01:59:00]**：休息时段出现与课程无关的文本，疑似识别异常/串入无关内容 —— "由于缺乏对当地社会和自然环境的了解，早期的探险家在踏上征途时，往往需要付出沉重的代价。"

## 【视频01】LRU 替换算法例题

[02:07:00 - 02:16:00]

例：主存 `24字节`、Cache `16字节`、全相联方式、主存块 `4字节`、按字节编址，CPU 给出主存地址访问序列（`04H、08H、0CH、05H、09H、14H、06H、0AH`…），按 LRU 选出被替换的块。第一步先把地址序列换算成主存块号（`04H→1号块`、`08H→2号块`、`0CH→3号块`…），即用地址除以块大小取整。随后按三条规则逐步更新各行计数器：初始 Cache 为空，前几次访问未命中且有空闲行（新行置 0、其余加 1）；命中时被访问行清零、比其低者加 1；当命中已满时，淘汰计数值为 3 的行并装入新块（新行置 0、其余加 1）。整个过程就是反复做"置 0 / 加 1"的计数器操作，最终不断淘汰计数值最大的块。

> **易错点**：大题必须写出完整过程（有过程分）；两分的选择题不必用这种最慢的完整写法，用自己更快的方法即可。

## 【视频01】替换算法的适用场景与算法替换位

[02:16:00 - 02:18:00]

替换算法只出现在 `全相联` 与 `组相联` 中，`直接映射` 不含替换算法。采用 LRU 时，需要在标记阵列之外额外增加一些信息，即 `算法替换位`，用于给相关 Cache 行排序。算法替换位的位数与"参与排序的行数"有关：全相联时与整个 Cache 的行数有关（如 8 行需 3 位），组相联时只与组内的行数有关（如组内 8 行需 3 位）。

## 【视频01】组相联映射：概念、地址划分、计算、注意点与替换

[02:18:00 - 02:32:00]

`组相联映射` 把若干 Cache 行合为一组（k 个行为一组即 k 路组相联），用以调和全相联"查找慢"与直接映射"易频繁替换"的矛盾；其思想是：组间采用直接映射、组内采用全相联映射（类似磁盘先寻道、再在磁道内顺序查扇区的思路）。地址划分三段：`块内偏移`（由块大小定，4B→2 位）、`组号`（由组数定，4 组→2 位）、`Tag`（地址总位数 − 组号位数 − 块内偏移位数）。例：`1KB` 主存（地址 `10位`）、数据区 `32字节`、Cache 行 `4字节` → 8 行；采用两路组相联 → 4 组。对地址 `1011011001`：低 2 位为块内偏移、中间 2 位为组号（`10` 即第 2 组）、高 6 位 `Tag = 2DH`，将该 Tag 与组内两行同时比较，某行有效位为 1 且 Tag 一致即命中。注意两点：组相联下主存地址的 Tag 位数并未减少、反而增加；比较器个数等于路数（四路组相联 = 4 个比较器）。加入/替换：组内有空闲行时可在组内任选行放入，组内满时用随机/FIFO/LRU 在组内替换；组相联的 LRU 算法替换位取决于组内行数（组内 8 行→3 位，组内 4 行→2 位）。

> **公式**：`组数 = Cache 行数 / 路数`；`组号位数 = log2(组数)`；`Tag 位数 = 地址总位数 − 组号位数 − 块内偏移位数`。

## 【视频01】命中率、缺失率与平均访问时间

[02:32:00 - 02:41:00]

若 CPU 访问的存储单元所在块在 Cache 中，称为 `Cache 命中`，命中概率为 `命中率 H = 命中次数 / 总访问次数`；不在 Cache 中则未命中，`缺失率 = 未命中次数 / 总访问次数 = 1 − H`。命中时 CPU 直接在 Cache 中存取所需的时间开销为 `Tc`（命中时间）；未命中时需把主存块读入 Cache 并把所需信息送 CPU，开销为 `Tm`（缺失损失）。平均访问时间其实是概率期望：`T = H·Tc + (1−H)·(Tc + Tm)`；未命中时间里必须含第一个 `Tc`，因为必须先访问 Cache 才知道未命中，之后再加 `Tm`。

> **公式**：`命中率 H = 命中次数 / 总访问次数`；`缺失率 = 1 − H`；`平均访问时间 T = H·Tc + (1−H)·(Tc + Tm)`。
> **易错点**：是否加第二个 `Tc` 取决于教材——408 按并行方式（主存送数据到 CPU 与送块到 Cache 并行）只加一个 `Tc`。

例（平均访问时间）：主存块 `16字节`、命中 `5ns`、未命中损失 `40ns`，`int` 数组有 `100` 个元素（每个 int 4 字节）。一个块可放 4 个 int、共 `25` 块，每块只第 1 个元素未命中，故每块未命中率 `1/4`、命中率 `3/4`；单块时间 = `3/4×5 + 1/4×(5+40) = 15ns`，数组读操作总计 = `25 × 15 = 375ns`。（该例题原题还需补上"存储单元长度与机器字长均为 `32比特`"的条件才严谨。）

## 【视频01】Cache 写操作（全写法/写分配法/回写法）与控制信息总结

[02:41:00 - 02:51:00]

`全写法`（写直达）：写命中时同时写 Cache 和主存；写未命中时有两种处理——`写分配法`（先在主存更新相应存储单元，再分配一个 Cache 行把更新后的主存块装入，能利用空间局部性，但每次写未命中都要从主存读入一个块，增加开销）与 `非写分配法`（只更新主存单元，不把主存块调入 Cache，减少读入 Cache 时间，但未很好利用空间局部性）。`回写法`（写回法）：写命中时信息只写入 Cache、不写主存；写未命中时在 Cache 中分配一行，把主存块调入该行并更新相应单元内容。为减少写回主存块的开销，每个 Cache 行新增一个修改位即 `脏位`：脏位为 1 表示该行主存块被修改过，替换时需写回主存；为 0 则无需写回。控制信息四部分总结：`有效位` 与 `Tag` 任何映射方式都有；`算法替换位` 只在全相联/组相联且用 LRU 时出现；`脏位` 只在写策略采用回写法时出现。

> **易错点**：脏位仅与回写法绑定；算法替换位仅与全相联/组相联 + LRU 绑定。

## 【视频01】综合例题（2016 真题缺失率、组相联总容量与比较器个数）

[02:51:00 - 03:02:00]

例 1（2016 真题）：数组 A 与变量 K 均为 `int`（4 字节），主存采用直接映射，数据 Cache 数据区 `1KB`、主存块 `16字节`，程序执行前 Cache 为空，循环体为 `a[k] = a[k] + 32`（先读后写）。数组 A 共 `1000` 个 int = `250` 个块，每块含 4 个 int；对每块：读首个元素未命中（调入该块），写回该元素命中，其余 3 个元素的读、写均命中，故每块 `1 次未命中、7 次命中`，缺失率 = `1/8`，选 C。

例 2：主存地址 `12位`、按字节编址，指令/数据 Cache 与主存采用四路组相联，写策略为回写法，替换算法为 LRU，主存块 `4字节`，指令与数据 Cache 数据区各 `64字节`。求数据 Cache 的总容量与比较器个数。比较器个数 = 路数 = `4`。Cache 行数 = 64 / 4 = `16` 行，四路组相联 → 4 组 → `组号 2 位`；`块内偏移 = log2(4) = 2 位`；`Tag = 12 − 2 − 2 = 8 位`。每行控制信息 = 有效位 `1` + Tag `8` + 算法替换位 `2`（组内 4 行用 LRU）+ 脏位 `1` = `12 位`；16 行共 `16×12 = 192 位 = 24 字节`，总容量 = `24 + 64 = 88 字节`。

> **易错点**：题目问的是"数据 Cache 的总容量"，只算数据 Cache，切勿再叠加指令 Cache。

## 【视频01】答疑与课程总结

[03:02:00 - 03:07:26]

答疑：替换算法不必纠结用链表等数据结构实现，硬件本身已固定，按硬件设计去理解其算法即可。答疑：未命中时间为什么是 `Tc + Tm` 而不是 `Tc + Tm + Tc`——408 按并行方式，主存块送入 Cache 与把数据送入 CPU 是并行进行的，`Tm` 期间 `MDR` 已获得该单元数据，故只加一个 `Tc`。答疑：数据 Cache 总容量题只算数据 Cache，误加指令 Cache 就会做错。总结：本讲（及前一讲）内容必须在一周内掌握，下周六为存储器综合课。
