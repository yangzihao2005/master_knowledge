# 计算机组成原理强化课 第5讲 IO和多处理器

## 并行计算的引入：从单核频率瓶颈到多处理器

[00:00:00 - 00:09:00]

本讲是强化阶段最后一讲，内容分两块：多处理器（并行计算入门，2022 年新考纲新增）与 I/O 知识强化回顾；多处理器部分包含 Flynn 分类、SIMD 与向量处理器、MIMD、按访存时间划分四块。此前学过的 CPU 结构（单周期、多周期、流水线）在执行指令时都是顺序地一条条执行，流水线只是让多条指令在时间上重叠，并不能减少指令条数。当指令条数与 CPI 固定时，缩短执行时间只能靠提高主频、缩短时钟周期；而单核主频提升到一定程度后遇到工艺瓶颈，于是转向并行：用多个 CPU 或多条流水线同时执行不同指令，理想情况下 N 个处理器可获得 N 倍加速。

> **公式**：指令执行时间 = 指令条数 × CPI × 时钟周期 = 指令条数 × CPI / 主频
> **易错点**：流水线是"重叠执行"而非"同时执行不同指令"，指令仍按序逐条流入，整体仍属 SISD。

## 并行体系结构的两种分类视角

[00:09:00 - 00:14:00]

多处理器有两套相互独立的分类：Flynn 分类按指令流与数据流的数量组合，分为 SISD、SIMD、MISD、MIMD；按访存时间是否一致分为 UMA 与 NUMA。SISD 就是前面学的顺序执行单流水线；SIMD 是一条指令驱动多个 ALU 处理多组数据（GPU 的思想源头）；MIMD 是同时执行多条指令（多核）。按访存时间分类关注的是多个处理器访问主存所需时间是否相同：相同为 UMA，不同为 NUMA。两套分类可以同时描述同一个结构，只是角度不同。

> **定义**：Flynn 分类（1966 年，斯坦福）按指令流与数据流的组合方式对并行计算机划分。

## Flynn 分类的四种模型

[00:14:00 - 00:18:00]

SISD：单处理器、单存储器，指令串行执行，每条指令最多处理一或两个数据（单目/双目运算）。SIMD：一个指令控制部件 + 多个处理单元 + 多个存储部件，通过系统内部互连网络连接；控制部件仍串行取指，所有处理单元同时执行同一条指令、各自处理局部存储器中的不同数据。MISD：多条指令同时处理同一数据，仅是理论模型，实际不存在。MIMD：多条指令分别处理多组不同数据，必然包含多个处理器或计算机，是大多数并行处理系统的方式。

> **易错点**：SIMD 中的"存储器"指具有存储功能的部件（寄存器组、cache 等），不等于主存。

## SISD 与 SIMD：数组加法的执行开销

[00:18:00 - 00:21:00]

以 C[i]=A[i]+B[i]（n=128）为例，SISD 逐元素执行需取数 256 次、加法 128 次、写回 128 次，且全部串行，速度很慢。SIMD 正是针对图像卷积、矩阵运算这类大规模数组运算提出的：一条指令同时驱动多个 ALU 完成多组数据的同一运算，指令条数成倍减少。早期图像卡即采用 SIMD，之后逐步演化为 GPU；现代 GPU 与当时思想相比已迭代二三十年。

> **公式**：SISD 完成 n 个元素的 C[i]=A[i]+B[i]：取数 2n 次、加法 n 次、写回 n 次。

## 核（core）的概念

[00:21:00 - 00:24:00]

408 范围内"核"可理解为一条能完整独立执行指令序列的流水线，包含私有高速缓存、TLB、MMU、指令预取部件与执行部件。所谓"四核处理器"，就是一个 CPU 内含四条可独立工作的流水线，理想情况下同一时刻并行执行四条指令。CPU 即处理器，多核指一个处理器封装内的多个核，各核有独立的缓存与执行部件。

> **定义**：核 = 可独立取指、译码、执行、访存的完整指令流水线及其私有支撑部件。

## MIMD、多核与超标量流水线

[00:24:00 - 00:29:00]

多核 CPU 在硬件上存在多个单核，每核一条流水线，可同时执行多条指令，属 MIMD；由多台主机构成的集群在逻辑上也是一个 MIMD 系统，每台主机相当于其中的一个"核"。同一个"单 CPU 多核"结构，从体系结构角度命名为 MIMD，从流水线角度命名为超标量流水线。二者的实质区别在于：普通流水线同一时刻只流入一条指令，超标量/多核可同时流入多条。

> **易错点**：超标量流水线与单 CPU 多核是同一事物的两种命名，不能当成两种不同结构。

## SIMD 处理数组运算的优化思路

[00:29:00 - 00:32:00]

同一段 8 元素数组加法，单核 SISD 要执行 8 次循环、每次十余条指令；改用 SIMD 图像卡只需 4 条向量指令：两次向量取数、一次向量加、一次向量存数。根本原因是 SIMD 引入了向量寄存器与向量存储（访存）方式，使一条指令能搬运、处理一整组数据。这也是 SIMD 特别擅长数组/矩阵运算的原因。

> **公式**：SIMD 完成 n 元素加法 ≈ 2 条向量取数 + 1 条向量加 + 1 条向量存数 = 4 条指令。

## 向量寄存器与向量取数指令（VLW）

[00:32:00 - 00:39:00]

32 位机的通用寄存器为 32 位，一次只能放 1 个 int；SIMD 的向量寄存器典型大小为 32 字节，可同时存放 8 个 32 位数据，容量是通用寄存器的 8 倍。普通指令不能访问向量寄存器，必须使用向量指令：VLW（向量取数）从基地址 S1 起一次取出 32 字节装入向量寄存器，恰好是 a0~a7 八个 int。两次 VLW 即把数组 A、B 分别装入 VT1、VT2；元素超过 8 个时需多次取数、改用多个向量寄存器。

> **公式**：向量寄存器 32B = 8 × 4B；一次 VLW 搬运 8 个 int。
> **易错点**：通用寄存器与向量寄存器位宽不同，普通 load/store 调不动向量寄存器，指令集必须同时扩展出向量指令。

## 向量加法指令、多 ALU 与 GPU

[00:39:00 - 00:45:00]

向量加法 VT1+VT2→VT3 无法由单个 ALU 完成：SIMD 在执行段配置多个 ALU（如 8 个），每个 ALU 的两个输入端分别接 VT1、VT2 的对应元素，同时运算、同时出结果，8 个 32 位结果依次拼接进 VT3。随后用向量存数指令把 VT3 写回数组 C 的起始地址，整个数组加法结束。GPU 是同一思想的放大：内部有成百上千个 ALU，做 4×4 矩阵加法时同时启动 16 个 ALU，做 32 个元素的运算就并行开 32 个 ALU。

> **易错点**：SIMD 的三要素是向量寄存器、向量指令、多个 ALU，缺一不可。

## MIMD 的二次划分与多核（片级多处理器）

[00:45:00 - 00:49:00]

MIMD 按处理单元的位置与互连方式再分为多核（片级多处理器）、SMP、MPP 三类。多核（片级多处理器）指一个 CPU 封装内含多个处理单元，每核一条完整流水线并配有私有 L1 cache，所有核共享末级 cache 与主存，核数常见为 2、4、8。

> **易错点**：片级多处理器 = 单 CPU 多核；说"多处理器"却只有一个 CPU 封装时，指的是这一层。

> ⚠️ **需回看视频 [00:47:00]**：疑似 ASR 识别错误/口误，把 LLC 说成"一般叫 L2 cache"，与实际多级 cache 结构不符，可能原意为 L3 —— "所有的核呢可能会共享一个LLC叫last level cache啊，一般叫L2 cache啊"

## 对称多处理器 SMP

[00:49:00 - 00:53:00]

SMP 指多块相同类型的 CPU 通过总线互连，以同等级别共享所有存储单元，多个 CPU 对称工作、无主次从属关系；因为共享同一物理内存，任一 CPU 访问任一地址的时间相同。典型场景是服务器主板：一块板可插 2/4/8 个 CPU，每个 CPU 还可多核（如 4 路 × 4 核 = 16 核）。家用主板只插一个 CPU，因而不属于 SMP。

> **定义**：SMP（对称多处理器）= 多个同构 CPU 经总线互连、平等共享内存与 I/O，无主从关系（袁春风教材定义）。

## 大规模并行处理机 MPP（集群）

[00:53:00 - 00:56:00]

MPP 用专用互连网络（如交叉开关）把数百至数千个 SMP 服务器连成超大规模集群，众多节点协同完成同一任务；从用户视角看是一个服务系统，每个 SMP 是一个服务节点，节点只能直接访问本地资源。逻辑上整个集群相当于一台主机，集群内每台主机相当于其中的一个"核"。

> **易错点**：SMP 是"一板多 CPU"，MPP 是"多服务器（多板）"，两者层级不同，不要混说。

## 并行计算部分小结（含课间休息）

[00:56:00 - 01:07:00]

小结：此前学的处理器模型全部是 SISD；GPU/图像卡采用 SIMD，靠向量寄存器、向量指令、多 ALU 三项改进；现代多核 CPU 采用 MIMD，再往下细分为片级多核、服务器级 SMP、集群级 MPP。本时间段后半段为课间休息，无新知识内容。

> **易错点**：服务器级多处理器结构记作 SMP，不要写成 SMT。

> ⚠️ **需回看视频 [00:56:00]**：疑似口误/ASR 错误，服务器级多处理器结构被说成 "SMT"（应为 SMP）—— "服务器级别的又称为这叫什么 SMT 这种结构"

## 答疑：考点定位与概念辨析

[01:07:00 - 01:13:00]

新增的并行计算内容若考，一般是选择题。408 引用的本科教材结构多为二三十年前的设计，现代的大小核、RISC-V 新特性等不在考纲内，答题必须按教材口径。408 范围内向量寄存器只属于 SIMD 结构；超标量流水线归入片级多处理器（单 CPU 多核）。SMP 按袁春风教材定义：多个相同类型 CPU 经总线互连、平等共享存储。流水线中一次只进入一条指令，片级多核则同一时刻可有多条指令进入流水线。

> **易错点**：不要用现代处理器（大小核、实际 cache 层级）去套 408 的老结构。

## 按访存时间划分：UMA 与 NUMA

[01:13:00 - 01:19:00]

按访问存储器的时间是否一致分为 UMA 与 NUMA。UMA 中所有处理器共享同一主存，任一处理器访问任一存储单元时间相同，典型为个人电脑多核 CPU 与 SMP 服务器。NUMA 中每个处理器有自己的本地存储模块，经统一编址形成单一地址空间，但访问本地存储快、访问其他节点存储慢；典型为集群，跨节点访问需发送地址、经网络传输数据。

> **定义**：UMA = 各处理器访存时间一致；NUMA = 访问本地存储器快于访问其他节点的存储器。

> ⚠️ **需回看视频 [01:14:00]**：疑似口误/ASR 错误，把一致性访存结构说成 NUMA（应为 UMA）—— "这个叫一致性的一个NUMA结构啊"

## 带 cache 的 UMA 与 cache 一致性问题

[01:19:00 - 01:24:00]

带 cache 和私有寄存器的 UMA 中，每个核只能访问自己的私有 L1 cache 与寄存器组，不能访问其他核的私有 cache；所有核共享 L2 cache 与主存，访问公共存储的时间仍一致。由此产生 cache 一致性问题：核一用回写法修改了 L1 中某块数据且该行未被替换，尚未写回主存；核二访问同一地址时从主存取到旧值。解决方案（如 MESI 协议）不在 408 要求内，只需知道问题会产生。

> **易错点**：一致性问题的根源是"私有 cache + 写回策略 + 共享主存"，三者同时具备才会出现。

## NUMA 的两种形态：NC-NUMA 与 CC-NUMA

[01:24:00 - 01:31:00]

NUMA 系统不带高速缓存时称 NC-NUMA（No Cache），每次都要直接访存，速度较慢；集群各主机配备一致性高速缓存时称 CC-NUMA，须维护 cache 一致性。CC-NUMA 常用基于目录的机制：每台主机增设目录，记录本地每个存储块是否被某节点的 cache 引用及引用者节点号；取数原则是"能在某主机的 cache 中找到，就绝不从存储器取"。目录项由有效位（是否在某 cache 中）与标记位（在哪个节点）构成。

> **定义**：CC-NUMA = 带一致性高速缓存的 NUMA；目录 = 记录存储块被哪个节点 cache 引用的表。
> **易错点**：NC/CC 中的 C 分别是 No Cache 与 Cache Coherent，两者都属 NUMA，不要与 UMA 混淆。

## 硬件多线程：细粒度与粗粒度

[01:31:00 - 01:37:00]

硬件多线程让多个线程以重叠方式共享处理器资源，为每个线程复制独立的寄存器文件与 PC，线程切换可实时完成，远比进程切换（数百至数千周期）轻量。细粒度多线程：每条指令执行后即切换线程，多线程交叉循环执行，每时钟周期跳过阻塞线程，硬件须每周期切换。粗粒度多线程：仅在高开销事件（如 cache 缺失）时切换，切换要求低，几乎不降低单线程执行速度。速记：擅长计算、不擅长分支（GPU）对应细粒度；擅长分支、通用处理（CPU）对应粗粒度。

> **易错点**：细粒度是"每条指令后切换"，粗粒度是"仅在长延迟事件时切换"，不要记反。

## I/O 接口的作用与内部组成

[01:37:00 - 01:39:00]

主机部件由高速元件构成，外设有自己的时钟与独立时序，二者完全异步，所以需要 I/O 接口（I/O 模块、设备控制器）在中间完成速度匹配、数据格式转换与同步协调。典型 I/O 接口包含数据缓冲寄存器（暂存数据）、状态/控制寄存器（保存状态信息与控制字）、地址译码与 I/O 控制逻辑，以及数据线、地址线、控制线。

> **定义**：I/O 接口 = 连接主机与外设、完成速度匹配与格式/时序转换的逻辑部件。

## I/O 端口与独立编址/统一编址

[01:39:00 - 01:42:00]

I/O 端口就是 I/O 接口中可被 CPU 访问的寄存器：数据缓冲寄存器即数据端口，状态/控制寄存器即状态/控制端口。独立编址：所有 I/O 端口单独编号，形成独立 I/O 地址空间，指令系统须有专门的输入输出指令，load/store 无法访问。统一编址：主存地址空间划出一段给 I/O 端口，二者位于同一地址空间的不同段，按地址范围即可区分，用普通访存指令即可访问，所有主存寻址方式都适用。

> **易错点**：独立编址下无法从地址码形式上区分主存与 I/O，必须靠指令操作码区分。

## 程序查询方式

[01:42:00 - 01:48:00]

程序查询（异步传送）由 CPU 执行 I/O 指令读取接口状态（就绪/忙/完成），据此控制数据交换；组成原理中考查概率不高，操作系统里结合进程状态会考得更深。典型流程：CPU 发启动命令→接口向外设发启动命令→外设把数据送入数据缓冲寄存器→外设回送结束状态→CPU 循环读状态→CPU 读走数据。常用独占式查询：CPU 全程忙等，与外设完全串行，每个数据传送前都必须先读状态。

> **易错点**：程序查询的数据传送由 CPU 执行指令完成（软件），不是硬件自动完成；磁盘扇区传送一般采用 DMA，而非程序查询。

## 中断响应流程与中断向量

[01:48:00 - 01:53:00]

每条指令执行结束后检查中断引脚，若有请求则按中断响应优先级选定一个响应，经中断隐指令进入响应周期。中断向量由中断服务程序入口 PC 与所需 PSW 两部分构成，由硬件判优（编码器给出中断类型号）取得。执行中断服务程序期间若又检测到中断请求，则依据中断嵌套（由屏蔽字决定的处理优先级）决定继续执行还是转去处理新中断。

> **定义**：中断向量 = 中断服务程序入口 PC + 初始 PSW。

## 中断响应时机与响应优先级

[01:53:00 - 01:56:00]

中断请求可在指令执行过程中任意时刻到达，但必须在当前指令执行周期结束后才检查中断引脚并响应；若无线索则继续取下一条指令。响应优先级用于主程序中被多个中断源同时请求时决定先响应谁；处理优先级（由屏蔽字决定）用于服务程序执行期间被新请求时决定是否嵌套。优先级次序：不可屏蔽中断 > 内部异常 > 可屏蔽中断；内部异常中硬件故障 > 软件中断；DMA 请求 > I/O 设备中断请求；I/O 传送类中高速 > 低速、输入 > 输出、实时 > 普通。

> **易错点**：响应优先级解决"主程序先选谁"，处理优先级解决"服务程序是否被打断"，两者不可混用。

## 中断向量表与向量地址

[01:56:00 - 01:58:00]

硬件判优得到中断类型号后，用它查中断向量表：向量地址 = 中断类型号 × 4 + 中断向量表基地址（MIPS 结构下一个向量占 4 字节，故乘 4）。取出向量后，把其中的 PC 送入 PC、PSW 送入状态寄存器，即转入对应中断服务程序。

> **公式**：中断向量地址 = 中断类型号 × 4 + 中断向量表基地址。

## 中断隐指令与中断处理过程

[01:58:00 - 02:00:00]

中断响应由中断隐指令（硬件）完成三步：关中断、保存 PC 与 PSW、引出中断向量。之后进入中断处理：保存现场与屏蔽字→开中断（允许更高优先级中断嵌套）→执行服务程序→关中断、恢复现场与屏蔽字→开中断→中断返回。屏蔽字决定服务程序执行期间哪些中断可被响应。

> **易错点**：通用寄存器由中断处理程序（软件）保存，中断响应阶段只保存 PC 与 PSW。

## 中断嵌套与屏蔽字分析例题

[02:00:00 - 02:03:00]

四个中断源响应优先级 4>3>2>1，由其屏蔽字可推出处理优先级 1>2>3>4，四者同时到达。主程序中先按响应优先级执行 4；4 执行一条指令后，1/2/3 的处理优先级均高于 4、屏蔽不掉，于是在这三者中按响应优先级取 3；3 执行后被 1、2 抢占，按响应优先级取 2；2 又被 1 抢占，执行 1；随后依次返回 2→3→4→主程序。结论：屏蔽后仍剩多个高处理优先级中断时，再用响应优先级决定先后。

> **易错点**：处理优先级只决定"能否打断"，同一层内先响应谁仍由响应优先级决定。

## 中断方式选择题辨析

[02:03:00 - 02:07:00]

中断与指令执行过程无关（键盘可在任意时刻按下），由指令执行过程引起的是异常。主程序中被多个中断同时请求时按响应优先级选，服务程序中被新请求时按处理优先级（屏蔽字）决定是否嵌套。可屏蔽中断必须处于开中断状态才能响应；中断隐指令保存的 PC 是返回主程序的下一条指令地址，不是服务程序地址；中断向量法属于硬件判优；中断向量表存的是各服务程序入口 PC 与 PSW，表地址不等于服务程序地址；通用寄存器在中断处理阶段保存，而非响应阶段。

> **易错点**：中断向量表地址 ≠ 中断服务程序地址；服务程序地址是向量中的 PC 值。

## DMA 方式的概念与三种传送方式

[02:07:00 - 02:13:00]

DMA 由专门的 DMA 控制器控制外设与主存之间直接传送数据，数据不经过 CPU，传送时 CPU 让出总线控制权；适用于磁盘等高速块设备（按扇区成块传送）。三种传送方式：CPU 停止法——DMA 发停止信号使 CPU 脱离总线，整块数据传完才释放；周期挪用——每次只让出一个总线事务周期，传完立即释放，是常考方式；交替分时访问——把一个存取周期分成两个时间片，分别给 CPU 与 DMA。

> **易错点**：周期挪用是"按数据字/总线周期逐次窃取"，CPU 停止法是"整块独占"，不要混淆。

## 2018 年真题①：程序查询的查询间隔与 CPU 占用率

[02:13:00 - 02:19:00]

题设：主频 500MHz、CPI=4，设备 A 速率 2MB/s，I/O 接口数据缓冲寄存器 32 位（4B），每次输入输出约需 10 条指令。设备 A 每秒产生 2MB 数据，需 2M÷4B=500K 次传送，故定时查询间隔为 1/500K=2μs，超过就会丢数。CPU 每秒为 A 花费 500K×10 条×4 周期=20M 个时钟周期，占 500M 周期的 4%。

> **公式**：查询间隔 = 1 ÷ (设备速率 ÷ 缓冲寄存器容量)；CPU 占用率 = 传送次数 × 每次指令数 × CPI ÷ 主频。
> **易错点**：速率单位中的 M=10^6（1MB/s=10^6 B/s），不是 2^20。

> ⚠️ **需回看视频 [02:18:00]**：转写算式残缺、分母不清，正确应为 20M ÷ 500M = 4% —— "它的占比就是200，20M除以4乘以100%"

## 2018 年真题②：中断方式能否承载设备 B

[02:19:00 - 02:21:00]

设备 B 速率 40MB/s，4B 缓冲寄存器对应每秒 40M÷4B=10M 次中断；每次中断响应与处理共 400 个时钟周期，故每秒需 10M×400=4000M=4G 个时钟周期，而 CPU 每秒仅 500M 周期，因此不能采用中断方式。若要支持，主频至少需约 4GHz。

> **公式**：每秒所需时钟周期 = (设备速率 ÷ 缓冲容量) × 每次中断开销。

> ⚠️ **需回看视频 [02:20:00]**：数值口误，4000M 即 40 亿（4G），不是"四千万" —— "至少一秒得有这个四千万个时钟周期"

## 2018 年真题③：DMA 方式下 CPU 的额外开销

[02:21:00 - 02:26:00]

DMA 方式下 CPU 只承担每个数据块的预处理与后处理（共 500 个时钟周期），块内传送由 DMA 硬件完成。设备 B 每秒 40MB，块大小 1000B，故每秒 40MB÷1000B=40K 个块，需 40K 次预处理+后处理，共 40K×500=20M 周期，占 500M 周期的 4%。

> **易错点**：DMA 的 CPU 开销只算预处理与后处理，绝不能把块内每个字节的传送算给 CPU。

> ⚠️ **需回看视频 [02:22:00]**：题干为预处理+后处理共 500 周期，此处却称后处理 400 周期，前后矛盾 —— "还有这个后处理的时间是400的这个时钟周期"

## DMA 块传输综合题：题干与传输速率

[02:26:00 - 02:31:00]

题设：主频 500MHz、CPI=5；磁盘每道 16 个扇区、每扇区 512B，转一圈 8.192ms，忽略寻道等时延；DMA（即磁盘控制器）缓冲器 1B，采用周期挪用，总线宽 8 位，总线事务周期 10ns；所有指令均只含一个总线事务。先求传输速率：每道容量 16×512B=8192B，8192B÷8.192ms=1MB/s（M=10^6）。

> **公式**：磁盘传输速率 = 每道容量 ÷ 旋转一周时间。
> **易错点**：8192B 与 8.192ms 是配套数字，得出的 1MB/s 按 10^6 计。

## 访存冲突量化：CPU 效率降为原来的 99%

[02:31:00 - 02:40:00]

缓冲器 1B、速率 1MB/s → 每秒 1M 次 DMA 请求，即每 1μs 一次，每次占用一个总线事务（10ns）。CPU 500MHz、CPI=5 → 每秒 100M 条指令，即每 10ns 一条，1μs 内可执行 100 条、需 100 次访存；DMA 每 1μs 占用 1 次总线事务，剩 99 次给 CPU，故 CPU 效率降为原来的 99%。

> **公式**：CPU 效率 = (单位时间内原总线事务数 − DMA 占用数) ÷ 原总线事务数。
> **易错点**：本题默认每条指令恰含一个总线事务、且访存时间占满整个指令周期，属理想化模型，不要钻特例。

## DMA 与中断的对比总结及选择题

[02:40:00 - 02:43:00]

DMA 的初始化（预处理）由 CPU 执行程序给控制器赋初值（设备驱动设置传输参数），数据传送完全由硬件完成，结束后由 DMA 控制器向 CPU 发中断，CPU 执行后处理。与中断对比：传送方式上 DMA 由硬件完成、CPU 不参与，中断由 CPU 执行服务程序（软件）；争用对象上 DMA 争总线/访存权，中断争 CPU 处理时间；优先级上 DMA 访存高于 CPU 访存，DMA 结束中断高于外设中断。周期挪用下每准备好一个数据字就请求一次（存储器）总线。

> **易错点**：DMA 并非"全程无中断"，传送结束后仍要发中断让 CPU 做后处理。

## 答疑：响应优先级与处理优先级的配合

[02:43:00 - 02:44:16]

中断嵌套的处理规则可归纳为循环：主程序中被多源同时请求→按响应优先级取最高者；进入服务程序后每执行一条指令再检查，若有新请求则用屏蔽字（处理优先级）判断能否打断；若屏蔽后仍剩多个，再在剩余者中按响应优先级选最高。如此反复，直到全部处理完，再按嵌套层次逐层返回。
