# 计算机组成原理冲刺课 第3讲 补充-25年真题44（1）争议点分析

## 题目背景与争议所在

[00:00:00 - 00:02:00]

2025 年真题第 44 题建立在第 43 题背景上，但真正对 44 题有用的条件只有两个：该机器是 32 位机器；数组 x、d 均定义为 int 类型。题目给出程序 P 的部分机器级代码（图 A）和 M 中补码除法器的逻辑结构（图 B）。争议只出现在第一小问的一个空：执行图 A 中的除法指令时，被除数为 d[i]、除数为 x，补码除法器中的 R、Q、Y 三个寄存器分别存放什么。

> **易错点**：本题按 32 位机器 + int 数组来定各操作数位宽，不要被第 43 题其余条件干扰。

> ⚠️ **需回看视频 [00:00:00]**：ASR 识别残缺，寄存器编号表述不清 —— "其中啊，零到啊四为通用寄存器，好，这个符号它代表符号"

## 补码除法器的寄存器分工

[00:02:00 - 00:03:00]

32 位机中通用寄存器为 32 位，而补码除法需要 64 位被除数 ÷ 32 位除数。因此先把 d[i]（int，32 位）装入 R1，再对其机器数做符号扩展得到 64 位，高 32 位放 R、低 32 位放 Q；除数 x 放入 Y。被除数按符号位扩展没有争议，争议在除数 x 的扩展方式：官方答案在高位补零（0x000000FF），另有答案补全 F（0xFFFFFFFF）。

> **公式**：64 位被除数 = 符号扩展(d[i])，高 32 位→R，低 32 位→Q；除数 x→Y

> **易错点**：R、Q 装的是被除数的高、低半部分，不是商和余数；Y 装的是除数。

## C 语言十六进制常量是"真值"而非机器数

[00:03:00 - 00:07:00]

`d[i] = 0x87654321`、`x = 0xFF` 是 C 语言赋值语句，`0x` 只是进制前缀，常量本身表示一个**真值**，与十进制写 `100` 性质相同，不存在"把位模式直接塞进变量"的含义。默认无前后缀的整数字面量是十进制，写 `0x...` 只是换一种进制表示同一个真值。以 `int test = 0x80000000` 为例：该真值为 2³¹，超出 32 位有符号数范围，发生溢出后成为最小负数 −2³¹；而写成 `-0x80000000` 时真值就是 −2³¹，在表示范围内，不再溢出，结果仍为 −2³¹。

> **定义**：整型字面量（含十六进制形式）表示真值，赋值时按目标类型做转换（必要时溢出/截断）。

> **易错点**：int 与 unsigned int 下"按机器数理解"和"按真值理解"结果恰好相同，所以不能用这两个类型来区分数值含义。

## 用 float 实验反证"真值赋值"

[00:07:00 - 00:10:00]

若把 `0x80000000` 当作机器数位模式赋给 float，则按 IEEE 754 单精度解读是符号位为 1、阶码全 0 的非规格化数，应该是一个极小的小数；但实际输出为 `2147483648.0000`，正是 2³¹ 的浮点表示。这说明过程是"先取真值 2³¹，再把该真值转换为浮点数"，从而证明十六进制常量表达的是真值。老师随后想再跑加负号的对照实验，但编译未成功。

> **定义**：IEEE 754 单精度 = 1 位符号 + 8 位阶码 + 23 位尾数；阶码全 0 且尾数非 0 为非规格化数。

> ⚠️ **需回看视频 [00:07:00]**：把 0x80000000 的位模式当 float 时，实际是 −0.0（阶码、尾数全 0 的零），不是"非常非常小的数" —— "它是一个非规格化数……它就是零，好像是"

> ⚠️ **需回看视频 [00:09:00]**：作为对照的负数 float 实验未编译成功，结论只由正数实验支撑 —— "我如果加个负号，然后编译运行……为什么没编译出来"

## 回到题目：x 的机器数是高位补零

[00:10:00 - 00:12:00]

`d[i] = 0x87654321` 的真值超出 int 正数范围（最高位为 1），赋值时溢出成一个负数，但其 32 位机器数仍是 0x87654321，正好与 Q 中内容一致。`x = 0xFF` 的真值是 255，与符号无关；把它写成 32 位完整形式就是 `0x000000FF`，即高位补零，只是平时书写省略了前导零（如同十进制 100 可写成 0000100）。因此这里的补零不是"零扩展"，而是真值本身写满 32 位。

> **易错点**：`0xFF` 不是"8 位寄存器里的 0xFF"，也不是符号扩展后的 0xFFFFFFFF；前导零被省略不代表符号位为 1。

> ⚠️ **需回看视频 [00:10:00]**：d[i] 溢出后的具体负数值口述含糊、未算出，只能确认机器数不变 —— "溢出结果是一个负的什么什么，对吧？是一个负数"

## 最终答案：R、Q、Y 的取值

[00:12:00 - 00:14:09]

d[i] 作为 R1 的内容送 Q，共 32 位，机器数为 0x87654321，最高位为 1；按符号扩展规则以最高位填充高 32 位，故 R = 0xFFFFFFFF。除数 x 本身就是 32 位，不需要任何扩展，其 int 机器数即 0x000000FF，直接写入 Y。故本题答案：Q = 0x87654321，R = 0xFFFFFFFF，Y = 0x000000FF（均以十六进制表示）。

> **公式**：Q = 0x87654321；R = 0xFFFFFFFF（符号扩展）；Y = 0x000000FF（真值写满 32 位）

> **易错点**：争议空只错在 Y——把它当成"补 F"就会答 0xFFFFFFFF，根因是把十六进制常量误当机器数。
