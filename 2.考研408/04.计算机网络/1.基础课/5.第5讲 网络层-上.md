# 计算机网络基础课 第5讲 网络层-上

## 网络层的地位与总体框架

[00:00:00 - 00:11:00]

网络层是计算机网络中知识点最多、几乎没有冷门考点的一层，基础课只覆盖高频与曾出过大题的部分，其余内容（如组播、SDN）留到强化课。网络层的目的，是在两台远程主机的操作系统之间提供数据传输服务。

网络层可划分为两个层面：数据层面负责在源主机与目的主机之间传送 IP 数据报，并让每个路由器按路由表完成转发；控制层面负责根据网络信息生成路由表。为实现主机间的传输，网络层提供两类功能——路由功能（用 RIP、OSPF、BGP 建立路由表）与 IP 功能。

> **定义**：网络层为两个远程主机的操作系统之间提供数据传输服务；数据层面负责转发，控制层面负责生成路由表。
> **易错点**：网络层"没有冷门"，2024 年 BGP 曾被直接出成 5 分大题，不能按旧经验跳过。

## TCP/IP 与 OSI 体系下网络层的服务对比

[00:11:00 - 00:18:00]

TCP/IP 体系下的以太网提供相邻结点之间、以帧为单位的无差错传输，"无差错"只保证帧不出现比特错；帧丢失或帧失序，链路层不处理。TCP/IP 的网络层则提供源主机到目的主机、以 IP 数据报为单位的尽力交付：不处理数据报丢失与失序，连数据部分的比特错也不处理。

两者的关键区别在差错范围：以太网要求整个帧（含数据、地址、FCS）一位都不能错，网卡收帧时做 CRC 校验，出错即丢弃，正确则去掉链路层首尾后经 DMA 送主存，不再检查数据部分；而网络层只要求 IP 首部正确。OSI 体系则希望网络层以可靠传输（虚电路）为主、兼顾不可靠传输（IPv4/IPv6），但虚电路实际几乎不用。

数据封装与解封装：进程加端口号后交给操作系统，操作系统加 IP 首部，网卡再加 MAC 地址与校验字段发上链路；接收端网卡校验后上交主存，操作系统去 IP 首部，再按端口号分发给进程。

> **易错点**：网络层只校验首部、不校验数据部分；链路层则校验整个帧。端口号属于进程，IP 地址属于主机（操作系统）。

## IPv4 数据报首部格式

[00:18:00 - 00:29:00]

IPv4 首部固定部分为 20 字节，按 4 字节一行排成五行。首部可以超过 20 字节（可选字段 + 填充），但 408 从未考过，未说明时一律按 20 字节处理。

第一行：版本占 4 位（IPv4 为 0100，IPv6 为 0110）；首部长度占 4 位，单位是 4 字节，首部 20 字节时填 5；区分服务不考；总长度占 16 位，单位字节，且包含首部。第二行的标识（16 位）、标志（3 位）、片偏移（13 位）都用于分片，片偏移的单位是 8 字节。

第三行是生存时间、协议与首部校验和：TTL 每经一个路由器转发前减 1，减到 0 即丢弃；协议字段指明上交哪个传输层协议（6 = TCP，17 = UDP）；首部校验和只校验首部，因 TTL 每跳都变，故每个路由器都要重新计算。第四、五行为源 IP 与目的 IP，各 32 位。

> **公式**：总长度 = 首部长度 + 数据部分长度。
> **易错点**：首部长度的单位是 4B（20B 填 5），片偏移的单位是 8B，总长度的单位是 1B。

## IPv4 地址的表示与分类地址

[00:29:00 - 00:35:00]

IPv4 地址长 32 位，约有 43 亿个地址，采用点分十进制书写：把每个字节写成十进制，用点隔开（如 193.32.216.9）。逻辑上地址分为网络号与主机号两部分，早期按网络号固定长度划分为 A、B、C、D、E 五类。

A 类网络号为 8 位、首位固定 0，主机号 24 位；B 类网络号 16 位、前两位固定 10，主机号 16 位；C 类网络号 24 位、前三位固定 110，主机号 8 位；D 类（1110）用于多播，E 类（1111）保留。日常使用的是 A、B、C 三类。

例：某公司分到 C 类网络号 194.2.3，某主机的主机号为 12，则其地址为 194.2.3.12，属于单播地址，只有该主机接收目的地址为它的 IP 数据报。

> **公式**：A 类主机数 2²⁴−2，B 类 2¹⁶−2，C 类 2⁸−2 = 254。
> **易错点**：类别由网络号前几位固定位决定，不是由第一个字节"感觉"决定；D 类不用于普通主机。

## 主机号分配规则与广播地址

[00:35:00 - 00:38:00]

任何一类网络中，主机号全 0 与全 1 都不能分配给主机。主机号全 0 表示网络本身（如 222.15.18.0 代表 222.15.18.0/24 这个网络），主机号全 1 表示该网络的广播地址（如 222.15.18.255）。

目的地址为某网络广播地址的 IP 数据报，会被该网络内所有主机接收；这些主机构成一个广播域。该广播数据报封装成以太网帧时，目的 MAC 地址为全 F（FF-FF-FF-FF-FF-FF）。

> **公式**：可用主机数 = 2^主机号位数 − 2。
> **易错点**：全 0/全 1 主机号不可分配，但它们仍要占两个编码，不能按 2^h 计算可用数。

## 冲突域与广播域的判定（2020 真题）

[00:38:00 - 00:41:00]

冲突域看交换机端口：交换机的每个连接主机的端口各构成一个冲突域；交换机与路由器直接相连的端口不计入冲突域（从真题选项反推，若计入则冲突域至少为 6 个，而选项中没有 6）。

广播域看路由器：路由器每个连接主机的端口一侧整体构成一个广播域，路由器两端属于不同网络号，因此互不广播。该题结论为 4 个冲突域、2 个广播域，选 C。

> **易错点**：交换机—路由器之间那段链路不计冲突域；记住设备性质——集线器既不隔离冲突也不隔离广播，交换机隔离冲突但不隔离广播，路由器两者都隔离。

## 网络号分配限制与特殊 IP 地址

[00:41:00 - 00:52:00]

A 类网络号虽有 8 位，但首位固定 0，只有 7 位可变：网络号全 0 表示"本网络"，全 1 即 127 网段用作本地环回测试，二者均不可指派，故 A 类可指派网络号为 2⁷−2 = 126 个。B 类可指派 2¹⁴ 个网络，C 类可指派 2²¹ 个；早期不指派的 128.0.0.0 与 192.0.0.0 现已可指派。

127.0.0.0/8 整段地址既可作源 IP 也可作目的 IP（作源时会被防火墙拦截、不出网）。广播地址有两种：已知网络号时用主机号全 1 的定向广播；完全不知道链路信息时用 255.255.255.255 受限广播。两者都只能作目的地址，对应目的 MAC 均为全 F。

0.0.0.0 有两种含义：出现在 IP 数据报中只能作源地址，表示本机尚未分配 IP；出现在路由表中表示默认路由，查表无匹配时从该表项对应端口转发。

> **公式**：可指派网络数 A:2⁷−2=126，B:2¹⁴，C:2²¹。
> **易错点**：255.255.255.255 与"主机号全 1"都表示广播，区别在于是否知道目标网络的网络号；0.0.0.0 在报文与路由表中的含义完全不同。

## 特殊地址真题（2017）

[00:52:00 - 01:02:00]

2017 真题问"只能作为源 IP、不能作为目的 IP"的地址：0.0.0.0 符合，选 A。127.0.0.1 既能作源也能作目的（127 网段任意主机号同理）；200.10.10.3 是普通 C 类单播地址，两者皆可；255.255.255.255 只能作目的、不能作源。

> **易错点**：题目问"只能作源"时不要错选环回地址；环回地址两种角色都允许。

## 0.0.0.0 的两种含义与默认路由

[01:02:00 - 01:15:00]

答疑确认：集线器不隔离冲突域与广播域，交换机隔离冲突域但不隔离广播域，路由器两者都隔离。0.0.0.0 究竟表示"本机未分配地址"还是"默认路由"，取决于它出现在 IP 首部还是路由表。

路由表示例：R1 左侧为 193.1.2.0/24、右侧为 193.1.3.0/24、上方经 194.1.1.0/24 连接 R2。目的地址 193.1.3.3 命中右侧表项，直接转发；目的地址 200.0.3.4 在表中无对应网络，则交给 0.0.0.0 表项（默认路由）送往互联网方向。

0.0.0.0 表项在路由表初始生成时就已存在，指向通往外部网络/互联网的接口；题目要求写路由表时，看哪个端口标注"通往互联网/外部网络"，就把 0.0.0.0 指向它。

> **易错点**：路由表中的 0.0.0.0 不是源 IP 也不是目的 IP，只是"查不到就发这里"的兜底表项。

## CIDR 无分类编址与斜线记法

[01:15:00 - 01:21:00]

分类地址的固定网络号长度造成严重浪费：A 类可容纳约 1677 万台主机，没有单位用得上；C 类只有 254 个地址，稍大的单位就得申请 B 类，大量地址闲置。CIDR（无分类编址）把"网络号"改称"网络前缀"，长度 n 不再固定（0～32，常用 1～30），主机号为 32−n 位，从而按实际需求分配。

CIDR 不再区分 A、B、C 类，采用斜线记法：在 IP 地址后加 `/n`，表示前 n 位是网络前缀。例如公司约 400 台主机可申请 /23（9 位主机号），约 20 台主机申请 /27 即可。

> **公式**：CIDR 地址块主机数 = 2^(32−n)，可用数 = 2^(32−n) − 2。
> **易错点**：CIDR 下不存在"这是 A 类还是 C 类"的判断，类别概念已被前缀长度取代。

## CIDR 地址块与最大/最小地址

[01:21:00 - 01:29:00]

网络前缀相同的所有连续 IP 地址组成一个 CIDR 地址块；知道块内任一地址，就能推出整块的起止地址。最小地址 = 前缀不变、主机号全 0；最大地址 = 前缀不变、主机号全 1。

例：128.14.35.7/20 的前 20 位为前缀，地址块为 128.14.32.0/20，最小地址 128.14.32.0，最大地址（广播地址）128.14.47.255，可分配 2¹²−2 个。128.14.35.7 与 128.14.35.9 前缀相同，同属该块、同一广播域。

CIDR 继承了主机号全 0/全 1 的含义：全 0 代表该网络前缀，全 1 代表该前缀的广播地址，二者仍不可分配。

> **公式**：地址数 = 2^(32−n)；可分配数 = 2^(32−n) − 2。
> **易错点**：广播地址的主机号是全 1，不是"最大可分配地址"；/20 的块边界落在第三个字节的低 4 位上，不要按字节边界算。

## 地址掩码（子网掩码）

[01:29:00 - 01:35:00]

计算机无法解析斜线记法，因此用 32 位地址掩码：前面连续 n 个 1、后面连续 32−n 个 0，1 的个数即网络前缀长度。用掩码与 IP 地址逐位相与，即得网络地址。

/20 的掩码为 255.255.240.0，/24 为 255.255.255.0，/25 为 255.255.255.128，/27 为 255.255.255.224。分类地址的默认掩码为 A:255.0.0.0、B:255.255.0.0、C:255.255.255.0。

> **公式**：网络地址 = IP 地址 AND 地址掩码。
> **易错点**：掩码中的 1 必须连续，不能出现 255.0.255.0 这类形式。

## CIDR 记法的使用限制与路由表结构

[01:35:00 - 01:39:00]

CIDR 记法不能出现在 IP 数据报的源/目的地址字段：首部格式固定、没有掩码字段，无法容纳 `/n`；报文中的地址一定特指某一台主机。考试中 CIDR 记法可以出现在路由表表项里（真题已出现过）。

路由表表项包含四个字段：地址块（目的网络）、地址掩码、下一跳、端口。下一跳是到达该地址块需要先经过的相邻路由器接口 IP。

> **易错点**：斜线记法只属于"地址块"语境，写进 IP 首部的源/目的地址就是错的。

## 子网划分的必要性与等长划分方法

[01:39:00 - 01:46:00]

例：公司有 240 台主机，申请 193.1.2.0/24。若平均分成 8 个部门，某部门主管发广播只能写 193.1.2.255，结果全公司 240 台都收到，无法实现部门间隔离，因此需要子网划分，让每个子网成为独立广播域。

子网划分在网络前缀不变的前提下，把原主机号再分为"子网号 + 主机号"；子网前缀长度 = 原前缀长度 + 子网号长度。等长划分时，分 2^k 个子网就从主机号借 k 位：/24 分 8 个子网借 3 位，子网前缀变为 /27，主机号剩 5 位。

每个子网内仍遵守：主机号全 0 表示该子网，全 1 表示该子网的广播地址。

> **公式**：/n 等分为 2^k 个子网 → 子网前缀 /(n+k)，每子网可用 2^(32−n−k) − 2 个地址。
> **易错点**：子网号必须互不重复；划分子网不改变对外看到的原网络前缀。

## 多级子网划分实例与子网掩码

[01:46:00 - 01:56:00]

以 193.1.2.0/24 为例：先分两个二级部门，借 1 位，得到 193.1.2.0/25 与 193.1.2.128/25。每个二级部门再分 4 个三级部门，再借 2 位，前缀变 /27：第一个部门得到 .0、.32、.64、.96 四个 /27；第二个部门得到 .128、.160、.192、.224 四个 /27。

路由器向外只需通告聚合后的前缀：R1 的路由表包含三个三级子网的具体表项、一个指向另一二级部门的 193.1.2.128/25 表项，其余全部走 0.0.0.0。

> **易错点**：多级划分时子网前缀逐级累加（24 → 25 → 27），不是每级都从原 /24 重新借位。

## 子网的广播域、直接交付与默认网关

[01:56:00 - 02:16:00]

每个子网是独立广播域。193.1.2.95（/27 下主机号全 1）是 193.1.2.64/27 的广播地址，只有该子网主机收到；193.1.2.96/27 内的主机收不到，因为属于不同广播域。

同一广播域内为直接交付：以太网帧的目的 MAC 直接写对方主机 MAC，中间交换机不改变这一点。不同广播域为间接交付：源/目的 IP 仍是两端主机，但帧的目的 MAC 要写本子网默认网关（路由器接口）的 MAC，由网关代为转发。

默认网关就是子网所连路由器端口的 IP。练习：21.3.0.0/16 划分为 128 个子网，借 7 位，主机号剩 9 位，每个子网可分配 2⁹−2 = 510 个地址。

> **定义**：默认网关 = 该子网所连接的路由器接口的 IP 地址。
> **易错点**：跨子网发送时目的 MAC 是网关的 MAC，不是最终目的主机的 MAC；目的 IP 始终不变。

## CIDR 的底层存储与相关答疑

[02:16:00 - 02:22:00]

计算机内部把 CIDR 地址按 8 字节保存：前 4 字节存 IP 地址，后 4 字节存地址掩码；写入路由表时，地址字段存与掩码相与后的网络地址，掩码存掩码字段。这就是"斜线记法不进入报文、却能在路由表中起作用"的原因。

路由器与 VLAN 交换机在划分子网的功能上等价。一个 IP 可以同时落在多个地址块中（如 128.1.2.1 同时属于 128.1.2.0/24 与 128.1.2.0/25），由最长前缀匹配决定走向；但不会出现一个 IP 对应两个子网。是否划分子网，只看路由表中的地址掩码。

> **易错点**：同一 IP 可匹配多个地址块，但最终只按最长前缀选中一个。

## 非平均子网划分（哈夫曼编码/前缀码）

[02:22:00 - 02:34:00]

各部门主机数不同，等长划分会浪费地址，实际多用非平均划分。其硬性要求是子网号互不重复；保证不重复的方法就是前缀码：需要 k 个子网就构造 k 个叶子的哈夫曼树，左 0 右 1，每个叶子的编码即一个子网号。

2019 真题：101.200.16.0/20 划分 5 个子网，编码取 0、10、110、1110、1111，对应主机号 11、10、9、8、8 位，最小子网可分配 2⁸−2 = 254 个地址。若按等长划分会得到不同（错误）结果，因为题目并未说"平均"。

A～E 类地址的前导固定位（0、10、110、1110、1111）本质上就是同一套前缀码，可对照记忆。

> **公式**：叶子编码长度 = 从原主机号中借用的位数；子网可用地址数 = 2^(剩余主机位) − 2。
> **易错点**：题目说"划分为 5 个子网"而非"平均划分"时，必须用前缀码构造，不能按 3 位等长切分。

## 2021 真题：由已知子网反推划分

[02:34:00 - 02:43:00]

题目只给出其中一个子网 192.168.9.128/26，问 A～D 中不可能是另外两个子网的是哪一个。第一步是反推父地址块：与已知子网及选项前缀一致的块只有两种可能——192.168.9.0/24 或 192.168.9.128/25。

按 3 个子网构造 3 叶前缀码（0、10、11）逐一代入。若父块为 /24：0 → 192.168.9.0/25（A），10 → 192.168.9.128/26（已知），11 → 192.168.9.192/26（C）。若父块为 /25：0 → 192.168.9.128/26（已知），10 → 192.168.9.192/27（D），11 → 192.168.9.224/27。

两种可能都无法得到 192.168.9.0/26（B），故答案为 B。

> **易错点**：父地址块未给出时，必须先找出所有可能父块再逐一验证，不能默认从 /24 划分。

## 路由聚合与最长前缀匹配

[02:43:00 - 02:55:00]

路由表存储空间有限，路由器会把同一方向、前缀连续的多个小子网合并成一个表项，即路由聚合（构造超网）。做法是把各子网地址写成二进制，取最长的公共前缀，公共前缀长度就是聚合后的前缀长度。

例：193.1.2.0/27、.32/27、.64/27、.96/27 的前 25 位相同，聚合为 193.1.2.0/25；.128、.160、.192、.224 四个 /27 聚合为 193.1.2.128/25。

转发时，用每个表项的掩码与目的 IP 相与，得到候选网络地址，凡匹配者中取前缀最长的一个：前缀越长，地址块越小，路由越具体。

> **定义**：最长前缀匹配——查表得到多个匹配结果时，选择网络前缀最长的那条路由。
> **易错点**：聚合后的前缀一定比原来短，且覆盖范围必须正好等于被聚合子网之并，不能顺带覆盖无关地址。

## 真题：路由聚合与最长前缀匹配

[02:55:00 - 03:03:00]

2018 真题：35.230.32.0/21、35.230.40.0/21、35.230.48.0/21、35.230.56.0/21 四个表项下一跳相同，聚合后为 35.230.32.0/19——第三字节 32/40/48/56 的前 3 位同为 001，从第 4 位开始变化，故前缀为 16+3=19 位。

最长前缀匹配真题：目的地址 169.96.40.5，表中 /23、/25、/27 均可匹配，取最长的 /27 对应接口（选 C）；若三条都不匹配才走 0.0.0.0 表项。

/30 子网 192.168.4.0/30 中，目的地址 192.168.4.3 是该子网的广播地址，能收到它的主机只有主机号为 01、10 的两台，即可分配主机数为 2（选 C）。

> **公式**：/30 子网可用主机数 = 2²−2 = 2。
> **易错点**：广播地址"所有主机都能收到"指的是子网内全部可分配主机，不等于地址总数 4。

## DHCP 协议与四步交互

[03:03:00 - 03:18:00]

DHCP 的作用是为主机分配 IP 地址；如今 DHCP 服务器通常集成在家用路由器中。分配方式分静态（管理员手工绑定，了解即可）与自动（首次租用后长期使用，考试重点）。

交互四步：① 客户机广播 DHCP Discover 寻找服务器；② 服务器广播 DHCP Offer，携带可提供的 IP；③ 客户机选定一个 Offer 后广播 DHCP Request；④ 被选中的服务器广播 DHCP ACK，正式分配地址。

地址规律：Discover 源 0.0.0.0、目的 255.255.255.255；Offer 源为 DHCP 服务器 IP、目的 255.255.255.255；Request 源 0.0.0.0、目的 255.255.255.255；ACK 源为服务器 IP、目的 255.255.255.255。

> **公式**：Discover/Request 源 IP = 0.0.0.0；四步的目的 IP 均为 255.255.255.255。
> **易错点**：Request 阶段客户机尚未获得地址，源 IP 仍是 0.0.0.0，目的仍是全 1 广播；这是协议规定，不要"讲道理"改成服务器单播地址。

## DHCP 报文地址与 2015 真题

[03:18:00 - 03:22:00]

DHCP ACK 除分配 IP 外还下发：子网掩码、子网地址（网络号）、默认网关 IP、DNS 服务器 IP，使主机一联网就掌握本子网全部配置。网关、默认网关、默认路由 IP 三者都指路由器连接该子网的接口地址。

2015 真题：111.123.15.0/24 中路由器接口、DHCP 服务器、Web 服务器与主机一已静态占用 .1～.4，故可动态分配范围为 111.123.15.5 ～ 111.123.15.254；主机二发送的 Discover 报文源地址 0.0.0.0、目的地址 255.255.255.255。

> **易错点**：地址池要扣除已静态占用的地址，以及网络地址（全 0）和广播地址（全 1）。

## IP 数据报分片：MTU 与分片发生位置

[03:22:00 - 03:29:00]

MTU（最大传送单元）是链路层帧数据部分能承载的最大字节数；以太网 MTU = 1500，因此 IP 数据报总长最多 1500 字节，数据部分最多 1480 字节（20 字节首部）。

主机发送前会由传输层限制报文大小，尽量把 IP 数据报控制在 MTU 内，避免刚发出就分片；分片主要由路由器在转发时执行。当路由器从 MTU 1500 的链路收到 1500 字节数据报，而要转发到 MTU 500 的链路时，必须分片。

> **定义**：MTU = 链路层帧数据部分可承载的最大数据量；以太网 MTU = 1500B。
> **公式**：无选项字段时，IP 数据部分上限 = MTU − 20。

## 分片字段（标识、DF/MF、片偏移）与重组

[03:29:00 - 03:39:00]

同一数据报的所有分片，源 IP、目的 IP、标识字段完全相同；总长度、标志、片偏移各不相同。MF = 1 表示后面还有分片，MF = 0 表示最后一片；DF = 0 允许分片，DF = 1 且长度超过 MTU 时路由器直接丢弃并回报差错。

片偏移表示该分片首字节在原数据报中的位置除以 8（单位 8 字节）。1500 字节数据报（数据 1480B）转到 MTU 500：前三片各 480B、最后一片 40B，片偏移依次为 0、60、120、180，MF 依次为 1、1、1、0。

除最后一片外，各片数据部分必须是 8 的整数倍；重组只在目的主机进行，路由器只负责转发分片。接收方按标识归类、按片偏移拼接，一旦发现空洞（缺片）就丢弃全部已收分片。

> **公式**：片偏移 = 该片首字节序号 ÷ 8；分片数据部分 = MTU − 20（取 8 的倍数）。
> **易错点**：路由器不重组；缺少任一分片则整组丢弃，重传由传输层完成。

## 分片后首部字段变化与 2021 真题

[03:39:00 - 03:45:00]

分片后可能变化的字段有五个：总长度、TTL（每经路由器减 1）、首部校验和（任何首部比特变化都要重算）、标志（MF）、片偏移。标识、源 IP、目的 IP 保持不变。

2021 真题：1580 字节数据报（首部 20B、数据 1560B）转发到 MTU 800。每片数据最大 780B，但须为 8 的倍数，故取 776B，分片总长 776+20 = 796B；数据被切成 776 + 776 + 8 三片，第二片总长 796、MF = 1，选 B。

> **易错点**：不能直接把 780 当分片数据长度，必须向下取 8 的倍数；第二片不是最后一片，MF 为 1。

## ICMP 差错报告报文与封装

[03:45:00 - 03:51:00]

ICMP 用于路由器或主机向源点报告差错与异常，缩短源主机发现差错的时间。差错报告共五种：终点不可达（无法交付）、源点抑制（拥塞丢弃）、时间超过（TTL 减为 0 或分片重组超时）、参数问题（首部字段有误）、改变路由/重定向（提示改走另一路由器）。

以下情形不再发送 ICMP 差错报文：对 ICMP 差错报文本身、对非第一片的分片、对组播地址、对特殊地址（127 网段、源地址 0.0.0.0）。

ICMP 报文封装在 IP 数据报中，IPv4 首部协议字段为 1。2012 真题"直接为 ICMP 提供服务的协议"答案是 IP；2010 真题因拥塞丢弃分组应发源点抑制报文。

> **易错点**：协议字段 1 = ICMP、6 = TCP、17 = UDP；ICMP 差错报文本身出错时不再产生新的 ICMP 差错报文。

## 答疑：网关、分片丢弃与校验和分工

[03:51:00 - 04:03:20]

多台主机同时请求 DHCP 时，服务器按内部机制依次处理，考试不涉及。网关严格说是路由器连接该子网的接口 IP；IGMP 属组播内容，强化课再讲。

分片重组失败的完整链条：接收方按标识把分片归类，按片偏移拼接，发现中间缺片即丢弃全部已收分片，并向源主机发送"时间超过"报文；真正的重传由传输层（如 TCP）超时重传完成，网络层不负责。

网络层只校验首部、传输层校验数据，是为了让路由器转发更快：路由器是网络层设备，本不应处理传输层内容，只校验 20 字节首部即可转发；数据部分由接收方传输层校验，丢失也由传输层发起重传。

> **易错点**：分片的重组（目的主机）与重传（传输层）都不在网络层完成，别把"尽力交付"理解成"网络层保证可靠"。
