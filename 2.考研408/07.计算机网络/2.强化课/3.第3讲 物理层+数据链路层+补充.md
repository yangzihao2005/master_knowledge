# 计算机网络强化课 第3讲 物理层+数据链路层+补充

## 近年真题分布与命题趋势

[00:00:00 - 00:06:00]

2020—2025 年大题主体基本在"链路层 / 网络层 / 传输层+应用层"三者间轮换：2020 网络层、2021 应用层+链路层、2022 链路层、2023 传输层+应用层（FTP 配 TCP）、2024 网络层（路由表建立、OSPF/BGP）、2025 链路层。按"相邻年份不重复"的经验，今年大概率落在传输层+应用层模型上，因此本讲第二个大题模型选了 FTP。物理层本身内容少，本讲以链路层与补充知识为主。

> ⚠️ **需回看视频 [00:04:00]**：年份与"主体层次"的对应前后矛盾，前文说"二三年考察传输层加应用层""二四年网络层、二五年链路层"，后文又说"二三考了网络层，二四考了链路层"，无法确定哪套说法为准 —— "二三年考察的是我们的传输层加应用层的内容……二三考了网络层，二二，二四考了链路层啊"

## FTP 的两类连接与主动模式（PORT）

[00:06:00 - 00:12:00]

FTP 并行使用两条 TCP 连接：控制连接由服务器 21 端口监听、客户机随机端口发起，传输用户标识、口令、改变远程目录、put/get 等命令，采用 7 位 ASCII 编码，只传命令不传文件数据；数据连接只用于传文件，每传完一个文件就断开，下一个文件重新建立。控制进程与数据进程是两个独立进程。数据连接的建立方式采用谢希仁教材唯一介绍的主动模式（PORT）：客户机随机开放一个端口并用 PORT 命令告知服务器，服务器再用 20 端口向该端口发起连接，上传与下载都是这样。

> **定义**：PORT（主动）模式——客户机在控制连接上告知自己激活的 IP 与端口，由服务器 20 端口主动向客户机发起数据连接
> **易错点**：数据连接永远由**服务器**发起，方向是"服务器 20 → 客户机激活端口"；21 端口跑控制、20 端口跑数据，两者不能互换

## FTP 一次完整下载流程

[00:12:00 - 00:23:00]

以客户机 192.168.70.130 从 192.168.70.131 下载文件 A、B 为例：① 输入 `ftp 192.168.70.131`，客户机端口向服务器 21 端口三次握手建立控制连接；② 在控制连接上发用户名、口令登录；③ 用 `get`/`RETR` 请求文件 A，并用 PORT 命令告知激活端口；④ 双方在控制连接上同步状态信息；⑤ 服务器 20 端口向客户机激活端口三次握手，建立数据连接；⑥ 20 端口传数据，传完释放数据连接；⑦ 文件 B 重复 ③—⑥，端口要重新告知、数据连接重新建立；⑧ 输入 `exit` 退出。

> **易错点**：断开方向遵循"谁发数据谁先挥手"——下载时由服务器发起四次挥手的第一次，上传时由客户机发起；而控制连接虽由客户机发出 exit，却仍由**服务器**发起第一次挥手

## 抓包实证：登录阶段（控制连接）

[00:23:00 - 00:31:00]

第 1—3 条是三次握手（130:49532 → 131:21），第 4 条服务器回 220 表示服务就绪，第 5 条客户机 ACK（len=0）。第 6—12 条完成登录：USER 01user → ACK → 331 要求输入密码 → ACK → PASS → ACK → 230 登录成功。第 12—20 条是状态信息同步（16 条告知服务器为 Unix 系统、20 条告知用二进制方式 TYPE I），这些同步报文仍走 21 端口控制连接，考试不考具体内容。

> **易错点**：判断一条报文属于哪条连接，只看端口——源/目的端口含 21 就是控制连接，含 20 才是数据连接

## 抓包实证：PORT 命令与数据连接的建立

[00:31:00 - 00:43:00]

`get file a.txt` 对应第 22 条报文：仍是客户机 → 服务器 21 端口，载荷为 `PORT 192,168,70,130,168,145`，即 IP 加"端口高字节、低字节"（168×256+145=43153），服务器据此知道客户机激活了 43153 端口。第 23 条回 200 PORT command successful，第 25 条 RETR 开始传送，第 26—28 条由服务器 20 端口向 43153 三次握手建立数据连接，第 30—32 条传输数据。传完由服务器发起第 33—36 条四次挥手，第 37 条在 21 端口回 226 告知传输完成。

> **易错点**：数据连接上只跑数据，所有状态码、指令、完成通知（150/226）都在控制连接上；PORT 命令的端口字段是"高字节,低字节"两段，需要乘 256 再相加

> ⚠️ **需回看视频 [00:33:00]**：客户机端口数值前后不一致（先举例 5421/54321，抓包中为 43153），PORT 命令里的 IP 与端口写法也被转写成"192.168.70.130.168.145"，需核对原板书写法 —— "port 192.168.70.130.168.145……激活的端口是43153"

## 抓包实证：第二个文件与退出控制连接

[00:43:00 - 00:48:00]

下载文件 B 与文件 A 完全同构：第 39 条新的 PORT（激活端口换成 40785），第 40 条 200，第 42 条 RETR file b，第 43—45 条服务器 20 端口重建数据连接，第 47—48 条传数据，第 50—53 条服务器发起四次挥手，第 54 条 226 完成。第 56 条客户机发 exit，第 57 条回 221 Goodbye，第 58—61 条才断开控制连接。

> **易错点**：两次下载各自有独立的 PORT 命令、独立的激活端口和独立的数据连接；控制连接全程只有一条，直到 exit 才释放

## FTP 真题辨析（2017 选择）

[00:48:00 - 01:00:00]

题目问"关于 FTP 的叙述错误的是"：A 数据连接每次传完即关闭——正确，file A 传完就断开、下载 file B 再新建；B 控制连接在整个会话期间保持打开——正确，只有 exit 后才由服务器发起断开；C "服务器与客户端的 20 号端口建立数据连接"——错误，20 端口在服务器一侧；D 客户端与服务器 21 端口建立控制连接——正确。

> **易错点**：C 的陷阱是把 20 端口挪到了客户端一侧，看到"客户端 20 号端口"就要判错

> ⚠️ **需回看视频 [00:38:00]**：讲解数据连接端口时多次说成"服务器的 22 号端口"，与 20 端口矛盾，疑为口误 —— "是由131的22号端口，向客户机的192.168.70.130的这个43153这个端口"

## 持久连接、流水线与拥塞窗口（真题答疑）

[01:00:00 - 01:10:00]

2023 真题所谓"流水线"其实只是把**一个**资源分成多个段传输，真正起作用的仍是 TCP 拥塞窗口随轮次增长。408 的固定套路是：请求**一个**资源时，该资源通常有多个 MSS（如 8 个）；在同一持久连接上请求**多个**资源时，每个资源固定 1 个 MSS。这样一来，"8 个资源各 1 MSS"与"1 个资源共 8 MSS"在流水线方式下答案完全一致，因为都受同一条 TCP 连接的拥塞窗口（初值 1 MSS，随 ACK 倍增）约束，同时发出多个请求并不能在一个 RTT 内收回全部数据。只有当每个资源各自单独建 TCP 连接时，才能并行、答案才会不同。

> **易错点**：不要因为"同时发出了 8 个请求"就认为一个 RTT 能收到 8 个 MSS；瓶颈是这条 TCP 的拥塞窗口，不是请求的个数

## 物理层考情与知识框架

[01:10:00 - 01:14:00]

物理层的目的是让信号通过编码或调制在信道上传输，功能是完成信号的转换（数字↔模拟）。近五年物理层考得少，出新型题最可能落在"编码与调制"，因为往年这块只考概念；而奈氏准则与香农定理的计算考法固定，练熟真题即可。转换共四种，408 只涉及三种：数字→数字、数字→模拟、模拟→数字，模拟→模拟属通信原理，不考。学习重点不是背公式，而是掌握每种转换**在什么时刻、什么设备上发生**，以及随之用哪条公式。

> **易错点**：物理层的"新题"往往不考公式，而考"这一步转换发生在网卡还是光猫/路由器"

## 数字信号 → 数字信号（编码）

[01:14:00 - 01:18:00]

发生在**网卡**内部：内存中的 IP 数据报经 DMA 送到网卡，网卡封装成以太网帧，再把帧转换成曼彻斯特编码这种另一种格式的数字信号发到链路上。因此"数→数"就是同一种链路上两种数字信号格式之间的转换，由网卡完成。考法通常是给出曼彻斯特编码波形让判断发送的比特序列（或反向画波形）。

> **定义**：编码——把一种数字信号格式转换为另一种数字信号格式，以太网使用曼彻斯特编码

## 数字信号 → 模拟信号（调制）

[01:18:00 - 01:26:00]

发生在**内置光猫功能的路由器**上：主机以曼彻斯特编码经网线送到路由器，路由器把数字信号调制成光这种模拟信号，送入光纤到用户分光箱。四种调制方式：ASK 改变载波振幅、FSK 改变载波频率（需要两个不同频率的载波）、PSK 改变载波相位、QAM 把 ASK 与 PSK 叠加。2024 真题就考了"需要两个不同频率载波的是"，答案为 FSK——说明不要只准备 QAM 计算，前三种的定义也要记。

> **公式**：QAM 数据传输速率 R = B·log₂(M·N)，其中 M 为相位数、N 为振幅数、B 为波特率

> **易错点**：ASK 用两个振幅、PSK 用两个相位、FSK 用两个频率，三者只需"一个载波 vs 两个载波"的区分，别混

## QAM 方案与奈氏、香农的联合计算

[01:26:00 - 01:31:00]

题目给"信噪比 30 dB、QAM 调制、速率不低于香农极限"，求 QAM 阶数。先由 30 dB 得 S/N=1000，香农极限为 W·log₂(1+1000)≈10W；奈氏上限为 2W·log₂(M·N)。令 10W ≤ 2W·log₂(M·N)，约去未知的 W，得 log₂(M·N) ≥ 5，即 M·N ≥ 32，故采用 QAM32。

> **公式**：香农 C = W·log₂(1+S/N)；奈氏 C = 2W·log₂V（V 为码元状态数）；dB 换算 10·lg(S/N)=30 → S/N=1000；波特率 B = 2W

> **易错点**：香农给的是**上限**，用来反推 QAM 的状态数；W 未给出不代表算不出，两边约掉即可

## 模拟信号 → 数字信号（解调）

[01:31:00 - 01:34:00]

发生在接收方向的同一个内置光猫路由器上：它从光纤收到模拟光信号，按采样定理采样后还原成曼彻斯特编码的数字信号，再经网线送到主机网卡。判据是采样频率必须不小于原始信号最高频率的两倍，否则无法完整保留原信号信息。模拟→模拟的转换属通信原理，计算机网络不考。

> **公式**：采样定理 f_s ≥ 2f_max

> **易错点**：发送方向（网线→光纤）是"数→模"，接收方向（光纤→网线）才是"模→数"，同一台光猫两个方向各做一种转换

## 互联设备两端"是否必须一致"

[01:34:00 - 01:38:00]

路由器连接两个子网时，两侧的链路层协议可以不同，速率也可以不同；交换机连接两个冲突域时，存储转发式允许不同，直通式则协议与速率都必须一致；集线器等物理层设备两端必须完全一致。根本判据是设备**有没有存储能力**：能缓存再转发就能做协议与速率转换，只是速率不匹配时缓存会被灌满而丢包。理论上只要具备存储就能异构互联，实际会因快进慢出而丢数据。

> **易错点**：记"物理层设备一律两端一致；有存储的转发设备才允许不一致"，直通式交换机没有存储，所以要和物理层设备同样处理

## 虚电路的概念与组成

[01:38:00 - 01:42:00]

OSI 体系下网络层同时提供有连接服务（虚电路网络）与无连接服务（数据报网络），而 TCP/IP 体系只有无连接的数据报服务，所以虚电路在现实中基本见不到，概念显得别扭。一条虚电路由三部分组成：源到目的的路径、沿路径每段链路的 VC 号（有方向）、以及沿途每个路由器的虚电路转发表（入接口、入 VC 号、出接口、出 VC 号四个表项）。属于同一虚电路的分组首部不携带目的地址，只携带 VC 号。

> **易错点**：目的 IP 只在**建立阶段**使用，数据传输阶段头部只有 VC 号；虚电路不预分配带宽

## 虚电路的转发过程

[01:42:00 - 01:48:00]

以 A→R1→R2→B 为例：A 发出的分组头 VC=12，R1 查表发现"入接口 1、入 VC 12"对应"出接口 2、出 VC 22"，于是改写 VC 号从 2 号口转发；R2 同理把 22 改成 32 再从 2 号口送出，主机 B 接收。分组内容不变，只有 VC 号逐段被替换。同一路由器可以从同一个入接口收到不同 VC 号的分组，据此分流到不同出接口。

> **易错点**：转发表是建立连接时一次性写入的四元组，转发时只做"查表 + 换号"，不做路由选择

## 虚电路的建立、拆除与 VC 号分配规则

[01:48:00 - 01:54:00]

建立阶段需给出接收方 IP，网络层选路后为沿途每条链路的每台路由器分配 VC 号并添加表项；拆除阶段通知对端"结束呼叫"，虚电路随即失效。VC 号有两条独立性质：一是**有方向**，A→R1 与 R1→A 不能同号；二是**每条路径独立分配**，A→B 用过 R1–R2 段的 VC=22 后，A→C 走同一段链路时必须重新分配（如 VC=100）。因此 R2 从 1 号口收到 VC=22 就转 2 号口（去 B），收到 VC=100 就转 3 号口（去 C）。

> **易错点**：新路径不能复用旧路径在同一段链路上的 VC 号，哪怕入接口、出接口都相同

## 虚电路与数据报服务的对比（2020 真题）

[01:54:00 - 02:06:00]

对比维度：① 连接——数据报无需建立连接，虚电路必须先建立；② 地址——数据报每个分组都带完整源/目的 IP，虚电路只在建立阶段带地址，之后用 VC 号；③ 路由选择——数据报每个分组独立选路，虚电路所有分组走同一路径；④ 顺序——数据报不保证按序，虚电路保证按序；⑤ 可靠性——数据报由主机负责，虚电路只要网络本身不断就可靠。2020 真题的错误项是"需要为每条虚电路预分配带宽"，虚电路并不预留带宽。

> **易错点**：虚电路的"可靠"是网络不断即按序到达，不等于预留资源；"预分配带宽"是典型干扰项

## CSMA/CD 与 CSMA/CA 的核心差别

[02:08:00 - 02:17:00]

以太网帧不含确认，发送方无法靠 ACK 判断是否冲突，于是规定"帧的传输时延 ≥ 2 倍传播时延"：只要在整个发送期间一直监听接入点，若听到别的帧就必然已在某处碰撞，立即停发并转退避重传；全程听不到则可断定无冲突。CSMA/CA 用于无线，信号衰减受障碍与噪声影响、传播距离不可预知，无法边发边听，还存在隐蔽站问题，所以只能"尽量避免"冲突而不能检测：一旦中途被撞，它仍会把整帧发完，浪费信道。

> **公式**：CSMA/CD 最短帧约束 L_min / C ≥ 2τ（τ 为单程传播时延）

> **易错点**：CA 不做冲突检测、也不会因冲突中途停发，这是它与 CD 最本质的差别

## 802.11 的四种帧与 RTS/CTS 字段

[02:17:00 - 02:20:00]

CSMA/CA 交互中只有四种帧：RTS、CTS、DATA、ACK。地址 1—4、去往 AP、来自 AP 等字段**只存在于 DATA 帧**；RTS 帧共 20 字节，只有 6 字节接收地址、6 字节发送地址和持续期（即 NAV），帧控制字段不必细究。CTS 与 ACK 的格式同理，只要抓住"地址四段只在 data 帧"。

> **易错点**：看到"地址 1/2/3/4、去往 AP"就要限定在 802.11 的 data 帧上，RTS/CTS/ACK 都没有

## 隐蔽站问题与 NAV 的作用

[02:20:00 - 02:26:00]

A 想发数据时先等一个 DIFS，若信道仍空闲才发 RTS；RTS 以广播范围传播，范围内的 B 与 C 都能收到。C 从 RTS 的接收地址看出这不是发给自己的，但可据其中的持续期设置自己的 NAV，在这段时间内保持静默。B 回 CTS 后，能收到 CTS 却收不到 RTS 的 D（A 的隐蔽站）同样据 CTS 的持续期静默，从而把隐蔽站也纳入退避。DATA 帧也带持续期，供既没收到 RTS 也没收到 CTS 的站点（如障碍物消失后出现的 E）设置 NAV。

> **定义**：NAV（网络分配向量）——由帧的持续期字段给出的"信道还将被占用多久"，其他站点据此推迟接入

> **易错点**：RTS 保护的是发送方周围，CTS 保护的是接收方周围；隐蔽站靠 CTS 才被约束

## NAV 的计算公式

[02:26:00 - 02:31:00]

收到 RTS 的站点按 RTS 的持续期设 NAV，其值为 SIFS + CTS 传输时间 + SIFS + DATA 传输时间 + SIFS + ACK 传输时间；收到 CTS 的站点则少了最前面的 CTS 一项，为 SIFS + DATA + SIFS + ACK；收到 DATA 的站点为 DATA 传输时间 + SIFS + ACK 传输时间。三个 SIFS 分别对应 RTS、CTS、DATA 的校验与帧间间隔，真题通常额外给"所有 SIFS 等长"这一条件以简化计算。

> **公式**：NAV_RTS = SIFS + T_CTS + SIFS + T_DATA + SIFS + T_ACK；NAV_CTS = SIFS + T_DATA + SIFS + T_ACK；NAV_DATA = T_DATA + SIFS + T_ACK

> **易错点**：DATA 帧的 NAV 里仍要算它自己的传输时间；公式起点由"收到哪一种帧"决定

## DIFS 与 SIFS 的关系

[02:31:00 - 02:35:00]

想发数据的站点必须先等一个 DIFS，且 DIFS 内信道始终空闲才能发 RTS。DIFS 被设计得比任何 SIFS 都长，是为了让正在交互的站点优先：对方可能正处在 SIFS 的校验阶段，等它校验完就能先发出 CTS 或数据，而新来的站点还在等 DIFS，从而避免被打断。

> **易错点**：只需记住"任意 DIFS > 任意 SIFS"及其原因（保证进行中的交互优先占住信道）

## 分组交换的时延计算

[02:35:00 - 02:44:00]

1 Mbit 文件按 1000 字节分组（忽略首部）得 1000 个分组；100 Mbit/s 链路上单分组传输时延为 8000 bit / 100 Mbit/s = 80 μs，由时延带宽积 1000 bit 反推单程传播时延为 10 μs。计算思路是**只看最后一个分组**：前 999 个分组发送需 999×80 μs，最后一个分组再依次经过每段链路的"传输 + 传播"。计入传播时延为 999×80+80+10+80+10 = 80100 μs = 80.1 ms；忽略传播时延则为 80.08 ms。

> **公式**：T = (n−1)·L/R + k·(L/R + τ_single)，n 为分组数、k 为链路（跳）数

> **易错点**：不要逐分组累加；总时间 = 前 n−1 个分组的发送时间 + 最后一个分组走完全程的时间（含每一跳的传输和传播）

## 吞吐量与瓶颈链路

[02:44:00 - 02:50:00]

端到端吞吐量取决于路径上**最慢（带宽最小）**的那一段，其余高速段都是干扰条件——若只问 R1 到 R2 一段链路，则答案就是该段的 100 Kbps。共享链路要先按并发流数均分：2 Mbit/s 公共链路被 4 个下载共享，每条分得 500 KB/s，再与各支路 1 MB/s 取最小，得每条流端到端 500 KB/s。该知识点 2024 选择、2025 大题小问连续两年出现。

> **公式**：端到端吞吐量 = min(各段速率)；共享链路每条流的份额 = 链路带宽 / 并发流数

> ⚠️ **需回看视频 [02:45:00]**：例题中带宽单位在 KB/s 与 Kbps 之间混用（10 KB/s、100 Kbps），是否同一量纲影响数值判断 —— "H1到路由器R1是10KB每秒……这一段链路它的这个速度是100Kbps"

## 帧序号的作用：固定帧头长度

[02:50:00 - 02:56:00]

LLC 子层本可给每个帧分配逻辑序号（0—999），但序号所需位数随数值变化（0 号帧 1 位、999 号帧 10 位），接收方拆帧时无法确定该切多少位作为帧头。于是引入固定长度的帧序号：逻辑序号对 2ⁿ 取余，n 为序号位数，接收方每帧固定剥掉前 n 位即可。由此帧序号为 0 的两个帧内容、长度可以完全不同，它们只是编号循环复用。

> **易错点**：帧序号的意义是"固定头部长度便于拆帧 + 供窗口判重"，不是"数据相同"的标志

## 窗口长度与序号比特数的关系

[02:56:00 - 02:59:00]

通用约束是发送窗口与接收窗口之和不超过 2ⁿ。停止等待的发送窗口恒为 1；后退 N 帧的接收窗口为 1，故发送窗口最大 2ⁿ−1；选择重传要正常工作需收发窗口相等且各为 2^(n−1)（这是保证新帧能与旧帧区分的最小要求，理论上最大可到 2ⁿ−1）。

> **公式**：W_T + W_R ≤ 2ⁿ；GBN W_T,max = 2ⁿ−1；SR W_T = W_R = 2^(n−1)

> **易错点**：题目问"至少/能正常工作"取 2^(n−1)，问"最大"取 2ⁿ−1，别混

## 信道利用率的计算

[02:59:00 - 03:05:00]

发送周期 T 从发出第一个比特起，到收到最后一个确认帧为止，等于首帧传输时延 + 一个往返传播时延 + 确认帧传输时延（确认帧忽略则末项为 0）。利用率为一个周期内有效发送时间与 T 之比，连续发送 W 帧时分子为 W×L/C。例：1000 B 帧、100 KB/s 链路，单帧传输 80 ms，RTT 为 0.48 s，T = 0.56 s；要求利用率不低于 80%，则 W ≥ 0.8×0.56/0.08 = 5.6，取 W = 6，对应序号 3 比特。2023 真题在同一 T 下只比分子：停等 1 份、GBN 7 份、SR 4 份，故 U1 < U3 < U2。

> **公式**：U = W·(L/C) / (L/C + 2τ + T_ack)

> **易错点**：分母中的首帧传输时延只算一次，不要乘 W；分子才是"窗口内所有帧的发送时间"

> ⚠️ **需回看视频 [03:02:00]**：口误，把"发送窗口为 1"说成后退 N 帧（应为停止等待协议），影响 2023 真题三个利用率大小的判断 —— "对于后退N帧来说，它是发送窗口为一啊"

## SDN：控制层面与数据层面的分离

[03:05:00 - 03:14:00]

传统网络层做两件事：按转发表转发数据（数据层面）、用 RIP/OSPF/BGP 建立路由表（控制层面）。问题是每台路由器各自跑路由协议、洪泛交换信息，链路上充斥建表报文而拥塞。SDN 把控制层面集中化：网络节点统一由"分组交换机"担任，它是砍掉自主建表能力的路由器，只按流表转发；上层由一台或一组服务器构成的远程控制器掌握全网状态，算出各网络之间的最优路径并统一生成流表，通过 OpenFlow（南向接口）下发。向上则通过北向接口提供 API 供应用开发者编程。SDN 流表可同时匹配 MAC 地址、IP 地址和端口号，而传统路由表只按 IP、链路层转发表只按 MAC。

> **易错点**：分组交换机不跑路由协议、不生成路由表；北向接口对上（应用/开发者），南向接口对下（分组交换机，下发流表）

## 帧长的约束（收尾答疑）

[03:14:00 - 03:16:54]

滑动窗口协议对帧长没有最小值要求，408 链路层中唯一对帧长有要求的是以太网帧（最短 64 B，由 CSMA/CD 的 2τ 约束决定）。

> **易错点**：看到"最小帧长"要立刻限定在以太网/CSMA-CD 语境，不要套到滑动窗口协议上
