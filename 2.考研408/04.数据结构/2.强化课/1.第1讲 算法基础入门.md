# 数据结构强化课 第1讲 算法基础入门

## 强化课安排与复习资料的使用边界

[00:00:00 - 00:13:00]

强化课共五次：本讲"算法基础入门"是第 1 讲，专门为零基础和跨考同学补代码入门，之后四讲才进入数据结构正式内容，全部结束后安排"二模"（十一之前）。真题不必全部留到最后：最近三年（23/24/25）留到冲刺阶段当套卷模拟，其余年份在基础、强化阶段都可以做。**不需要额外刷力扣**——408 加数一、英一没有那个时间，性价比太低；把王道书上的题目和讲义上的例题、练习题全部写完就够。课上补充的算法题多取自力扣，因为部分真题的算法题原型就来自力扣，甚至原样照搬。

## 一模答卷暴露的六类共性问题

[00:13:00 - 00:17:00]

数据结构算法题固定三问：算法思想、代码实现（关键语句给注释）、时间与空间复杂度。一模中集中暴露的问题有：①算法思想写得太简（只写"用二叉树的中序遍历"）或太细（把每行代码翻译成中文）；②私自改动题目给出的函数名、参数列表，甚至改二叉树结点的结构体定义——近两年真题一般会给出函数头，改动要扣分；③全篇没有一行注释，阅卷老师没有时间逐行反推你的思路；④边界条件没考虑，代码不健全；⑤循环细节（for 的边界、while 的退出、变量初值）没想清楚；⑥第三问漏写，或时间、空间复杂度只写一个。

> **易错点**：题目给了函数头就照抄，参数一个不加、一个不减；注释要写在关键变量、关键判断、关键循环处，几个字即可。

## 算法基础课的五项训练目标与暴力解保底策略

[00:17:00 - 00:21:00]

目标依次是：读懂题干给了什么条件、用画图模拟代替空想（链表、树、图尤其如此）、对简单题形成朴素算法思想（哪怕暴力）、把思想翻译成合法 C 代码、在复杂度相同时用技巧做局部优化（提前结束、压缩篇幅）。**保底要求是暴力解必须写得出**：12 分的算法题，暴力解正确一般能拿 8 分左右，扣分主要落在第二问，第一、三问写对不扣分，因此不影响上 120 分。初试阶段一律不上机，上机费时且效率低。

> **易错点**：复杂度要写你"这个实现"的复杂度，不能自认为最优是 O(n) 就写 O(n)。

## 单调数组：题意与判定思路

[00:21:00 - 00:24:00]

给定长度 n 的整型数组 nums，元素**互不相等**，判断是否单调，返回布尔值。由于元素互异，单调只能是严格递增或严格递减，不存在相等情形。例：1,2,4,9 各相邻对都是递增，整体递增，返回 true；若数组中既出现局部递增又出现局部递减（如 …5,4…），整体必然不单调，返回 false。

> **定义**：单调数组 ⇔ 所有相邻元素对 nums[i] 与 nums[i+1] 的大小关系方向一致。
> **易错点**：题干"均不相等"是简化条件，比较时不必处理相等。

## 数组遍历的代码模板

[00:24:00 - 00:27:00]

遍历数组用整型循环变量 i 作下标，它与链表里存放地址的指针不是一回事，只起标记作用。模板为 `for (i = 0; i < n; i++)`，循环体内对 nums[i] 做访问或修改。n 个元素的下标范围是 0 到 n-1，当 i 增到 n 时条件为假，循环退出。

> **公式**：`for (int i = 0; i < n; i++) { /* visit nums[i] */ }`
> **易错点**：写成 `i <= n` 或多算一个元素，会访问 nums[n]，越界。

## 反证思想与双标志位判定单调性

[00:27:00 - 00:35:00]

判定从"局部推整体"不方便，改用反证：只要发现一处局部递增，就能否定"整体递减"；发现一处局部递减，就能否定"整体递增"。于是设两个标志位 inc（increase）与 dec（decrease），初值都为 true，一趟遍历中同时维护：nums[i] < nums[i+1] 时 dec = false，nums[i] > nums[i+1] 时 inc = false。遍历结束后用逻辑或合并，一真即真。

> **公式**：`return inc || dec;`
> **易错点**：初值必须为 true（反证的大前提是"两种可能都还成立"），置 false 后不要再改回 true。

## 单调数组的代码实现与下标越界细节

[00:35:00 - 00:42:00]

函数原型 `bool isMonotonic(int* nums, int n)`，用指针接收数组首地址（不建议用 C++ 的取地址写法，上机一般传指针）。循环写成 `for (i = 0; i < n - 1; i++)`，因为循环体要取 nums[i+1]，若写 i < n，最后一轮 i = n-1 时访问 nums[n] 就越界。也可以改成与前一个元素比较，此时 i 从 1 开始、条件写 i < n。变量与函数名尽量用英文单词或其缩写，避免 a、b、c 这类魔法变量和拼音命名。

> **易错点**：访问 nums[i+1] 时循环上界必须是 n-1；比较下标方向换了，初值和上界要同步换。

## 两数之和：题意与双指针暴力思想

[00:42:00 - 00:48:00]

给定数组 nums、目标值 target，找出和为 target 的两个数，**返回它们的下标**而非数值；题目保证有解且答案唯一，因此找到即可立即 return，不必继续遍历。考研不能用哈希表、不能用 STL，只能走朴素路线：枚举任意两个元素，判断其和是否为 target。答案唯一这一点是后续剪枝（提前返回）的依据。

> **易错点**：题目要下标，不要返回元素值。

## 双重 for 循环模板与 C 语言返回数组

[00:48:00 - 00:55:00]

双重循环模板：外层 `i = 0; i < n; i++`，内层从符合题意的初值开始 `j`，条件 `j < 边界`。本题两数下标不同，内层取 j = i+1，不必从 0 开始，这就是最基础的双指针法。C 语言不能一次返回两个值，需 `malloc` 一个大小为 2 的 int 数组装下标，函数返回类型写成 `int*`；malloc 的空间大小是 `sizeof(int) * 元素个数`。比较必须用 `==`，单个 `=` 是赋值；函数末尾要保留一个兜底的 `return`，否则编译器报错。

> **公式**：`int* result = (int*)malloc(sizeof(int) * 2);`
> **易错点**：`nums[i] + nums[j] = target` 是赋值不是判断；返回的 result 数组不计入空间复杂度。

> ⚠️ **需回看视频 [00:53:00]**：疑似 ASR 识别错误（内层循环边界乱码）—— "内层的话就是i小于一，i小于n，j小于j等于i减一，j小于n"

## 空间复杂度的计算口径

[00:55:00 - 00:57:00]

空间复杂度只统计算法执行过程中额外开辟的辅助空间，不含输入数据，也不含题目要求返回的结果。本题只申请了常数大小的 result 数组，即使算上也是 O(1)；若过程中额外开了长度为 n 的数组，则为 O(n)。

> **定义**：空间复杂度 = 算法额外占用的辅助存储空间随问题规模 n 的增长量级。

## 回文数：边界条件与数位拆装技巧

[00:57:00 - 01:06:00]

判断整数 x 正读反读是否相同。示例中 x = -11 返回 false，说明负数一律直接返回 false——这是从示例里读出的第一个边界条件，读题要能读出边界。核心思想是逆置：拆位用 `x % 10` 取个位、`x / 10` 去掉个位；重组用 `rev = rev * 10 + digit`，循环条件 `while (x != 0)`。拆的过程中原数会被破坏，需另存 origin 以便最后比较。逆置结果可能超出 int 范围（如 52368 逆置为 86325），reverse 应声明为 long。

> **公式**：`rev = rev * 10 + x % 10;  x /= 10;`
> **易错点**：reverse 用 int 声明，上机时会被溢出用例卡掉。

> ⚠️ **需回看视频 [01:03:00]**：口误后自我更正、数值不确定—— "它应该是等于65536啊，65536……哦，6553，6536……65535能够保证表示的最大数是个65535"

## 回文数优化：只逆置后半部分

[01:06:00 - 01:15:00]

回文数分偶位与奇位两类。偶位时只需逆置后一半，逆置结果与前一半相等即为回文；奇位时中间位不影响结果，逆置后多出的那一位（中间位）用 `/10` 去掉再比。代码：`while (x > num) { num = num * 10 + x % 10; x /= 10; }`，返回 `x == num || x == num / 10`，循环在 x 不大于 num（即已折半）时结束。另有一个隐蔽边界：以 0 结尾的非零数（如 1010）会被误判为 true，需先排除 `x % 10 == 0 && x != 0`。优化解法只对特定规律成立，general 情况下的边界要靠上机跑测试用例补。

> **公式**：`return x == num || x == num / 10;`
> **易错点**：奇数位时忘记去掉中间位；漏掉末尾为 0 的用例。

> ⚠️ **需回看视频 [01:12:00]**：ASR 识别错误，奇数位回文的返回条件表述残缺—— "所以说它就是一个x是否等于一个三。19对10取整，去掉中间这一位，那3等于3"

## 顺序表删除值为 x 的元素：结构体定义与朴素 O(n²) 解法

[01:15:00 - 01:19:00]

题目要求自己写出顺序表的结构体定义（maxSize = 100，成员为 data 数组和 length），返回删除后的顺序表。顺序表的删除是逻辑删除，必须把后面的元素逐个前移覆盖，并同步修改 length。朴素做法：工作指针 i 从表首扫，遇到 x 就令 j = i+1 到表尾逐个前移一位，length 减一，时间 O(n²)。

> **易错点**：忘记 `L.length--`；顺序表、单链表、双链表、二叉树、图的结构体定义都要能独立默写。

## 计数变量实现 O(n) 一步到位删除

[01:19:00 - 01:29:00]

观察暴力过程可发现规律：每个非 x 元素被前移的次数，恰好等于它前面 x 的个数。于是设 count 记录已遇到的 x 个数，遍历时若 `data[i] != x` 就执行 `data[i - count] = data[i]`（一步到位），否则 count++；遍历完 `length -= count`。时间 O(n)、空间 O(1)，代码仅一个 for 循环。写代码时关键变量（如 count）和关键判断必须加简短注释。

> **公式**：`if (L.data[i] != x) L.data[i - count] = L.data[i]; else count++;`
> **易错点**：循环上界用题目给的 n；最后必须修正 length，否则返回的表长度不变。

## 合并两个非递减顺序表

[01:29:00 - 01:45:00]

双表各自有序，要求合并后仍保持大小关系（不要求稳定，相等元素先后随意）。用三个指针 i、j、k：i、j 分别扫描两表，k 指示结果数组写到哪里，每次把较小的元素写入 result[k] 并后移对应指针；结果数组需开 m+n 大小。循环条件写成 `while (i < m || j < n)`，若写成 `&&`，短表耗尽后还得再补两个 while 搬剩余元素，共三个循环。时间复杂度 O(m+n)——即使短表先结束，长表仍要逐个搬运。

> **公式**：`while (i < m || j < n)`，短表耗尽后另一表直接整体搬运。
> **易错点**：`&&` 写法下忘记处理剩余元素，会漏数据或越界；答案要求写 O(m+n)，不是 O(n)。

> ⚠️ **需回看视频 [01:37:00]**：口述"与/或"与代码不符，语义表述混乱—— "如果你写成i小于m，并且……给它与上一个与上一个j小于一个n……我这样写或的话，就是只要它俩有一个表还没有遍历结束"

## 答疑：STL 与库函数的使用边界

[01:45:00 - 01:55:00]

考研代码只能写 C/C++ 原生结构，STL 不能用（C++ 的 vector 可以用）。库函数是否可用看一条标准：**用了它是否降低了题目难度**——排序本身是考点时直接调 sort 肯定不行，而 abs、max 这类不影响难度的小函数可以用。408 不考动态规划，因为一考就得连带贪心、回溯、分治，不现实。考场上若连暴力解思路都没有，先跳过，不要耗时间。

## 奇偶划分：相向而行的双指针

[01:55:00 - 02:08:00]

要求偶数在前半部分、奇数在后半部分，两部分内部顺序不限，等价于把后半部分的偶数换到前面、前半部分的奇数换到后面。用相向双指针：i 从表首向右找奇数，j 从表尾向左找偶数，各自跳过本就在正确位置的元素，找到一对后交换。**不能一发现奇数就与 j 位置直接 swap**：j 脚下可能本来就是奇数，强行交换反而破坏正确性；必须先让 j 越过这些奇数。代码与快排 partition 几乎同构。

> **易错点**：四个 `even < odd` 判断缺一不可——外层控制划分结束，两个内层 while 防止指针越界，交换前再判一次合法性；少写一个就会换错。

## 荷兰国旗问题：三指针一趟排序 0/1/2

[02:08:00 - 02:29:00]

数组只含 0、1、2，要求 0 在前、2 在后、1 居中。设 left、right 两个"守门员"：left 为左闭右开区间，保证 left 左侧全是 0；right 为左开右闭区间，保证 right 右侧全是 2；两者脚下元素状态未知。另设工作指针 i 遍历：`nums[i]==0` 时 swap(i,left)、left++、i++；`==1` 时 i++；`==2` 时 swap(i,right)、right--、**i 不动**。i 不自增的原因是换过来的值是未检查的，可能就是 2，若跳过它会永远卡在中间换不出去。循环在 i > right 时结束（right 右侧已保证全是 2），时间 O(n)、空间 O(1)。

> **公式**：`for (i = 0; i <= right; i++)` 中处理 2 需写 `i--` 抵消自增；处理 0 不再额外 i++。
> **易错点**：处理 2 后 i 自增会漏算；循环跑到 n 会把已经归位的 2 又换乱。

## 单链表删除所有值为 x 的节点

[02:29:00 - 02:41:00]

不带头节点时首元节点要特判，统一做法是自己加一个虚头节点 dummyHead：`dummyHead->next = head`，之后所有结点处理方式一致。单链表没有 pre 指针，需额外设 pre 标记前驱，并保证 pre 与 p 始终紧邻。删除顺序是**先改前驱的 next，再释放本结点**：`pre->next = p->next; free(p); p = pre->next;`。循环条件必须是 `while (p != NULL)`，写成 `p->next` 会漏删尾结点。严谨写法最后 `head = dummyHead->next; free(dummyHead); return head;`，避免内存泄漏（考试不因此扣分）。malloc/new 的空间在堆区，不会随函数返回自动释放；临时变量在栈区，随函数结束自动回收。

> **易错点**：先 free 再改指针会断链；用 `p->next` 作循环条件漏删最后一个结点。

## 只出现一次的数字：排序 + 成对查找

[02:41:00 - 02:48:00]

除一个数外其余都出现两次，找出那个数。解法一排序后成对检查：`for (i = 0; i < n - 1; i += 2)`，若 `nums[i] != nums[i+1]` 则 nums[i] 就是答案；若每一对都相等，说明答案是最后一个元素。解法二计数（两趟，2n）。排序解法要先手写排序（冒泡 + flag 优化），代码约 25 行，这也是它不讨喜的原因。

> **易错点**：步长写 i++ 而非 i += 2，会破坏成对结构；循环上界要留出 i+1 的位置。

> ⚠️ **需回看视频 [02:46:00]**：口误/表述与代码不一致，步长说法自相矛盾—— "这也是为什么我这儿用i加一之后，这儿n减一"

## 异或解法：交换律与结合律

[02:48:00 - 02:53:00]

按位异或的规则是相同为 0、不同为 1，因此 a ^ a = 0、a ^ 0 = a，且异或满足交换律与结合律。把数组中所有元素依次异或，成对出现的元素两两抵消为 0，最后剩下的就是只出现一次的那个数。代码把 ans 初始化为 nums[0]，循环从第二个元素（下标 1）开始，共 7 行，时间 O(n)、空间 O(1)。

> **公式**：`a ^ a = 0`，`a ^ 0 = a`，`a ^ b ^ a = b`
> **易错点**：ans 从 nums[0] 起就要从下标 1 开始循环，从 0 开始会把它自身异或成 0。

> ⚠️ **需回看视频 [02:51:00]**：表述不严谨（"answer 不等于零即找到"对唯一元素为 0 的情形不成立）—— "当我最后的这个answer呢，它不等于零的时候，那就我们找到了那个……只出现了一次的元素"
