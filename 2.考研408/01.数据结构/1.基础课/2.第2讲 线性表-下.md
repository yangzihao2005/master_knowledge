# 数据结构基础课 第2讲 线性表-下

## 本章概览：操作受限的线性表

[00:00:00 - 00:11:00]

本讲从线性表延伸到"操作受限的线性表"。栈与队列本质上仍是线性表，只是把插入、删除的位置限制在端点，因此称为操作受限。按存储方式，栈分为顺序栈、链栈、共享栈；队列分为顺序队列、循环队列、链式队列与双端队列。栈的典型应用是括号匹配、中缀转后缀、后缀表达式求值（栈与递归放到二叉树一讲），本章后半部分则是数组、特殊矩阵压缩存储与串的模式匹配。

> **易错点**：栈和队列都是**线性结构**，"受限"只体现在插入删除的位置上，不改变元素之间一对一的逻辑关系。

## 栈的定义与基本术语

[00:11:00 - 00:12:00]

栈是只允许在**同一端**进行插入和删除的线性表。允许操作的一端叫栈顶（top），另一端叫栈底；栈底方向既不能插入也不能删除，这就是"操作受限"之所在。没有任何元素时称为空栈，从线性表角度看就是一个空表。

> **定义**：栈（Stack）是仅允许在一端（栈顶）进行插入和删除的线性表，特点是后进先出（LIFO，First In Last Out）。

## 顺序栈的结构定义

[00:12:00 - 00:13:00]

顺序栈用一个定长数组加一个 `int` 型栈顶指示器描述，数组容量为 MaxSize，元素类型不限。它与顺序表的结构非常像，区别只在于多出的 `top` 用来指示栈顶位置。

> **易错点**：这里的 `top` 是 `int` 型下标，只起**指示位置**的作用，不是链表里带 `*` 的真指针，不能按地址语义理解。

## 顺序栈 top = -1 的初始化与入栈

[00:13:00 - 00:15:00]

初始化令 `s.top = -1`，表示栈空，且下一次插入从下标 0 开始。入栈必须**先移动指针、后赋值**：`s.data[++s.top] = x`，拆成两行写更直观。

> **公式**：初始化 `s.top = -1`；入栈 `s.data[++s.top] = x`。

## 栈顶指针语义、判满与上溢

[00:15:00 - 00:17:00]

在"初值 -1 + 先移指针后赋值"的约定下，只要栈非空，`top` 就恒指向当前栈顶元素。于是栈满时 `top` 恰好指向 MaxSize-1，判满条件为 `top == MaxSize - 1`；此时再入栈即发生上溢。

> **公式**：判满 `s.top == MaxSize - 1`。
> **易错点**：题干往往只说"非空时栈顶指针指向栈顶元素"，据此即可反推初值必为 -1；说"指向栈顶元素的下一个位置"则初值必为 0。

## 出栈、判空与下溢

[00:17:00 - 00:19:00]

出栈顺序与入栈相反：先取栈顶元素，再移动指针，`x = s.data[s.top--]`。出栈前必须先判空，`top == -1` 即空栈；对空栈执行出栈就是下溢。

> **公式**：判空 `s.top == -1`；出栈 `x = s.data[s.top--]`。
> **易错点**：入栈先判满、出栈先判空；取值与移指针的先后顺序由初始化约定决定，两套约定不能混用。

## 顺序栈 top = 0 的另一种约定

[00:19:00 - 00:22:00]

若初始化 `top = 0`，入栈就要**先赋值、后移指针**：`s.data[s.top++] = x`。此时非空时 `top` 指向栈顶元素的下一个位置（也就是下一次插入的位置），判满条件变成 `top == MaxSize`，出栈则要先减指针再取值 `x = s.data[--s.top]`，判空为 `top == 0`。

> **公式**：初值 0 时——入栈 `s.data[s.top++] = x`；出栈 `x = s.data[--s.top]`；判满 `top == MaxSize`；判空 `top == 0`。

## 两种 top 约定的对照

[00:22:00 - 00:24:00]

两种写法都是顺序栈，唯一区别是 `top` 的初值，由此派生出"指向栈顶元素"和"指向栈顶元素下一位置"两套语义、两套操作顺序。这是本章第一个高频考点：题目不给初值，只给非空时刻指针的位置，要求反推初始化。

> **易错点**：初值 -1 → 判空 `top == -1`、判满 `top == MaxSize - 1`、入栈先加后赋、出栈先取后减；初值 0 则四处全部相反。

## 出栈序列种数与卡特兰数

[00:24:00 - 00:28:00]

n 个元素依次入栈、允许在任意时刻出栈，能得到的出栈序列数为卡特兰数。三个元素 A、B、C 可穷举出 5 种合法序列，而 CAB 不可能：C 出栈时 A 仍压在 B 之下，A 不可能先于 B 出栈。

> **公式**：出栈序列种数 $= \dfrac{1}{n+1}\binom{2n}{n}$（n=3 时为 5）。
> **易错点**：题目只说"依次入栈"，并未要求全部入栈后再出栈，必须按"随时可进可出"模拟，否则会漏解。
> ⚠️ **需回看视频 [00:27:00]**：卡特兰公式转写残缺（疑似 ASR 把分式与组合数念乱），需确认标准形式 —— "三加上一个一分之一，然后乘以一个C二n，就是C六三"

## 共享栈的结构与操作

[00:28:00 - 00:31:00]

共享栈让两个顺序栈共用一段 MaxSize 的空间：0 号栈栈底在下标 0、向高地址增长，1 号栈栈底在下标 MaxSize-1、向低地址增长，两栈底相向、栈顶相向。0 号栈沿用 `top0 = -1` 的约定（先加指针后赋值）；1 号栈入栈时指针要**减**：`s.data[--top1] = x`，出栈后指针再加。

> **易错点**：1 号栈的指针移动方向与 0 号栈相反，入栈写 `--top`、出栈写 `++top`，写反就会越界。
> ⚠️ **需回看视频 [00:30:00]**：1 号栈栈顶指针的初值说法不确定，需确认教材约定 —— "按照原来的设定，我可以把它放在max size这个地方，其实也可以放在max size减一"

## 共享栈的判满与优点

[00:31:00 - 00:33:00]

当两栈指针都指向各自的栈顶元素时，栈满等价于两个指针相邻，即 `top1 - top0 == 1`。与"两个栈各占一半空间"相比，共享栈让一端空闲的空间可被另一端继续使用，从而提高空间利用率、降低上溢风险。

> **公式**：判满 `top1 - top0 == 1`（等价于 `top0 + 1 == top1`）。

## 共享栈判满条件的四种变体

[00:33:00 - 00:35:00]

若把 `top0` 的初值取 -1 或 0、`top1` 的初值取 n 或 n-1，判满表达式随之改变，本质仍是判断"下一次插入是否会与另一栈栈顶重叠"。若两指针都指向各自栈顶元素（-1 与 n），满时 `top1 - top0 == 1`；若都指向待插入位置（0 与 n），满时 `top0 == top1`；混合约定则需按同样思路现推。

> **易错点**：不要死记某一个式子，先判断两个指针各自"指向栈顶元素还是待插入位置"，再判断何时重叠。

## 链栈的结构定义

[00:35:00 - 00:36:00]

链栈用链式存储实现栈，只需一个栈顶指针，这里的指针是**真指针**。与链表一样要拆成两个结构体：链栈（`LinkStack`）只含 `top` 指针，链栈结点（`LNode`）含 `data` 域与 `next` 域。老师给出的示例是不带头结点的链栈。

> **定义**：链栈 = 只在表头插入、删除的单链表，`top` 即单链表的头指针。

## 链栈的入栈（头插法）

[00:36:00 - 00:41:00]

链栈只能在一端操作，因此入栈永远是**头插**：先修改新结点的 `next` 指向当前栈顶，再让 `top` 指向新结点，即 `s->next = top; top = s;`。空栈时 `top == NULL`，这三行代码依然成立，无需特判。带头结点时同理，只是插入位置变成头结点之后：`s->next = top->next; top->next = s;`。

> **易错点**：链栈虽本质是单链表，但绝不能在表尾插入——那会破坏后进先出。只写 `top = s` 而漏掉 `s->next = top`，只在空栈时偶然正确，不具普适性。

## 链栈的出栈与判空

[00:41:00 - 00:46:00]

链栈入栈不需要判满（结点动态申请，理想情况下内存充足；真溢出由系统抛出异常处理），但出栈必须判空。不带头结点时判空为 `top == NULL`；出栈先用工作指针 `p` 标记栈顶，再 `top = top->next`，最后 `free(p)`，删到最后一个结点时 `top` 自然变成 NULL。带头结点时判空为 `top->next == NULL`，出栈为 `p = top->next; top->next = p->next; free(p);`。

> **公式**：不带头结点——入栈 `s->next = top; top = s;`，出栈 `p = top; top = top->next; free(p);`
> **易错点**：带头结点的链栈，`top` 永远指向头结点、不会为空，判空必须看 `top->next`。

## 栈操作的结构体封装

[00:46:00 - 00:47:00]

除数据成员外，还可以把 `push`、`pop`、`getTop` 等成员函数写进结构体。使用者声明一个 `LinkStack s` 后直接 `s.push(x)`、`s.pop()` 即可，不必关心内部实现，结构体就成了"黑盒子"。这也是后续调用库函数（如 Python 深度学习框架）时的同一套封装思想。

## 真题：出栈序列中 P3 的可能取值

[00:47:00 - 00:53:00]

入栈顺序 1…n，出栈序列为 P1…Pn，已知 P2 = 3 时问 P3 可能取值个数。解题关键是按 P1 的取值分类讨论：P1 可取 1、2、4，共三类情形，只有 P1 = 3 不成立（3 要当 P2，就不可能先出栈）。逐类模拟可得 P3 可取 1、2、4、5…n，唯独取不到 3，故可能取值个数为 n-1。

> **易错点**：这类题没有公式可套，必须"分类 + 逐步模拟"；判断某个序列是否合法，只需看是否存在"压在栈中更靠下的元素反而先出"的情况。

## 队列的定义与顺序队列结构

[00:53:00 - 00:55:00]

队列只允许在一端插入、在另一端删除，因此是先进先出（FIFO）。允许删除的一端叫队头（front），允许插入的一端叫队尾（rear），删除称出队、插入称入队，无元素时称空队。顺序队列同样用"数组 + 两个 int 型指示器"描述，`front`、`rear` 也是下标而非真指针。

> **定义**：队列（Queue）是只允许在队尾插入、队头删除的线性表，特点是先进先出（FIFO）。

## 顺序队列的初始化与入队

[00:55:00 - 00:57:00]

常规约定令 `front = rear = 0`。入队只能在队尾，元素从下标 0 开始放，所以**先赋值、后移指针**：`q.data[q.rear++] = x`。此时非空队列的 `rear` 指向队尾元素的下一个位置，而 `front` 始终指向队首元素。

> **公式**：初值 0 时——入队 `q.data[q.rear++] = x`；判满 `q.rear == MaxSize`。

## 顺序队列的出队与假溢出

[00:57:00 - 01:00:00]

出队只能动队头，**先取值、后移指针**：`x = q.data[q.front++]`，故非空时 `front` 恒指向队首元素。连续入队到 `rear == MaxSize` 就判满，但若此前已出队多次，数组中前面其实空着位置——这种"还有空间却报满"的现象叫假溢出。

> **易错点**：假溢出不是真的没空间，而是 `front`/`rear` 只会单向前进而"看不到"前面已释放的位置。

## 假溢出的成因与 front = rear = -1 的约定

[01:00:00 - 01:02:00]

假溢出的根源是两个指针都只能感知自己指向的那一个位置，无法回头利用前面空出的单元。若改成 `front = rear = -1` 初始化，则非空时 `rear` 指向队尾元素、`front` 指向队首元素的**前一个**位置，于是入队变成先移指针后赋值、出队变成先移指针再取值。

## 顺序队列两种约定的对照

[01:02:00 - 01:03:00]

初值 0：`front` 指队首元素、`rear` 指队尾元素下一位置，入队先赋值后移 `rear`，出队先取值后移 `front`。初值 -1：`front` 指队首元素前一位置、`rear` 指队尾元素，入队先移 `rear` 后赋值，出队先移 `front` 再取值。与栈一样，题目可用"非空时刻指针指向何处"反推初值。

> **易错点**：栈的 `top` 与队列的 `front/rear` 是同一套"初值决定语义、语义决定代码顺序"的逻辑，务必对齐记忆。

## 循环队列：用取模把顺序队列首尾相接

[01:03:00 - 01:06:00]

解决办法只有一步：让指针加一后对 MaxSize 取模，`rear = (rear + 1) % MaxSize`，指针走到数组末尾就自动回到下标 0，从而重用前面空出的单元。这只是代码层面的"臆想成环"，内存中仍是顺序存储、连续排列，并不是真正的环。

> **公式**：`rear = (rear + 1) % MaxSize`，`front = (front + 1) % MaxSize`。
> **易错点**：循环队列仍属**线性结构**（逻辑上仍是一对一的线性关系），只是用取模让存储空间首尾相接；不能因为"循环"二字就判成非线性结构。

## 循环队列的初始化与入队

[01:06:00 - 01:08:00]

初始化仍取 `front = rear = 0`。入队先判满，再先赋值后移指针：`q.data[q.rear] = x; q.rear = (q.rear + 1) % MaxSize;`。当元素把数组塞满时，`rear` 会绕回 0，恰好与 `front` 相等。

> **易错点**：`rear == front` 既可能是队空（初始状态）也可能是队满（绕一圈后），单靠这一个条件无法区分。

## 元素个数公式与空满歧义

[01:08:00 - 01:10:00]

非空时 `front` 指队首元素、`rear` 指队尾元素下一位置，元素个数为 `(rear - front + MaxSize) % MaxSize`；加 MaxSize 是为了处理 `rear` 绕回后小于 `front` 的情况。同理，出队也用取模移动 `front`，出队到与 `rear` 相等时队空。

> **公式**：元素个数 `= (rear - front + MaxSize) % MaxSize`。
> **易错点**：不能直接用 `rear - front`，`rear < front` 时会得到负数。

## 循环队列空满判定的三种实现

[01:10:00 - 01:14:00]

方案一：牺牲一个存储单元。队空 `front == rear`，队满 `(rear + 1) % MaxSize == front`，代价是浪费一个空间。方案二：在结构体中增设 `size` 记录元素个数，队空 `size == 0`、队满 `size == MaxSize`，入队 `size++`、出队 `size--`。方案三：增设标志位 `tag`，入队后置 1、出队后置 0；当 `front == rear` 时，`tag == 0` 为队空（由删除造成），`tag == 1` 为队满（由插入造成）。

> **公式**：方案一 队满 `(rear + 1) % MaxSize == front`，队空 `rear == front`。
> **易错点**：方案二、三都是为了在不浪费空间的前提下消除 `front == rear` 的二义性；`tag` 的取值含义（1 表示刚插入）不要记反。

## 真题：由非空状态反推 front/rear 初值

[01:14:00 - 01:20:00]

数组 0…n-1 存放循环队列，非空时 `front`、`rear` 分别指向队首元素和队尾元素，且第一个入队元素存在 a[0]。由"只做过一次入队、`front` 未动过"可定 `front = 0`；由 `rear` 指向队尾元素（此时也是 a[0]）可得插入前 `(x + 1) % n = 0`，故 `rear` 初值为 n-1。答案：`front = 0, rear = n-1`。

> **易错点**：本题的初值是一零一负的**混合**状态，不满足"两个指针同进退"的直觉；只要抓住"非空时刻指针指向谁"这一条，所有这类题都能反推。

## 链队列的结构定义

[01:20:00 - 01:21:00]

链队列用链式存储实现队列，结构体 `LinkQueue` 含队头指针 `front` 与队尾指针 `rear`（都是真指针），结点 `LNode` 与单链表相同，含 `data` 与 `next`。示例为不带头结点的链队列，队空即 `front == rear == NULL`。

## 链队列的入队

[01:21:00 - 01:25:00]

入队只能在队尾做**尾插**：先申请并初始化新结点 `s`（`s->data = x; s->next = NULL;`），再 `q.rear->next = s; q.rear = s;`。空队时不能直接写 `q.rear->next`，需特判：让 `q.front = q.rear = s`。带头结点时无需特判首元素，`s->next = q.rear->next; q.rear->next = s; q.rear = s;` 一套代码通用，且 `front` 永远指向头结点、全程不动。

> **易错点**：不带头结点的链队，入队与出队都要为"空队/只剩一个元素"单独分支；带头结点能消除这些分支。

## 链队列的出队（不带头结点）

[01:25:00 - 01:28:00]

出队只能动队头，先判空（`front == NULL` 即空），再用工作指针 `p` 标记队首结点。一般情况：`q.front = q.front->next; free(p);`。特殊情况是被删的正是最后一个结点（`q.front->next == NULL`），删后队列变空，必须同时把 `front` 和 `rear` 置为 NULL，否则 `rear` 变成野指针。`free(p)` 可以提到 if/else 之外统一写一次。

> **易错点**：删最后一个结点时忘记同步 `rear`，是链队最典型的 bug。

## 链队列的出队（带头结点）与指针约定

[01:28:00 - 01:31:00]

带头结点时判空看 `q.front->next == NULL`；出队为 `p = q.front->next; q.front->next = p->next;`，若 `p == q.rear`（删的是最后一个元素）则令 `q.rear = q.front`，最后 `free(p)`。由于 `front` 恒指头结点，也可以把 front/rear 的语义整体对调（队首放表尾、队尾放表首），同样能完成全部操作，只是实现与复杂度略有差别。

> **易错点**：带头结点的链队中"删最后一个元素"的判断是与 `rear` 比较，而不是判断 `p->next == NULL`。

## 链式队列的优势

[01:31:00 - 01:32:00]

链队内存动态分配，只要内存充足就不会溢出，也不存在假溢出问题。它更适合"队列个数多、每个队列长度事先无法估计"的场合，例如操作系统中的优先级作业调度——用一个申请一个，避免大量空间浪费。

## 双端队列及其变体

[01:32:00 - 01:33:00]

双端队列允许在两端进行插入和删除。若限制只允许一端入队、两端均可出队，称为**输入受限**的双端队列；若限制只允许一端出队、两端均可入队，称为**输出受限**的双端队列。这类题没有技巧，考试时逐个模拟即可。

## 真题：火车轨道调度的最少队列数

[01:33:00 - 01:46:00]

n 条轨道即 n 个队列，列车只能从左进、右出（先进先出），入队次序给定、要求驶出次序为 1…9。维护每条轨道"从队首到队尾递增"这一不变量：新元素只能接到队尾仍小于它的轨道上；若某元素（如 1）必须是下一个输出，则它只能进空轨道。按 8、4、2、5、3、9、1、6、7 依次模拟，共需 4 条轨道。

> **易错点**：能否并入某队列，判据是"接在队尾后仍保持递增"，而不是"比队首大"；顺序不对会多开轨道，答案偏大。

## 栈与队列的应用概览

[01:46:00 - 01:48:00]

本讲涉及三类应用：括号匹配、中缀表达式转后缀表达式、后缀表达式求值，另外补充了直接用栈求中缀表达式值。栈与递归的关系因涉及较抽象的内容，安排到二叉树一讲再讲。

## 栈的应用之一：括号匹配

[01:48:00 - 01:52:00]

从左到右扫描表达式：遇左括号就入栈；遇右括号则弹出栈顶，检查是否与它同类型配对。若栈空（没有对应的左括号）或类型不匹配，立即判定非法；扫描结束后栈必须为空，否则说明有多余的左括号。

> **易错点**：括号不仅要"左右数量相同"，还必须**类型匹配且嵌套次序正确**，`(]` 与 `([)]` 都是非法；判断顺序是"先判栈空，再判类型"。

## 中缀转后缀：两个栈的规则

[01:52:00 - 01:57:00]

用两个栈：`result` 存操作数与结果，`temp`（有些题叫 OP 栈）存运算符。遇操作数直接压 `result`；遇左括号直接压 `temp`；遇右括号则把 `temp` 中运算符依次弹出并压入 `result`，直到弹出左括号为止（括号本身不进入 `result`）。遇普通运算符时与 `temp` 栈顶比较优先级：栈内优先级高，就弹出栈顶压入 `result`；否则当前运算符入 `temp`。扫描结束后把 `temp` 中剩余运算符全部弹出压入 `result`，再按栈底到栈顶输出即为后缀表达式。

> **公式**：优先级口诀——"中缀下先算的，后缀下也要先算"：括号内 > 乘除 > 加减，同级从左到右（故栈内同级运算符优先出栈）；左括号入栈后优先级视为最低。
> **易错点**：遇到右括号是"连续出栈直到左括号"，不是只弹一个；转换的目的是去括号，所以括号不写入结果。

## 中缀转后缀：完整示例

[01:57:00 - 02:02:00]

以 `(2+3-1)*2-3*(8/4)` 为例，逐步模拟两个栈：遇 `(` 入 temp，`2` 进 result；遇 `+` 时栈内只有 `(`（优先级最低），故 `+` 入 temp；`3` 进 result；遇 `-` 时栈内 `+` 与它同级且中缀下 `+` 先算，故 `+` 出栈进 result，`-` 入 temp；`1` 进 result；遇 `)` 时连续出栈直到 `(`，把 `-` 送入 result 并丢弃括号。此时 temp 空，`*` 直接入栈，`2` 进 result；遇 `-` 时栈内 `*` 优先级更高，`*` 出栈进 result，`-` 入栈；`3` 进 result；遇 `*` 时栈内 `-` 优先级更低，`*` 直接入栈；遇 `(` 因其"括号内先算"而直接入栈；`8` 进 result，`/` 入栈（高于 `(`），`4` 进 result；遇 `)` 让 `/` 出栈进 result。最后把 temp 中剩余的 `*`、`-` 依次弹出，得后缀表达式 `2 3 + 1 - 2 * 3 8 4 / * -`。

> **易错点**：手算时一定要逐步记录两个栈的**瞬时状态**，真题常问"扫描到某字符时 temp 栈中有哪些符号""栈的深度最大是多少"。

## 栈的应用之二：后缀表达式求值

[02:02:00 - 02:07:00]

只需一个操作数栈 OP。遇操作数直接入栈；遇运算符则连续弹出两个操作数，**先弹出的是 A、后弹出的是 B**，计算 `B op A` 并把结果压回栈。以 `2 3 + 1 - 2 * 3 8 4 / * -` 为例：`2+3=5`，`5-1=4`，`4*2=8`，`8/4=2`，`3*2=6`，最后 `8-6=2`。扫描结束时栈中唯一剩下的元素就是整个表达式的值。

> **公式**：`B op A`（例如 `8 4 /` 计算 8/4，而不是 4/8）。
> **易错点**：减法、除法的操作数次序由出栈顺序决定，写反结果就错；加法、乘法虽不受影响，但不要因此养成坏习惯。

## 栈的应用之三：直接求中缀表达式的值

[02:07:00 - 02:12:00]

把前两个方法合起来：仍用 `temp` 存运算符、`result` 改存操作数。当某运算符从 `temp` 弹出时，立刻从 `result` 弹出两个操作数，计算 `B op A` 后压回 `result`；扫描结束后 `result` 栈顶即为结果。本例最终结果为 2，与"先转后缀再求值"一致。

> **易错点**：三类题（中缀转后缀、后缀求值、中缀直接求值）唯一要记的是"运算符出栈时如何与操作数结合"；优先级一律按中缀的数学运算顺序判断，不必背教材的栈内/栈外优先级表。

## 数组与特殊矩阵：本章概览

[02:12:00 - 02:14:00]

这一部分先讲数组的存储，再讲特殊矩阵的压缩存储，最后讲串。数组是线性表的推广，考试只关注一维与二维数组的地址计算。二维数组存入连续内存时有行优先与列优先两种方式；特殊矩阵包括对称矩阵、三角矩阵（上/下三角）、三对角（带状）矩阵与稀疏矩阵。

> **易错点**：矩阵下标一般从 1 开始，数组下标从 0 开始，两者相差 1，是压缩存储计算最常见的失分点。

## 一维数组的存储与地址计算

[02:14:00 - 02:16:00]

一维数组在内存中连续存放，元素地址 = 基地址 + 偏移量，偏移量 = 前面元素个数 × 每个元素所占单元数。

> **公式**：`LOC(a_i) = LOC(a_0) + i × L`（L 为每个元素占用的存储单元数）。
> ⚠️ **需回看视频 [02:15:00]**：一维数组地址示例中"偏移元素个数"的说法与结果不自洽（求 a[2] 时说的是 3 个元素），需核对是笔误还是另有前提 —— "基地址零一加上一共有多少个元素呢？它一共是三个元素"

## 二维数组的存储：行优先与列优先

[02:16:00 - 02:19:00]

二维数组可理解为"每个元素又是一维数组的一维数组"，存入内存时被展开成一维。**行优先**：先存完第 0 行再存第 1 行，同行元素相邻、跨行有步长；**列优先**：先存完第 0 列再存第 1 列。地址计算思路统一：先算前面整行（或整列）的元素总数，再加上本行（本列）内的偏移。

> **公式**：m 行 n 列，行优先 `LOC(a_ij) = LOC(a_00) + (i×n + j) × L`；列优先 `LOC(a_ij) = LOC(a_00) + (j×m + i) × L`。

## 特殊矩阵与压缩存储

[02:19:00 - 02:21:00]

特殊矩阵指含大量相同元素或大量零元、且分布有规律的矩阵。既然有规律，就不必用 n² 个空间全部存下，只存"有区别"的那部分，再用下标公式映射回原位置，这就是压缩存储。对称矩阵满足 `a_ij = a_ji`（沿主对角线对称），所以只需存一半（上三角或下三角任选），另一半用对称性换算。

> **定义**：压缩存储——按规律只存储部分元素，通过下标映射函数 k = f(i, j) 完成原矩阵与一维数组间的转换。

## 对称矩阵的下三角压缩与下标公式

[02:21:00 - 02:26:00]

存下三角（含主对角线）是按行展开：第 1 行 1 个、第 2 行 2 个……第 n 行 n 个，共 `n(n+1)/2` 个元素。求 `a_ij`（i ≥ j）在一维数组中的下标：先数前 i-1 行共 `1+2+…+(i-1) = i(i-1)/2` 个，再加上本行第 j 个（本行第 j 个即列号 j），最后因数组下标从 0 开始减 1。

> **公式**：存下三角时 `k = i(i-1)/2 + j - 1`（i ≥ j，i、j 从 1 开始）。
> **易错点**：若问的是上三角元素 `a_ij`（i < j），它并未被存储，需用对称性换成 `a_ji` 再代入公式；两个公式切勿混用 i、j 的位置。

## 三角矩阵的压缩存储

[02:26:00 - 02:32:00]

三角矩阵分两种。**下三角矩阵**：下三角（含对角线）全为同一常数，上三角不规则，于是存上三角 + 一个常数单元，共 `n(n+1)/2 + 1` 个位置；存上三角时第 1 行 n 个、第 2 行 n-1 个……第 n 行 1 个。**上三角矩阵**：上三角为常数，存下三角 + 一个常数单元，下三角的存储方式与对称矩阵完全相同。常数存于下标 `n(n+1)/2` 处。

> **公式**：下三角矩阵存上三角时 `k = (i-1)(2n-i+2)/2 + (j-i) `（i ≤ j，化简后即前 i-1 行元素数 + 本行第 j-i+1 个，因数组从 0 开始需减 1）；常数在下标 `n(n+1)/2`。
> **易错点**：问"下三角区域的元素"时，答案恒为 `n(n+1)/2`（常数单元位置），与 i、j 无关；问"上三角矩阵的上三角元素"时同理。
> ⚠️ **需回看视频 [02:29:00]**：上三角部分 k 的推导过程转写残缺（求和项与末尾"减一"交代不清），需按教材公式复核 —— "前面求和呢就是这个，后面求和就是加上一个j减i加一"

## 三对角（带状）矩阵的压缩存储

[02:32:00 - 02:37:00]

三对角矩阵只有主对角线及其上下各一条斜线（共三列）元素非零，其余全为 0。按行优先压缩：第 1 行 2 个、中间各行 3 个、第 n 行 2 个，共 `3n-2` 个元素。求下标时以"主对角线元素是本行第 2 个"为基准，用 `j - i` 作偏移量（-1、0、+1），再加基准 2 并减去 1。

> **公式**：`k = 2i + j - 3`（i、j 从 1 开始，行优先，数组下标从 0 开始）；元素总数 `3n-2`。
> **易错点**：第一行只有 2 个元素，用"每行 3 个"估算会多算 1 个，必须回补；这是本公式最容易错的地方。

## 已知数组下标 k 反求 i、j

[02:37:00 - 02:41:00]

由 `k = 2i + j - 3` 直接反解出 `j = k - 2i + 3`，还差 i。利用"前 i-1 行按每行 3 个计算会多算 1 个（第 1 行只有 2 个）"，可得不等式 `3(i-1) ≤ k+1 ≤ 3i-1`（k+1 是 1 起算的序号），解出唯一整数 i 后代回即得 j。

> **公式**：`j = k - 2i + 3`，i 由 `3(i-1) ≤ k+1 ≤ 3i-1` 取整求得（等价于 `i = ⌈(k+2)/3⌉`）。
> **易错点**：不等式的左右端点都来自"按 3 个/行"的近似，等号在"本行第一个元素"处取到；漏掉 ±1 就会算错行号。
> ⚠️ **需回看视频 [02:39:00]**：反求 i 的不等式推导过程含混（"什么时候取等号"一段转写不清），需按教材重新推一遍 —— "它是不是肯定是大于等于三乘以一个i减一的呀？"

## 稀疏矩阵与三元组

[02:41:00 - 02:44:00]

稀疏矩阵非零元极少且分布无规律，无法用下标公式映射，改用三元组 `(行号, 列号, 值)` 顺序存储非零元（还有链式的邻接表、十字链表表示法，只需了解）。注意：只有三元组**不能**还原原矩阵，因为不知道总行数与总列数，必须额外保存矩阵的行数 m 和列数 n。

> **易错点**：三元组表必须附带"总行数、总列数"，否则尾部全零的行列会丢失——这是简答题常考点。

## 串的基本概念

[02:44:00 - 02:45:00]

主串是给定的长串，子串是从主串中截取的任意连续片段（模式串也是主串的子串），串长即字符个数。本章真正的考点是模式匹配：先理解朴素（暴力）匹配的过程与复杂度，再看 KMP 如何消除主串指针的回溯，最后是改进的 KMP（nextval）。

## 朴素（暴力）模式匹配

[02:45:00 - 02:50:00]

用 i 扫描主串 S、j 扫描模式串 P，逐字符比较：相等则同时后移；失配则 i 回到本轮起点的下一个位置、j 回到 0，从头再比。每轮失败都"前功尽弃"，主串指针反复回退是它慢的根源。

> **公式**：时间复杂度 O(m×n)，m 为主串长、n 为模式串长；未给长度时写作 O(n²)。
> **易错点**：失配后 i 的落点是"本轮起点 + 1"，而不是"失配位置 + 1"。

## 前缀、后缀与部分匹配值 PM

[02:50:00 - 02:54:00]

对模式串的每个前缀子串分别计算：前缀指除最后一个字符外的所有头部子串，后缀指除第一个字符外的所有尾部子串，PM 值取"最长相等前后缀"的长度。例如 `aabaa` 的 PM 依次为 0、1、0、1、2（`aa`→1，`aaba`→1，`aabaa`→2）。

> **定义**：PM（Partial Match）值 = 该子串最长相等前后缀的长度；无相等前后缀时记 0，单字符子串记 0。
> **易错点**：PM 取的是**最长**相等前后缀的**长度**，不是相等前后缀的**个数**；两者数值偶尔巧合相等，最易混。
> ⚠️ **需回看视频 [02:51:00]**：后缀枚举转写为乱码（"A，AA，BA，AA，AB，AA"），需确认后缀的定义与枚举结果 —— "就是A，AA，BA，AA，AB，AA啊"

## next 数组的求法与下标约定

[02:54:00 - 02:57:00]

把 PM 数组整体右移一位、丢弃末位、首位补 -1，即得 next 数组；例如 `aabaa` 的 next 为 -1、0、1、0、1。若题目中模式串下标从 1 开始（王道常用），则把整个 next 数组每项加 1，得到 0、1、2、1、2，本质不变，只是起始位置不同。

> **公式**：`next[j] = PM[j-1]`（j ≥ 1），`next[0] = -1`；1 起下标版本整体 +1。
> **易错点**：-1 版本与 0 版本相差 1，做题前先看题干的字符串下标起点，否则整题答案全错。

## KMP 匹配中 next 的用法

[02:57:00 - 03:01:00]

KMP 的匹配框架与暴力法相同，区别只在失配时：**主串指针 i 不动，模式串指针回退到 `j = next[j]`**，再从该位置继续比较；若 `j == -1`（退无可退），则 i 与 j 同时后移一位（i++、j=0）。回退后 j 之前的那一段必定已与主串匹配，无需重比，这正是省下比较次数的原因。

> **公式**：失配 → `j = next[j]`；`j == -1` → `i++; j = 0`。
> **易错点**：KMP 只回退模式串，绝不回退主串；这是与朴素匹配的唯一本质区别。

## 为什么会"无效后退"：紧邻字符判定

[03:01:00 - 03:06:00]

失配后回退到 `next[j]`，此时要比较的字符是"最长相等前缀后面紧邻的那个字符"，而上一轮刚失配掉的模式串字符是 `P[j]`。若两者相同，则这一轮必然再次失配——因为刚刚已经证明该字符与主串对不上。结论：**是否会在同一处继续失配，取决于最长相等前后缀的紧邻字符是否等于上一轮的失配字符**；相同则必败（无效后退），不同则有可能成功。

> **易错点**：这里比较的是"模式串的两个字符"（紧邻字符 vs 上一轮失配字符），与主串内容无关；只有比较后才知道能否成功，只能说"有可能"。

## next 数组的缺陷

[03:06:00 - 03:11:00]

若模式串形如 `aaab`、主串中对应位置一直是 a，则每次失配回退到的位置仍是 a，必然反复失配，出现连续无效后退（示例中一处连续失配 4 次）。根源就是 `P[next[j]] == P[j]`——回退后的字符与刚才失配的字符相同，替换毫无意义。

> **易错点**：next 数组只保证"前缀已匹配"，不保证"回退位置的字符与失配字符不同"，所以存在冗余比较。

## nextval 数组：改进的 KMP

[03:11:00 - 03:23:00]

求法思想：对每个位置 j，从最长的相等前后缀开始考察，若"该前缀后面紧邻的字符"等于 `P[j]`（即上一轮失配的那个字符），则该回退无效，改取次长的相等前后缀继续判断；如此向下，直到找到紧邻字符与 `P[j]` 不同的长度 L，则 `nextval[j] = L`。若所有候选（含空前缀，此时看首字符 `P[0]`）都与 `P[j]` 相同，说明退到哪里都会失败，记 -1，匹配时直接 i++、j=0。首位固定为 -1。求得的值数组再整体右移一位、首位补 -1，即得 nextval（与求 next 的移位方式一致）。

> **公式**：`nextval[0] = -1`；若 `P[j] != P[next[j]]` 则 `nextval[j] = next[j]`，若 `P[j] == P[next[j]]` 则 `nextval[j] = nextval[next[j]]`（与老师的"改进 PM"法等价）。
> **易错点**：最长前后缀无效时要退而取**次长**，不是直接记 0/-1；空前缀情形必须额外比较首字符。
> ⚠️ **需回看视频 [03:16:00]**：改进 PM 中"不选时记 0 还是记 -1"的表述前后矛盾，需以教材 nextval 递推式核对 —— "不选就是负一，啊，不选就是零"

## nextval 的匹配效果

[03:23:00 - 03:28:00]

用法与 next 完全一样：失配时 i 不动、`j = nextval[j]`；区别在于 nextval 中不会再出现"回退到相同字符"的位置，若值为 -1 则直接让主串与模式串同步后移一位。对比示例中，用 next 要连续失配 4 次，用 nextval 只失配 2 次即匹配完成。

> **易错点**：nextval 里出现 -1 表示"连首字符都不必比"，处理方式等同于 next 中的 j == -1（i++、j=0）。

## 例题：nextval 与三对角矩阵下标

[03:28:00 - 03:30:00]

第一题给定模式串与已算好的 nextval，要求按"失配查表回退"直接选出匹配过程，与 next 的用法一致，只需查表不需重算。第二题：100 阶三对角矩阵、下标 1…100，按行优先压缩到下标从 0 开始的一维数组，求 `a[30][30]` 的 k——代公式 `2×30+30-3 = 87`；也可现推：前 29 行共 `2+28×3 = 86` 个，本行主对角线元素是本行第 2 个，故 k = 86+2-1 = 87。

> **公式**：`k = 2i + j - 3`，代入 i = j = 30 得 87。

## 串匹配真题的考法总结

[03:30:00 - 03:35:57]

三种考法：①直接问 next 或 nextval 数组（nextval 近两年反复考，必须会）；②问匹配过程中失配了几次、比较了多少次字符、某次失配后 j 应回退到哪个下标——只能模拟；③与矩阵压缩结合考下标计算。改进 PM 手算时只需盯住三个位置：最长相等前后缀是谁、它后面紧邻的字符是谁、上一轮失配的字符是谁，把三者写出来用括号标清即可。

> **易错点**：每多算一张表就多一次出错机会，用 nextval 可直接绕过 next；但若 nextval 的移位/补 -1 记错，整题作废。
